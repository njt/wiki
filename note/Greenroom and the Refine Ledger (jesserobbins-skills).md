# Greenroom and the Refine Ledger (jesserobbins/skills)

Jesse Robbins' skills marketplace is small — two entries — but the pairing is a coherent thesis: agents need **private scaffolding around public work**. greenroom gives that scaffolding a filesystem shape (a private notes repo beside every public repo); roborev-refine-and-polish gives a long multi-reviewer loop a private ledger so convergence is earned rather than assumed. Both are skills in the Claude Code sense: instructions plus a script, distributed as a plugin marketplace and simultaneously as standalone skills via `npx skills add`. The interesting content is not the packaging but the working disciplines the skills encode — and the lengths the packaging goes to so those disciplines survive being executed by an agent with a fresh context every shell call.

---

## Architecture

The repo is a **catalog, not a codebase**. Each skill lives in its own repository (canonical, carrying releases and CI); this repo holds the marketplace manifest and byte-identical mirrors.

- `.claude-plugin/marketplace.json` — the Claude Code plugin manifest, pointing at `jesserobbins/greenroom.git` and `jesserobbins/refine-and-polish.git` by URL.
- `skills/<name>/` — mirrors refreshed from each source repo's newest release (prereleases included — the sync script reads `/releases`, not `/releases/latest`, because the latter 404s on prerelease-only repos).
- `scripts/sync-mirrors.sh` + `.github/workflows/sync-mirrors.yml` — a daily GitHub Action that copies the payload, rewrites the version label in README.md, and proves provenance: each mirror is byte-identical to its release, `--check` reports staleness without changing anything, and MIRRORS.md records the mapping. One-way sync; issues go upstream.

The only substantial code is **greenroom's 1,838-line `scripts/greenroom.py`**, a stdlib-Python CLI with four subcommands (`new`, `retrofit`, `sync`, `collect`). Its architecture is a set of layout invariants enforced by code rather than convention:

- A **wrapper folder** per project, deliberately *not* a git repo, holding sibling repos: `<project>-public/`, `<project>-private/`, optionally `<project>-private-fork/` (cloned with remote named `upstream` so `origin` stays free for a private GitHub remote).
- `discover_repos()` finds *any* git repo dropped under the wrapper, so forks and extra clones are absorbed automatically; `choose_canonical()` picks the repo agents launch from (`*-public` preferred), which is what keeps session history in one bucket.
- Agent wiring is generated per repo: `AGENTS.md` as the canonical orientation file with a `CLAUDE.md` containing exactly `@AGENTS.md` (and a Gemini equivalent), plus per-repo Claude settings that grant sibling-repo access and `.claude/settings.local.json` excludes. A VS Code multi-root workspace is written with trailing-comma-tolerant JSONC parsing (`_strip_trailing_commas`) so user-edited workspaces survive re-sync — a small, telling detail about respecting state the tool doesn't own.

## Key techniques

- **The resolver block as infrastructure.** greenroom's SKILL.md opens with a 25-line shell block the agent must paste *verbatim into every command* that runs the script, because every Bash-tool invocation is a fresh process and `$greenroom` cannot survive. It resolves the script across four tiers — `$CLAUDE_PLUGIN_ROOT`, a walked-up project-local install, the newest plugin-cache version (sorted on the VERSION directory alone so a second marketplace owner can't shadow a newer version), then `~/.claude/skills` — with guard comments explaining each subtle bug it prevents (a stale ancestor `.claude/` outranking the cache; `ls` failing under `set -e`). This is prompt engineering as robust software distribution: the skill assumes an amnesiac executor and encodes idempotent path resolution in the prompt itself.
- **Collect as archaeology.** `cmd_collect` recovers private-shaped docs that landed in public history before the layout existed. It scans (1) the default branch against a conservative glob table (`docs/design/**`, `**/*-design.md`, `**/*.draft.md`, …) mapping to five buckets, and (2) unmerged branches whose names start with `design/`, `notes/`, `drafts/`, `private/` — the branch-name convention as a retroactive privacy signal. Dry-run first, `--apply` copies bytes read from git at a SHA; it never rewrites public history (that's `git filter-repo`'s job, deliberately out of scope) and never executes content.
- **Refusal to do the dangerous step.** The script never pushes and never creates a remote. It *prints* `gh repo create <owner>/<name> --private --source=...` commands (fully `shlex.quote`d, with `<owner>` interpolated only as a placeholder when `gh` isn't authed) and the skill instructs the agent to relay them verbatim and run them only on an explicit yes — always `--private`, never offering a public variant. The blast radius of an agent mistake is capped by making the irreversible step a human-gated paste.
- **The ledger as a typed database in Markdown.** roborev-refine-and-polish is pure SKILL.md — no script. Its core artifact is a table with columns `Iteration | Agent | Sev | Location | Type | Status/Commit`, where the **Type** column carries a four-way taxonomy that does the real analytical work: NEW (first appearance), REGRESSION of `<iter>.<agent>.<sev>` (my fix broke this — needs a regression test at the boundary that broke), REPEAT (same symptom post-fix — a *defend* signal, not a re-fix signal), LOOP (finding closed in N reappears identically in N+1 — the meaning of "fixed" disagrees; stop coding, reconcile). The row keys on roborev job ids, so the ledger is an index into `roborev log <job>` rather than a duplicate of reviewer output.
- **Convergence as a stated, immovable criterion.** Default: zero H/M findings, or only findings on the **deliberate-pushback list** — findings you've decided *not* to fix, each with at least two reasons (one about the code, one about future direction) and an explicit note that iteration N+1 is expected to re-raise it verbatim. This is the only mechanism that lets reviewers who can't see prior turns converge: without it, every defensible design call becomes an infinite loop.
- **Reviewer-coverage honesty.** Reviewers are subscription-backed CLIs (claude-code, codex, pi), each its own job. When one's auth breaks mid-loop the skill prescribes: record an `N/A` row; try the *subscription-only* fix first (a model-slug mismatch, repoint at a plan-served model); one retry as a `1b` sub-iteration; then waive — and caption convergence as "claude-code only; codex structurally unavailable all iters." Never set `OPENAI_API_KEY` to revive a downed reviewer: "a single-agent pass honestly captioned beats a two-agent pass faked with an API key."
- **The Low-tail budget stop.** roborev's verdict Fails on any finding, including a lone Low; the skill explicitly demotes it to a mechanical gate. A motivated reviewer produces a roughly steady stream of new Lows each iteration (observed: 5, 3, 4, 4) because each fix is new surface to critique. The stop rule is therefore the **iteration budget** (five default, ten ceiling), not an empty Low surface — and the closing must say "convergent at the iteration budget; remaining Lows are a reviewer tail," not "no Lows remain."

## Design decisions

The overriding trade-off is **honesty over convenience**. Every mechanism — the N/A row, the coverage caveat, the budget stop wording, the "never rewrite past rows, append corrections" rule, the ban on linking the ledger from a public PR (the path itself is a leak) — exists to prevent the loop from manufacturing a convergence it didn't earn. The cost is ceremony: the skill itself says a one-iteration loop should skip it.

greenroom makes the opposite-looking but complementary trade: heavy upfront structure (wrapper layout, generated AGENTS.md wiring, workspace files, sync machinery) to buy a permanent, enforceable privacy boundary. Where most agent setups default everything into one repo, greenroom insists the raw thinking stay under git but never published — and `collect` acknowledges the reality that some of it already leaked, while pointedly refusing to scrub history.

The mirror architecture trades freshness for verifiability: mirrors go stale until the daily sync, but "byte-identical to the release" is a checkable property, and provenance lives in MIRRORS.md rather than sidecar manifests. Notably, the sync even auto-updates the version label in the README because "it is otherwise hand-maintained and drifts" — the author documenting his own failure mode.

## Comparison notes

- [[Matt Pocock Skills — Skills for Real Engineers]] is the closest structural sibling: both are personal Claude Code plugin marketplaces whose real payload is process discipline, and both dual-publish via `npx skills` for cross-agent portability. Pocock's skills own the *flow* (grill→spec→tickets→implement); Robbins' own the *boundaries* (what stays private, when the loop stops). They compose rather than compete.
- [[Agentic Engineering at Kenn]] uses roborev as its verification layer and names the same pathology this ledger skill exists to fix — reviews that never converge. McKinney's answer is a whole tooling stack; Robbins' is one Markdown file with a type column. The ledger is the poor man's version, and arguably the more transferable one.
- [[Claude Code Skills System]] describes Anthropic's official skills architecture; this repo is a working specimen of it, pushed to an edge Anthropic's docs don't cover: a skill whose SKILL.md must teach an agent to re-resolve its own install path every invocation, because plugins install at different roots per shape and shell calls are stateless.
- [[The End of Code Review]] and [[Agentic Code Review]] argue review is becoming agent-vs-agent verification; the refine ledger is a concrete answer to what that actually requires operationally — typed findings, a pushback list, and a convergence criterion a human wrote down before the loop started.

**Weak points worth naming.** The refine skill is tightly coupled to one product (roborev) and one ecosystem of subscription CLIs; the ledger method is general, the commands are not. greenroom's resolver block is a marvel of defensive prompting but is also a symptom: distribution across plugin shapes and agent hosts is unsolved, and each skill author reinvents the workaround. And a 1,838-line script inside a "skills" repo shows where the skill format hits its ceiling — past a certain size you're writing software, and SKILL.md is not a software spec.
