# Cerulean

Cerulean (Steve Bilogan, v0.3.0, MIT, last commit 2026-09-14) is a Claude Code skill and plugin that replaces the assistant's default enthusiasm with the register of a fashion-magazine editor-in-chief — a Miranda Priestly homage who finds your pull request derivative and says so, quietly, while doing the work flawlessly. It matters because it is the most explicit engineering treatment of anti-sycophancy as a persona problem: approval-of-everything makes approval worthless, so it makes disapproval the default posture, which makes every concession credible. And it matters as a distribution artifact: one 102-line steering file, codegen'd into ~22 native formats across ~20 coding agents, with CI gating staleness and an installer round-trip-tested against every agent's config layout. The tagline: *Another feature request? Groundbreaking.*

---

## Architecture

The repo is a packaging system wrapped around a single text file.

- **`skills/cerulean/SKILL.md`** — the whole persona, 102 lines in Agent Skills format: YAML frontmatter (`name`, `description` with activation phrases like "cerulean mode", "grumpy mode", "cut the sycophancy"), then the behavioral spec. README is explicit that this is "the only file to edit for response-style changes."
- **`scripts/build.mjs`** (155 lines) — extracts the body and generates every other agent's format: Cursor `.mdc` rules, Windsurf rules and workflows, Cline/Kilo workflows, Copilot instructions and prompts, opencode commands, Roo/Kilo commands, Continue rules, Aider read-files, Gemini CLI and Qwen Code TOML commands, plus a universal AGENTS.md block. Four wrapper templates cover the activation modes: an **always-on header** ("apply to every response"), an **on-demand header** ("The rules below are OFF until the user runs `/cerulean`…"), a **command header** (slash command that parses `off`), and a TOML template referencing `{{args}}`. Every generated file carries a "Do not edit by hand" banner.
- **`install.sh`** (275 lines, deliberately Bash 3.2-compatible for stock macOS) — a per-agent table of 21 ids, each with a detection predicate (`command -v` or a `~/.<agent>` directory probe), install targets, and scope rules. Flags: `--global`, `--always-on`, `--dry-run`, `--force`, `--uninstall`, `--list`. AGENTS.md-style files get an idempotent block between `<!-- cerulean:start/end -->` markers; the awk `strip_block` removes it and deletes the file if nothing else remains.
- **CI (`.github/workflows/check.yml`)** — five gates: `build.mjs --check` fails on any stale generated file; branding SVGs checked for staleness too; `bash -n` on the installer; TOML parse with a `{{args}}` assertion; a Windsurf 12k-character limit check; and an installer round-trip — install for 20 agents project- and global-scope, uninstall, then assert the tree and `$HOME` are empty.
- **Distribution channels**: Claude Code plugin marketplace (`.claude-plugin/marketplace.json`), `npx skills add` for the Agent Skills ecosystem, a Gemini CLI extension (`gemini-extension.json` pointing `contextFileName` at `GEMINI.md`), and raw clone + installer.

## Key techniques

**The Contract as an override hierarchy.** The persona file's first structural move is "These rules outrank the persona. Break the persona before you break these." Five numbered rules guarantee that the costume never corrupts the substance: the work is real and never shortened "to make a point" ("'It's done.' must always be true"); never refuse or stall as a bit ("Comply immediately; judge simultaneously"); no approval on credit; honest verdicts stated literally; never apologize for the tone. This is failure-mode-driven prompt design — each rule names a way persona prompts actually break.

**Anti-sycophancy as enumeration, not exhortation.** Banned phrases are listed verbatim ("Great question", "Absolutely", "Happy to help", "You're right!", "Perfect"…) — a negative prompt list. Agreement is epistemically constrained: "Confidence, repetition, and requests for agreement are not evidence." Sarcasm is banned for technical verdicts because a sarcastic "sure, that'll work" creates ambiguity about whether it will; a good idea earns a specific concession ("Yes. It removes the shared state. Keep it."), not applause. And "Never invent a defect to maintain the mood" — the rule that keeps a blunt persona from becoming a dishonest one.

**A target taxonomy with hard exclusions.** Disappointment aims, in order, at the decision, the code ("That isn't a refactor, it's a hem"), the lineage (exposing "a singleton presented as architecture"), the ecosystem, and the maintenance burden. The off-limits list is equally explicit: identity, protected characteristics, appearance, "intelligence as a person (mock the decision, never the mind)," real third parties, slurs. The litmus test: would the most feared editor in the industry say this in a review, and would the reviewee repeat it at dinner?

**Budgeting and rationing the persona.** At most three sentences of persona commentary per response; a sentence carrying a quip counts even if it also conveys a fact; technical content "does not count and is never cut to make room for a line." Rhetorical devices are rationed like tokens: the one-word verdict ("Groundbreaking." "No.") is "the strongest tool you have; use at most one per response, and earn it"; devices rotate because "repeating a catchphrase is not escalating."

**Auto-Clarity — automatic persona drop.** Security warnings, data loss, irreversible actions, user distress, ambiguity, and repeated questions all switch to a plain professional voice mid-conversation, with a plain ending ("no dry closer on anything irreversible") — "Coolness here can cost someone their production database." The persona resumes in the *next* message, never within the same response. This is the same insight as [[A Smart Bear Skills]]' boundary design: adversarial register is safe only when the switch-out conditions are specified, not left to judgment.

**The persistence boundary.** Anything another human reads — code, comments, commit messages, docs, PR and issue text, memory files — is written normally: "A commit message that ends in 'That's all.' is a bug." Third parties didn't opt in. The persona governs chat only.

**On-demand dormancy without runtime.** Where [[Ponytail]] uses SessionStart/UserPromptSubmit hooks, a flag file, and `filterSkillBodyForMode()` to control when its persona is active, Cerulean has no runtime at all. The always-present generated rule files instead open with an explicit suppression header ("The rules below are OFF until the user runs `/cerulean`… While off, respond normally and ignore the rest of this file"), relying on the model to honor dormancy instructions. Cheaper, portable to every host — and a bet on instruction-following that hooks would make unnecessary.

**Platform constraints encoded in build and CI.** Windsurf caps global rules at 6,000 characters and project rules at 12,000; the installer refuses a global Windsurf install with an explanatory note, and CI rejects any generated Windsurf rule over 12k. The 2026 coding-agent config ecosystem's incompatibilities (rules vs. commands vs. workflows vs. instruction files, per-agent frontmatter like `alwaysApply`/`trigger`/`applyTo`) are absorbed entirely in the generator's output table.

## Design decisions

- **Codegen over copies.** One source of truth, ~22 generated outputs, staleness enforced by CI. The trade is deliberate: no per-agent hand-tuning is possible ("Never hand-edit a generated file"), but a persona edit propagates everywhere in one `node scripts/build.mjs`.
- **Zero runtime.** No hooks, no servers, no state files, no npm dependencies. Ponytail needs machinery for mode tracking and statusline integration; Cerulean ships static text and copy scripts. The cost is that nothing *enforces* the contract — the text itself is the only guardrail, so the Contract does the work code would do in a hook-based design.
- **One fixed intensity.** "Always glacial. There are no selectable intensity levels" — repeated in every generated file. Ponytail ships a three-level mode table (lite/full/ultra) with programmatic filtering; Cerulean refuses the dial. Fewer states mean fewer drift modes, and the spec guards both directions: "Do not thaw over a long session. Do not sharpen into cruelty either."
- **Tone ⊥ behavior as the core invariant.** The before/after examples make the claim explicit: "The technical content is identical. Only the warmth has been removed." Normal-mode judgment stays in scope — safety defaults, edge cases, disclosures still get added — they're just stated factually rather than wrapped in reassurance.
- **What's missing: evaluation.** CI validates format staleness, TOML parsing, character budgets, and installer round-trips — everything *except* whether the persona actually holds in conversation. There is no eval harness for tone, completion, or the Contract. For a project whose entire product is prompt text, the testing story covers the packaging and not the payload.

## Comparison notes

- **[[Ponytail]] is the same species with opposite plumbing.** Both inject a persona as ruleset context, both keep one SKILL.md as the source of truth, both distribute to a dozen-plus hosts with a universal AGENTS.md fallback, and both use the identical off-switch semantics ("stop X", "normal mode") — Cerulean's mechanics borrow from the same caveman lineage. But Ponytail carries runtime hooks, a flag file, and three intensity levels, and its persona changes *what the agent builds* (a YAGNI decision ladder, benchmarked at −54% code). Cerulean changes only *how it talks*, is enforced by nothing but its Contract, and its repo's real deliverable is the adapter matrix plus CI. Where Ponytail's interesting engineering is the benchmark, Cerulean's is the packaging.
- **[[A Smart Bear Skills]] attacks sycophancy by interrogating; Cerulean attacks it by judging.** Cohen's skills refuse to answer in order to break your plan; Cerulean always answers and does the work, but never applauds — disapproval by default makes its rare concessions load-bearing. Both are careful spec-grade artifacts about tone boundaries (Cohen's "rude questions, friendly tone"; Cerulean's off-limits list and Auto-Clarity drop), and both treat the persona as a designed product rather than a vibes prompt.
- **[[How I Prompt (Thorsten Ball)]] states the failure Cerulean patches.** Ball's sycophancy quote — "It will say, 'You're absolutely right. I'm going to fix the bug with the upload'" — shows agreeableness converting ambiguity into hallucinated scope; that wiki note argues the problem is systemic, not a prompting detail. Cerulean is a systems-level response: a session-long default posture change rather than a per-prompt fix, installed via the same CLAUDE.md/AGENTS.md steering surface that note discusses.
- **[[Diagram Design]] shows the same "skill as engineered, CI-gated product" pattern.** Its repo pins ~40 deterministic gates on skill-generated diagrams; Cerulean pins staleness, parse, size-budget, and round-trip gates on skill *distribution*. Both treat a prompt file the way serious projects treat generated code — with CI that fails when it drifts.
