# Exact — a cross-platform app runtime designed for agents

Exact (repo `expo/exact`, internally "exact2") is a cross-platform application runtime from the Expo team built on a bet: that most UI code will soon be written by AI agents, so the runtime should be shaped so an agent can build, run, *see*, operate, and prove an app with no person in the loop. You write the view in **Contract**, a small declarative language with no JavaScript, no I/O, and no escape hatches, and your data logic in TypeScript or Rust behind one typed seam. One compiled *plan* runs on web (real DOM), macOS (AppKit), iOS (UIKit), and Linux (GPU/CPU painter). It matters as the most complete worked example yet of "agent-native" architecture — a system whose APIs, tests, and governance are designed for a machine reader first.

---

## Architecture

The pipeline is: Contract source → compiler → plan → host-specific presentation.

- **`contract/`** — the compiler, four passes (`syntax` → `types` → `analyze` → `lower`), ~89K lines across the passes. It refuses up to twenty independent errors per run with stable ids and source ranges; `contract build --json`, `symbols`, `fmt`, and `types` (generates `app.contract.d.ts`) are all machine surfaces.
- **`plan/`** — the compiled artifact: relational tables (slots, derives, resources, actions, timers, nodes, bindings, handlers, regions) plus three pools (strings, bytecode, data). Its shape is declared once in `plan/tables/format.json` and generated by `build.rs`. Loading is a validation pass, never trusted indexing; every plan carries a format digest.
- **`runner/`** — the plan's VM: keyed component instances, events, timers on a seekable clock, and the data seam. `runner/src/agent.rs` implements the agent read operations once for all hosts — deliberately *from the runner and kernel, never from a host's mirror*, a lesson coded from exact1's defect log.
- **`kernel/`** (~22K lines) — a columnar node arena with generation-checked identity, CSS layout via a patched vendored Taffy, transactional apply (wire frames and in-process ops enter one validate-then-apply engine; a rejection changes nothing), and layout proportional to change via per-node dirty flags. Text measurement is an injected trait object (CoreText on Apple, cosmic-text on Linux); on the web the browser lays out the same CSS itself, so the web build carries no layout engine.
- **`host/`** — web (DOM writer), Apple (a Rust static library with C ABI under AppKit/UIKit presenters), Linux (paints the tree itself onto DRM/KMS or into a buffer), plus server-side rendering that adopts pages in place instead of hydrating.
- **Data seam** — TypeScript runs on Hermes (pinned, attested Ibex bundles, loaded as bytecode *after* first pixel) or in the browser's own engine; Rust runs natively and can be hot-replaced as a shared library or Wasm. Every answer is checked against the shape Contract declared; network, files, SQLite, and secrets sit behind explicit grants.

## Key techniques

- **Ten operations, on purpose.** `scripts/agent.mjs` (~1,470 lines) exposes `tree · screenshot · tap · type · state · layout · logs · clock · prefer · perf` identically across web, macOS, iOS (simulator or physical device), and Linux. The predecessor's agent API grew to eighty wire names "one reasonable addition at a time"; the cap is the design.
- **The agent owns the clock.** Between two operations nothing moves. `clock +60000` or `clock settle` advances a seekable clock instead of sleeping — the same mechanism powers motion, so tests have no timing flakes. This is the single most transferable idea in the repo.
- **Tests are scripts of the driver operations.** An `app.test.contract` runs unchanged on any host with no second evaluator. A build marker binds every runtime artifact and the driver *refuses to drive a build older than its sources*, naming the rebuild — staleness is a refusal, not a hazard.
- **The plan is baked.** Constant data is evaluated into the plan at build time, so the first frame needs no JavaScript; the boot path "executes and compiles nothing," and the module graph is *counted* on every commit (`scripts/boot.mjs`), not timed — startup is treated as emergent and unretrofittable.
- **Refusals over misbehavior.** Contract requires keyed `for` loops, refuses recursion in `fn`s, refuses alias spellings ("`size` is spelled `font-size` here"), and checks every data answer against a declared shape. The language is small enough that a whole app fits in a context window.
- **Browser as parity oracle.** Native layout, Canvas 2D, SVG, and authored motion are diffed against what Chrome draws with the same inputs; unavoidable deviations must be declared with reasons in the design record.
- **Governance as code.** `rules/RULES.md` is a 700-word capped file of [check]/[review] rules: six blocking checks in 65 s total, 1,500 lines per file, fail-fast banned ("a check that surfaces one defect per run turns N bugs into N × runtime"), fix loops capped at 3 rounds. And the remarkable one: **agents may remove apparatus freely and may add none** without explicit human approval — an asymmetry aimed at governance accreting "one reasonable addition at a time."

## Design decisions

- **No JS in the view at all.** Expressions are pure; effects happen only in actions, as named typed mutations. This is what makes the plan bakeable, diffable, and executable identically on four hosts — and what stops an agent from wiring a data race it can't express. The cost: no JSX/React tier, and anything dynamic must be modelled as state/mutation, which is a real expressiveness tax.
- **Write the web, ship the platform.** Layout and names are CSS's; whatever is unsaid (system label colours, native buttons, Back gesture) is the platform's. Apps that say less look more at home. Sacrificed: pixel-identical cross-platform branding, on purpose — a linter (`no-tells.mjs`) *holds apps to* not naming colours or font sizes.
- **Access hatches, not escape hatches.** Platform widgets are hyphenated native modules laid out by the kernel; where native code needs the object Exact built (a `UIView`, a DOM element), `hatch="word"` hands it over — but it may only act on authored nodes, like a person would. Extension is disciplined rather than forbidden.
- **Pre-1.0 with no shims.** Delete, don't deprecate; no migration guides. The repo optimizes for the edit-to-verified loop staying under a minute, accepting that early adopters eat churn.

## Comparison notes

- Unlike [[The Persistent Gravity of Cross Platform]], which argues coordination costs pull teams toward cross-platform frameworks and that agentic coding *deepens* that gravity (human verification is the bottleneck), Exact attacks the other end: it makes the runtime itself the verification substrate, so an agent drives all four hosts through one ten-verb protocol instead of one framework per platform.
- [[Agent-Native Architectures (Every)]] argues agents need machine-first interfaces; Exact is that thesis carried into a UI runtime — down to the seekable clock, which is the same "no wall-clock waits" move agent harnesses make, applied to animation.
- Against [[Harness Engineering in Practice]]'s pattern of bolting verification harnesses onto existing codebases, Exact builds the harness into the product: `AGENTS.md` in every generated app, `feedback note` one-line friction diaries, and tests that are literally driver scripts.
- Its rules file is a sharper-edged cousin of the governance material around [[10 Principles for Agent-Native CLIs]] — where that piece describes machine-first CLI design, Exact adds the anti-accretion rule (agents may delete apparatus, never add it) as the actual enforcement mechanism.
