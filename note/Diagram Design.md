# Diagram Design

Cathryn Lavery's Diagram Design is an Agent Skill — shipping simultaneously as a Claude Code plugin, a Codex/Copilot/Factory Droid plugin, and a Pi/Kiro/OpenCode skill — that generates 40 editorial diagram types as single self-contained HTML files with inline SVG. Its answer to "AI diagrams look like slop" is not a better renderer but a *grammar*: an opinionated design system (atomic-tangerine accent reserved for 1–2 focal nodes, Instrument Serif + Geist type stack, a 4px coordinate grid, ≤9 nodes per diagram) plus a battery of ~40 deterministic CI gates that verify the geometry of what the model produces. It matters as one of the most rigorously engineered examples of a cross-host skill, and as a working proof that taste can be enforced on generative output with lint rules instead of hope.

## Architecture

The skill is organized as **progressive disclosure in three tiers**, mirroring the load model of the host agent rather than fighting it:

- **Tier 1 — `skills/diagram-design/SKILL.md`** (587 lines, hard-capped at 40,000 bytes by ADR 0004). Loaded on every invocation. It carries the philosophy ("the highest-quality move is usually deletion"), the routing table for all 40 visual types, the six non-negotiable connector rules, the 4px grid, per-type complexity budgets, and the pre-output "taste gate" checklist. Notably its frontmatter `description` must name every type — "flowchart", "Gantt", "Sankey" are the lexical hooks that make "make me a flowchart" route to this skill at all, and `verify-docs-sync.py` fails CI if one goes missing.
- **Tier 2 — `references/`.** ~56 files loaded *only when routed*: one `type-*.md` per visual type (layout grammar + type-specific anti-patterns), `semantic-patterns.md` (behavior), `animation.md` (motion contract), `onboarding.md`, `profiles.md`, `output-spec.md`, `import-*.md`, and three style primitives (annotation callouts, sketchy turbulence filter, terminal chrome). A routine "make me a flowchart" loads exactly two files: `SKILL.md` + `type-flowchart.md`.
- **Tier 3 — `assets/`.** 162 files: `template*.html` scaffolds (light/dark/full/motion) and an example triple for every type, all valid output the model can copy from.

The **deterministic core** is four Python scripts in `skills/diagram-design/scripts/`: `drawio_extract.py` (897 lines), `mermaid_extract.py` (1,355), `excalidraw_extract.py` (704), and `self_check.py` (457). The first three parse untrusted source files into a normalized IR — never rendering, never fetching — and print a compact Markdown digest (nodes, edges, hubs, containers, cycles, budget flags, type candidates) sized to be read into context. `self_check.py` is a distilled output validator that ships *to installed agents*, so the accessibility and single-file-safety contract applies to generated diagrams, not just repo assets.

Around this, the repo root is a multi-host distribution layer: `.claude-plugin/`, `.codex-plugin/`, `.factory-plugin/`, and `.agents/plugins/marketplace.json` manifests share one plugin root (ADR 0008), `commands/` holds Claude Code slash-command front matter, and `prompts/` holds the Pi prompt templates — every command file just delegates to a reference file as the single source of truth.

## Key techniques

- **Semantic patterns as a separate axis from layout.** Eight patterns (fan-in queue, stage framework, unstructured-input→artifact, paired policy traces, secure paved road, governance catalog, compensating security layers, traceable block decomposition) describe *behavior*; the 40 visual types describe *arrangement*. A pattern routes to the nearest existing type and brings its own tighter budget and anti-patterns. This is ADR 0002's discipline: adding behavior costs one routing-table row, never a new type, template set, and example triple.
- **"Redraw, don't convert" importing.** The extractors deliberately discard source coordinates, palettes, and shape quirks — what survives is components, relationships, grouping, direction. Four dials (`format × size × detail × audience`) then fit output to destination: a slide preset means 16px node names in 64px boxes, and `executive` audience rewrites *wording* (`Auth Service / JWT · RS256 · :8443` → `Sign-in`) without changing node count. Every import ends with a fidelity ledger of what was merged or dropped.
- **Paint-order-aware geometry lint.** `verify-geometry.py` codifies SKILL.md §6 rule 6: because arrows are drawn before boxes, a label mask that lands partly inside a later-painted node gets clipped by its fill. The check classifies rects by size (≥60×40 = node, 20–200×8–14 = mask) and fails only on mask-over-later-node overlaps — masks inside zones are legal because zones paint first. This is a rendering-pipeline subtlety promoted to an enforced contract.
- **Pixel-diff clipping detection.** `lint-render.py` measures clipping by paint, not geometry: `getBoundingClientRect()` ignores stroke width and `clip-path`, so instead each SVG is screenshotted twice — as authored, and with `overflow` released — and the images diffed. Ink that appears outside was being cut off. Releases are staged (SVG alone, then each clipping ancestor) so a wrapper release can't mask spill. There are no golden images, and network is cut at the browser resolver.
- **A byte-pinned motion controller.** Motion is optional and static-first: the complete diagram must be readable with no JavaScript, under `prefers-reduced-motion`, and in print. When motion is chosen, the file may carry exactly one `<script data-diagram-controls>` whose body must *byte-match* the reviewed controller in `template-motion.html` (SHA-256 in `lint-skin.py`, string equality in `verify-motion.py`, repeat in `self_check.py`). Hand-edited controllers fail every gate.
- **Brand onboarding as token extraction.** "Onboard to https://yoursite.com" fetches the page, maps detected colors/fonts to semantic roles (`paper`, `ink`, `muted`, `accent`, `link`) with WCAG AA contrast checks, shows a proposed diff, and writes `references/style-guide.md` — the only place hex values live; every type reference says `accent`, not `#eb6c36`. Named profiles in `~/.diagram-design/profiles/<slug>.md` plus a `.diagram-design` project marker resolve the parallel-workspace race (ADR 0006): profiles survive plugin updates because they never live inside the install.
- **Security at the trust boundary.** Extractors treat every label, link, and directive as inert data; DTD/entity declarations are rejected; decompression is bounded (`_decompress_limited`) so a small payload can't zip-bomb; the skin linter rejects remote assets, CSS `@import`, and executable attributes (`onclick`, `srcdoc`).

## Design decisions

- **Deletion as the quality bar.** Target density 4/10, ≤9 nodes, ≤12 arrows, accent on 1–2 elements. The skill's core claim is that a diagram is done "when nothing can be removed" — the complexity budget is what makes each type reference teachable and each output checkable.
- **Layout grammar over autolayout.** The skill never runs a layout engine; it gives the model per-type hand-layout grammars with fixed spacing rules and *verifies the result*. This inverts the usual "agents can't route edges" pessimism — instead of splitting placement from routing algorithmically, it constrains the design space until the model's placement is the layout.
- **The 40,000-byte cap trades routing surface for body prose — explicitly never the reverse.** ADR 0004 records the v2.3 mistake: slimming the description to fit the cap deleted the type names that trigger skill invocation. The lesson is generalizable: the description is the only text an agent sees *before* deciding to load, so it's the last thing to cut.
- **Counts are ADR-enforced.** The type count only moves for a genuinely new *layout grammar* (28 → 38 → 39 → 40, each with a per-grammar argument), and the amendment procedure says a PR that edits the counters without amending the ADR "has quietly made itself the authority." Small governance, but it's exactly the mechanism that keeps a design system from accreting.
- **Verification runs where the output is.** The repo gates (`scripts/verify-*.py`, run in CI across Linux/Windows/macOS, pinned Playwright builds, Python 3.9 compatibility) and the installed-skill gate (`self_check.py`) are two halves of one contract. The trade-off: no bespoke interaction is possible, since the controller can't be extended per-diagram — accepted in ADR 0001 as the price of a shareable, auditable artifact.
- **Weak spot.** The style guide itself admits the pre-baked `assets/` examples lag the current tokens (a "v5.1 task"), so the gallery and the spec can drift — the exact failure mode the repo's own doc-sync gates exist to catch elsewhere.

## Comparison notes

- Where [[Claude Code Skills System]] describes the *platform* — directories with a `SKILL.md` entrypoint, lazy loading, three-tier deployment — Diagram Design is the most complete worked example of that architecture pushed to production discipline: progressive disclosure with byte caps, cross-host manifests, ADRs, and adversarial tests of its own gates (`test-verify-*.py` keep the checkers honest "in both directions").
- [[TALA (Diagram Layout Engine)]] bets that models place nodes well but route edges badly, so routing should go to a deterministic engine. Diagram Design makes the opposite bet: skip the autolayout engine entirely, give the model an orthogonal-connector grammar plus six enforced rules, and verify geometry after the fact — deterministic *verification* instead of deterministic *generation*.
- Like [[Agent Skills Library (dzhng)]], it treats quality gates as the actual content of a skill, not an afterthought: three-gate review per slice there; ~40 verify scripts, a pinned motion controller, and a shipped `self_check.py` here. Both show skills converging on the guardrails-and-feedback-loops pattern — instructions plus deterministic checks over instructions alone.
- [[2389 Plugin Marketplace]] and Diagram Design share the distribution model — one repo, `/plugin marketplace add`, many skills — but Diagram Design's interesting move is *portability of the same plugin root* across Claude Code, Codex, Copilot, Factory Droid, and Pi (ADR 0008), with per-host update semantics documented honestly (Pi has no auto-refresh; Droid tracks commits, not manifest versions).
