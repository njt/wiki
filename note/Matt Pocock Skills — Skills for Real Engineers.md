# Matt Pocock Skills — Skills for Real Engineers

A repo of 25+ markdown agent skills (v1.2.3, MIT) that Matt Pocock uses daily, distributed as a Claude Code plugin and via skills.sh. It matters less as a tool catalog than as a worked argument about process architecture: skills should be small, composable, and hackable, in deliberate opposition to monolithic spec-driven frameworks (GSD, BMAD, Spec-Kit) that "own the process" — because when the process itself is owned by a framework, bugs in the process are hard to resolve. The whole thing is prose engineering: ~1,300 lines of SKILL.md across the promoted buckets, a handful of bash scripts, no application code. The repo's own `CONTEXT.md` is written in the glossary format its skills enforce — terms, relationships, flagged ambiguities — so the repo is a demonstration of its own discipline.

---

## Architecture

**Structure: a bucket-of-skills with an explicit router.** No runtime, no framework — just files:

- `skills/engineering/` (18 skills), `skills/productivity/` (8), `skills/misc/` and `skills/in-progress/` (a staging area; skills "graduate" to the plugin on promotion, e.g. `wizard` at v1.2).
- Each skill = `SKILL.md` with YAML frontmatter (`name`, `description`, optional `disable-model-invocation: true`) plus reference docs the skill owns (`tdd/tests.md`, `tdd/mocking.md`, `domain-modeling/CONTEXT-FORMAT.md`, `wizard/template.sh`).
- `ask-matt` is a **router**: it documents the main flow (`/grill-with-docs → /to-spec → /to-tickets → /implement`, with `/implement` internally driving `/tdd` then `/code-review`) plus on-ramps (triage, diagnosing-bugs, wayfinder) and a vocabulary layer (domain-modeling, codebase-design) that runs underneath everything.
- Packaging: `.claude-plugin/plugin.json` lists skill paths; every skill also carries an `agents/openai.yaml` for Codex so invocation policy is synced across harnesses. Changesets + a `sync-plugin-version.mjs` script keep plugin.json's version in step with package.json.

**The invocation lattice is the real architecture.** Per `.agents/invocation.md`: skills split into **user-invoked** (`disable-model-invocation: true` — only a human can fire them, and no skill may ever call them) and **model-invoked** (default; rich trigger-phrased descriptions for auto-invocation). Dependencies are expressed as explicit Skill-tool calls ("Call the Skill tool twice, for 'grilling' and 'domain-modeling'") rather than file links or bare `/name` mentions — because naming the tool is what gets it fired. `grill-with-docs` is the purest example: its entire SKILL.md is one line delegating to two other skills, and partial loading (grilling fires, domain-modeling doesn't) is the skill's most-reported failure mode.

**Per-repo configuration is itself a skill.** `/setup-matt-pocock-skills` explores the repo (remotes, existing CLAUDE.md/AGENTS.md, monorepo signals), then writes `docs/agents/issue-tracker.md` (GitHub/GitLab/local-`.scratch/`/freeform), triage label mappings, and a domain-doc layout decision (single vs multi-context). Every downstream skill assumes this config and, if missing, stops and tells the user to run setup — a clean precondition pattern.

## Key techniques

- **Frontier-based grilling.** `grilling` maps a plan as a *design tree* and works only the **frontier** — decisions whose prerequisites are already settled — asking the whole frontier per round with recommended answers, then recomputing. Facts are the agent's job (dispatch a sub-agent to look things up; don't block the frontier on it); decisions are the user's. Termination condition: empty frontier, "nothing left silently assumed."
- **Two-axis review that is never merged.** `code-review` pins a diff fixed point, finds the spec source (commit-referenced issue → user path → docs/specs convention), then runs Standards and Spec sub-agents **in parallel** so contexts don't pollute each other, and aggregates them verbatim under separate headings. It explicitly refuses to pick a single winner across axes, because a change can pass one and fail the other. The Standards axis carries a fixed Fowler smell baseline (12 smells as judgement calls) that documented repo standards always override.
- **Triage as a state machine over a tracker.** Two category roles (bug/enhancement) × five state roles (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`), mapped to real tracker labels via config. PRs are "issues with attached code" using the same machine. Every AI-written tracker comment must open with a disclaimer. `wontfix` distinguishes already-implemented (point at code, don't write to the `.out-of-scope/` KB) from rejected (do write there) — a persistent negative-knowledge base that stops re-litigated requests from returning.
- **Tracer-bullet tickets with blocking edges.** `to-tickets` demands vertical slices cut through every layer, each demoable, each sized to one fresh context window, each declaring its blockers. Wide refactors are the documented exception: sequence them expand–contract with batches sized by blast radius, falling back to a shared integration branch when batches can't stay green alone.
- **Diagnosis before hypothesis.** `diagnosing-bugs` forbids theorizing until a "tight, red-capable" loop exists — one command, already run once, that asserts the user's exact symptom, is deterministic, fast, and agent-runnable — and offers a ranked menu of nine loop constructions (failing test → curl → trace replay → fuzz → bisection harness → differential → HITL bash script) plus loop-*tightening* as a first-class activity (faster, sharper signal, more deterministic).
- **The wizard: push execution to the human, but as a program.** For human-only steps (dashboards, secrets), the agent writes a bash script from a fixed template (progress, confirmation gates, hidden secret entry, `gh secret` writes) and **never runs it** — it verifies statically (`bash -n`, shellcheck, tracing that every `set_secret` matches a real `secrets.*` CI reference). Secrets never enter model context. "The first run is yours, and that run is the test."
- **The smart zone.** Context hygiene is codified: keep grilling→to-spec→to-tickets in one unbroken window; don't push past ~150k tokens of degraded reasoning; `/compact` at phase boundaries, `/handoff` for portability across sessions/directories/harnesses, sub-agents for scoped side tasks.

## Design decisions

- **Composability over process ownership** is the founding trade-off, and it has a cost the repo admits: no ledger ties grilling answers through to specs, tickets, and tests — precise decisions (ordering guarantees, numeric defaults) get softened into prose downstream, and the docs tell you to re-read the spec against your own answers. Compare Spec-Kit-style frameworks, which buy traceability at the price of a black-box pipeline.
- **Prose over tooling, mostly.** Almost everything is instructions; the only deterministic checks are packaging guards (version sync) and optional hooks (the `git-guardrails` skill blocks `push`/`reset --hard`/`clean -f` via a PreToolUse hook). `code-review` even instructs to *skip anything tooling already enforces* — a division of labor where linters own the mechanical and prose owns the judgement.
- **The ADR bar is deliberately high and the glossary deliberately narrow.** ADRs need all three of: hard to reverse, surprising without context, a real trade-off — so most sessions produce zero, and that's "working as designed." `CONTEXT.md` is "a glossary and nothing else"; the most-reported failure is models treating it as a scratch spec and ballooning it to thousands of lines.
- **Cross-harness neutrality.** Skills are invoked by Skill-tool name, never `/slash` syntax or cross-folder file links; `wizard` deliberately became model-invoked so agents reach for it when hitting a credentials wall. The cost: harness-specific quirks (Claude desktop dropping user-invoked skills) become upstream bugs you route around.
- **Honest failure documentation.** The docs pages ship with "it's working if" checklists and known-bug sections (arrow keys in the wizard prompt, silent file-writing loss under orchestration wrappers). That level of self-criticism is rare and changes how much you should trust the happy path.

## Comparison notes

- [[Matt Pocock — Grill Me, Then Go AFK]] is the earlier snapshot of the same thinking: this repo is that pipeline productized — grilling formalized into a frontier-round primitive, the smart zone now codified in `ask-matt`'s phase-boundary tree, and AFK implementation now flowing through tracked tickets rather than a single handoff.
- [[A Smart Bear Skills]] is the closest structural sibling — another personal skill package where skills *interrogate* rather than answer — but Cohen's skills are standalone Fermi-scorecard tools, whereas Pocock's compose into an explicit flow with an invocation lattice and a router.
- [[Agent Skills Library (dzhng)]] shares the composable-markdown-skills thesis (fog-of-war planning, spec-as-control-surface, per-slice verification) but is harness-portable by design, while Pocock's ships natively into Claude Code and Codex with per-harness invocation policy files.
- [[Claude Code Skills System]] describes the platform mechanics (SKILL.md frontmatter, progressive disclosure) this repo is built on; Pocock's contribution is what to *do* with those mechanics — particularly the user-invoked/model-invoked split and Skill-tool dependency convention, which the platform docs don't prescribe.
- Against [[When Spec-Driven Development Pays Off]] and the spec-driven canon generally: this repo agrees specs are the durable artifact (`to-spec` publishes to the tracker with a `ready-for-agent` label) but insists the spec be *synthesized from a settled conversation* rather than produced by a framework's mandated phase order.
- The `codebase-design` vocabulary (depth, seam, leverage, locality) and `domain-modeling`'s glossary discipline connect this repo to [[Vedana — Domain Models as Agent Context]] from the other direction: Vedana builds glossaries as runtime context infrastructure; Pocock maintains them as human-owned repo files the agent reads and updates inline.
