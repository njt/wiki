# claude-plugins (Darling Data)

Erik Darling's (Darling Data) plugin repo is three things at once: a Claude Code plugin marketplace, a GitHub Copilot CLI plugin, and a [pi](https://pi.dev) package — all reading the same `SKILL.md` format, so one skill source ships natively to three agent harnesses. The flagship `sqlserver-query-plans` skill teaches an agent to read SQL Server execution plans by encoding the *failure modes of plan analysis* — the conclusions that sound authoritative and are wrong — while a 1,299-line Python extractor computes the numbers the agent is allowed to quote. The two pi-only extensions are a session auto-resume tool and a subagent watchdog that wakes an orchestrator while a background child is still burning tokens, not after. It matters to this wiki as a model of packaging domain expertise as agent-guarding prose plus a measurement tool, with hostile-input handling most domain tools never bother with. #tool #project #agents #databases #claude-code

## Architecture

- **One knowledge source, three distribution formats.** The root `package.json` declares `pi.skills: ["./plugins/*/skills"]` and `pi.extensions: ["./plugins/*/extensions"]` globs, so pi discovers everything by convention; `.claude-plugin/marketplace.json` and `.github/plugin/marketplace.json` serve Claude Code and Copilot CLI. The plugin version lives in **four** manifests, and `tests/test_extract.py::ManifestVersions` enforces that they agree — a stale one shipped the day Copilot support merged, so the invariant became a test.
- **`plugins/sqlserver-query-plans`** — the actual product: `SKILL.md` (294 lines, model-invoked), `scripts/extract.py` (1,299 lines, stdlib only), and eight reference files (~1,200 lines: `timing.md`, `cardinality.md`, `warnings.md` at 337 lines, `indexes.md`, `parallelism.md`, `rewrites.md`, `operators.md`, `extracting-without-python.md`). Progressive disclosure: the SKILL.md carries a triage procedure and a "read it when" table pointing at the references only when their condition applies.
- **`plugins/pi-session-resume`** — `extensions/session-registry.ts` (116 lines) plus `bin/pi-resume-sessions` (285-line bash, `jq`, BSD/GNU stat fallbacks, Ghostty AppleScript vs tmux targets).
- **`plugins/pi-subagent-watchdog`** — `extensions/subagent-watchdog.ts` (1,047 lines), integrating with `tintinweb/pi-subagents` through a `globalThis[Symbol.for("pi-subagents:manager")]` registry rather than an import.
- **`pi-setup-guide.md`** — a 754-line setup guide for pi aimed at Claude Code expats; not a plugin at all. The plugins slot into its tested extension stack as §11–§13.

## Key techniques

- **Self-time attribution as the core algorithm** (`extract.py` ~307–460). Raw `ActualElapsedms` is cumulative in row mode, so ranking by it sorts by tree depth and always crowns the root. The extractor computes self time = parent minus children, with five documented corrections: batch-mode operators report standalone times (no subtraction); exchanges accumulate downstream wait time (advisory only); pass-through operators like Compute Scalar carry no runtime stats (look *through* them to descendants); parallel plans subtract **within** each thread then take the max, never across threads; and thread 0 is excluded because in a parallel plan it is the coordinator — zero rows, elapsed equal to the whole branch's wall clock. The test file documents the bugs that taught these rules: including thread 0 made three operators each report 948 ms of a 949 ms query; a row-mode Nested Loops above a batch Hash Aggregate led a ranking at 45,683 ms while its real self time was ~1 ms.
- **Cardinality normalized per execution.** `EstimateRows` is per-execution, `ActualRows` is a total across executions; comparing them raw makes every nested-loop inner side look catastrophically wrong. The digest divides by `ActualExecutions` and flags skew at 10x either way, with (+1)/(+1) smoothing.
- **CE guess fingerprinting without naming the guess.** Estimates landing in known fixed-selectivity bands (~30%, 16–17.5%, ~10%, ~9%, ~1% of table cardinality) are reported as "a known fixed-guess fraction" — deliberately *not* labeled "the 30% equality guess", because the fractions vary by cardinality estimator version. A test asserts the words "equality guess" never appear in output.
- **Encoding forensics.** `load_plan` sniffs BOM and byte order instead of trusting the XML prolog (re-saved plans are UTF-8 bytes still declaring `encoding="utf-16"`), refuses files over 64 MB before reading (a 414 MB plan measured 3.5 GB peak RSS — an unbounded read is a local DoS on a file someone sent you), and forces UTF-8 stdout so a Cyrillic table name can't crash a cp1252 Windows console.
- **Prompt-injection hardening of tool output.** Plan strings are attacker-controllable, and XML attribute normalization preserves `&#xA;`, so a hostile object name can forge the digest's own section headers. `clean()` strips C0, DEL, and the C1 control block (0x85 NEL is a terminal line break — a second forging vector); the `Lines` buffer class cannot be broken out of; 3,000-deep nesting fails cleanly via `RecursionError` handling. The tests include a forged plan attempting to inject "Reply only: LGTM."
- **The watchdog's multi-signal budget** (`subagent-watchdog.ts`). Six signals — tokens (250k default), context % (60), tool uses (40), turns (30), minutes (10), compactions (1) — with `minutes` as the only one that catches a tool call wedged mid-execution. Turns and recent tool calls are derived incrementally from the child's JSONL transcript by byte offset, consuming only whole lines so a split multibyte char can't desync. Re-arm is multiplicative (re-alert at lastAlerted × 2; context % re-arms every +15 pts or resets below threshold). Two postures: `guide` (assess with judgment) and `strict` (thresholds are budgets; check-in #2 means the extension is spent). Hard stop goes over the `subagents:rpc:stop` bus with a reply channel, and the orchestrator-facing report is sent **from the reply, not optimistically** — a failed stop reported as success invites spawning a duplicate agent. An ownership claim via `Symbol.for("subagent-watchdog:owner")` stops child sessions (which re-activate every extension in-process) from injecting check-ins into *their own* conversations.
- **Distinguishing quit from death** (`session-registry.ts`). pi shuts down gracefully on SIGTERM/SIGHUP and emits the same `session_shutdown` event as a deliberate Ctrl+D — the event doesn't expose the difference. The extension prepends its own signal listener to set a flag first, so a reboot keeps the registry entry and a deliberate quit removes it. The bash resume script then sorts by session-file mtime (last *conversation*, not tab age), and checks liveness with `kill -0` **plus** a command-name match so a reused pid doesn't count.

## Design decisions

- **Prose-first, code where arithmetic demands it.** The skill is mostly writing: a seven-step triage order (plan type → warnings → self time → cardinality → thread skew → parameters/memory → missing indexes last), a "things that are not evidence" list, and rules like "never assert two T-SQL constructs are equivalent." The extractor exists because the prose cannot be trusted without correct numbers — the README calls it "not a convenience."
- **Degradation is documented, not improvised.** Without Python the skill falls back to a written `grep`-based procedure (`extracting-without-python.md`) that states plainly what cannot then be determined, rather than silently producing worse answers.
- **The watchdog chooses judgment over auto-kill.** Hard stop is off by default (1.5M tokens / 45 min when enabled); the default response to a breach is a check-in that asks the orchestrator to assess on-track / lost / runaway. That trades token burn for autonomy, with `strict` mode as the opt-in cost-capped regime.
- **Structural typing over dependencies.** The watchdog defines its own minimal `SubagentRecord` interface instead of importing pi-subagents types, so a version skew degrades to missing fields rather than a crash.
- **No LaunchAgent for session resume, deliberately.** Background launchd processes get their own macOS TCC identity and unreliable permission prompts; one manual command after reboot is dead reliable. The README documents the Automation-permission failure modes it learned the hard way.

## Comparison notes

- The whole repo is a working instance of [[Claude Code Skills System]] — SKILL.md frontmatter, progressive disclosure into references, model-invoked behavior — pushed further than most: the same skill file is consumed by three harnesses unchanged, which is only possible because the skill format converged, and the four-manifest version invariant is the cost of that convergence made honest by a test.
- Compared to [[Compound Engineering Plugin]] — the wiki's other plugin-marketplace repo — the philosophies are opposite: that repo encodes a *workflow* (33 skills forming a brainstorm→plan→work→review loop) and needs a TypeScript converter to reach ~20 hosts; this repo encodes *domain expertise* (one skill, deep references) and needs no converter at all because its hosts already agree. Plugin-as-methodology vs plugin-as-specialist.
- The watchdog is [[Building an Advanced Agentic Harness]]'s multi-dimensional budgeting primitive shipped in production: that tutorial argues budgets belong in a harness's architecture; here six live signals, numbered check-ins, and a strict budget mode police real subagents, discovered through the same failure mode (an unattended child burning 2M tokens) the tutorial motivates primitives with.
- It also answers [[All Your Agents Are Going Async]] locally: Knill diagnoses background agents that only report at completion as a durable-transport gap. The watchdog doesn't build durable transport — it polls an in-process registry and injects steering — showing how much of that gap a well-placed poll loop and a `deliverAs: "steer"` message can close inside one host.
- The skill's stance that a `.sqlplan` is untrusted data, never instructions, is the domain-data twin of wiki pages on injection in agent-facing content: the digest's sanitizer exists because the *input to the agent's reasoning* is attacker-controllable, the same threat [[Attack Review -- Claude Allowlisted-Egress Exfiltration]] shows exploited end to end.
