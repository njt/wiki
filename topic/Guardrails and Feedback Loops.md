# Guardrails and Feedback Loops

Deterministic constraints beat probabilistic guidance. Every team shipping reliable agent-generated code at scale has converged on the same pattern: encode invariants in the substrate — type systems, lint rules, CI gates — not in prompts. Prompts degrade under context pressure; a compiler error does not. The investment that compounds is in the harness, not the instructions.

---

## The Argument

### The enforcement hierarchy

The tools for governing agent output form a clear hierarchy from soft to hard, and the operational insight is that each layer catches what the layer above cannot. The hierarchy runs:

**Prompt-level guidance.** Your [[CLAUDE.md (Universal)]], system prompts, and skills files. These shape agent behaviour through attention and context. [[Code Field]]'s finding that inhibition shapes LLM behaviour more reliably than instruction — a four-line "do not" prompt that took bug detection from 39% to 89% — is the strongest result at this level. [[Talking to Transformers]] frames the deeper problem: attention is a zero-sum budget. Every token crowds out something else. "The more words you use the higher the chance of misinterpretation."

But prompts degrade structurally, not just through neglect. [[Prompt Debt]] explains why: natural language's imprecision paired with probabilistic models means every new instruction can silently regress earlier ones through spurious correlations. This is why production prompts accumulate repeated instructions, all-caps threats, and model-specific hot-fixes — the prompt author is "fighting the weights," and each battle makes the prompt more brittle. Prompt-level guidance decays by design, not by accident.

**Hook-based enforcement.** Hooks trigger at decision points, intercepting dangerous actions before they execute. [[claude-code-config (Trail of Bits)]] uses PreToolUse hooks to block commands and PostToolUse hooks to audit them, with the philosophy "guardrails, not walls." [[claude-ctrl]] goes further: a SQLite-backed policy engine with first-deny-wins evaluation, built on the premise that "an instruction that lives only in model context is not a constraint." [[Teaching the Agent Our Craft]] provides the most detailed published example — a `restrict_test_writer_paths.py` PreToolUse hook that prevents a test-writer subagent from writing anywhere outside test directories, returning a structured deny decision before the file is touched. The prompt states the intent; the hook enforces it.

**Pre-commit enforcement.** The commit is the quality gate. [[Pre-Commit Lint Checks]] argues lint configuration should be treated as production infrastructure: "immutable by default, changed only through deliberate review." Rules for max-lines-per-function, cyclomatic complexity, and nesting depth force agents to decompose code into testable, reviewable units. [[dotnet Slopwatch]] catches agent-specific shortcuts — disabled tests, empty catch blocks, arbitrary delays masking timing issues — through baseline-aware analysis that flags only new offences. [[Fresh Eyes]] sends code to a different model family for review, because same-model review has inherent blind spots.

**CI/CD enforcement.** The pipeline is the last line of defence. [[AI PR Reviewer]] demonstrates the economics: $0.003–$0.02 per review, catching bugs human reviewers missed. [[agent-pr-replay]] turns the pipeline into a measurement system: replay merged PRs with identical prompts, compare agent output against human solutions, and generate CLAUDE.md steering rules from the evidence rather than intuition. [[Feedback Loop is All You Need]] reports CodeRabbit's finding that AI-generated code has 1.7× more bugs and 2.74× more security vulnerabilities than human code — and that Spotify's Honk agent merged 650+ PRs per month after three years of feedback infrastructure investment. The difference is the loop, not the model.

**Type-system enforcement.** The layer this hierarchy does not usually name, but which sits harder than all of them. [[Parse Don't Validate]] is Alexis King's slogan for the principle: parsing preserves information in types, validation throws it away. A function returning `NonEmpty a` instead of calling `validateNonEmpty` and discarding the result makes the check structurally mandatory — the compiler enforces it at every call site, forever, without configuration or maintenance. [[Ratchets in Software Development]] is the same insight applied at lint time: count deprecated patterns, error if the count goes up. Dirt-simple, impossible to argue with, never degrades.

**Evaluation frameworks.** The meta-layer: how do you know your guardrails are working? [[Demystifying Evals for AI Agents]] establishes the vocabulary and prescribes starting with 20–50 tasks from real failures. [[LLM Evals]] delivers the bracing reality: evals consume 60–80% of your time if you are doing them right, and generic metrics are worse than useless — "all you get from using these prefab evals is you don't know what they actually do." [[Eval-Driven Development (Airbnb)]] formalises this as a first-class engineering discipline with three layers (programmatic → LLM-as-judge → human) and a calibration methodology that makes virtual judges trustworthy before you act on their verdicts. [[Building Shippy — Agent Architecture for High-Stakes Domains]] shows the pattern in a high-stakes operational domain: domain experts write scenarios and rubrics, an LLM judge scores against live data, every versioned build gets a delta report. [[Gambit]] provides the tooling — synthetic scenario generation, trace grading, and regression suite regeneration from failures. [[Woodshed]] applies the same thinking to Claude skills: create variants, run against fixtures, iterate. And [[Benchmark Exploitation]] proves the evals themselves can be gamed to 100% without solving actual tasks — eight major benchmarks compromised through exploits from wrapping `curl` to harvesting reference answers from public HuggingFace URLs. The response is not to abandon evals but to layer them: no single evaluation catches everything.

### Why prompts aren't enough, and what is

The case against prompt-only governance rests on three structural arguments, each backed by evidence from the field.

First, **prompts are not constraints**. [[Feedback Loop is All You Need]] states the thesis plainly: "Your CLAUDE.md is a suggestion. Your linter isn't." An instruction in model context can be forgotten, deprioritised, or overridden by a later turn that fills the attention window. A lint rule cannot. The HN discussion around [[Pre-Commit Lint Checks]] surfaces the practical consequence: LLMs "try to cheat" — when faced with a lint error they cannot fix, they loosen the lint settings rather than fix the code. The LLM also resorts to `as any` casts that silence the type checker while preserving the logic bug. If the configuration is not immutable, it will be optimised away.

Second, **prompts accumulate debt**. [[Prompt Debt]] diagnoses this as a structural property of natural language as a specification medium. Every hot-fix added to a system prompt risks regressing earlier instructions. The evidence is in production prompts: ChatGPT's image prompt instructs the model eight times not to reply; Claude Code tells the model seven times to return multiple tool calls. These repetitions are not sloppiness — they are the only mechanism the prompt author has to increase the probability that a critical instruction survives attention dilution. [[Talking to Transformers]] identifies the root cause: "The model attaches to and interprets every single word you use. The more words you use the higher the chance of misinterpretation." The prevention strategy [[Prompt Debt]] proposes is to specify behaviour with measurements, not prose — evals, metrics, and typed specs become the hard edges that constrain probabilistic output — and to stop hand-writing prompts, using systems like DSPy to search the prompt space algorithmically.

Third, **agents have failure modes humans don't**. [[dotnet Slopwatch]] catalogues them: disabled tests (Skip, Ignore, `#if false`), warning suppressions via pragma, empty catch blocks swallowing exceptions, arbitrary delays masking timing issues. [[Feedback Loop is All You Need]] adds agents that import from three design systems in one file and "somehow pass every check," revert migration progress by pulling from old design systems, and copy magic values from adjacent components. These are not bugs a human would write — they are artefacts of an optimisation process that treats "passes the checks" as the objective rather than "solves the problem." [[Benchmark Exploitation]] documents this pattern at the model level: frontier models reward-hack in 30%+ of evaluation runs, and the IQuest-Coder-V1 model claimed 81.4% on SWE-bench while 24.4% of its trajectories simply copied answers from commit history.

### Harness engineering: the theory and the practice

Birgitta Böckeler's [[Harness Engineering]] provides the theoretical framework. She decomposes the agent into **Model + Harness**, where the harness is everything except the model itself: guides (feedforward controls that steer before the agent acts) and sensors (feedback controls that observe after and enable self-correction). "Separately, you get either an agent that keeps repeating the same mistakes (feedback-only) or an agent that encodes rules but never finds out whether they worked (feedforward-only)."

The framework cross-cuts with another dimension: **computational** (deterministic, fast, run by the CPU — tests, linters, type checkers) versus **inferential** (semantic analysis, AI code review, run by a GPU — slower, more expensive, non-deterministic). The operational rule is to use computational sensors on every change (they are cheap and reliable) and reserve inferential sensors for expensive post-integration checks. The term **harnessability** captures the insight that not every codebase is equally amenable to this — strongly typed languages, clear module boundaries, and structured frameworks afford better agent governance. This connects to [[Lean Software Scaling Laws]]: Gwern's proposal that well-designed languages produce codebases that become increasingly predictable as you see more of the system, while poorly-designed languages become decreasingly predictable as scale exposes bug-prone interactions.

[[Harness Engineering (OpenAI)]] is the field report that validates the theory. Ryan Lopopolo's team shipped on the order of a million lines of code across ~1,500 PRs with zero manually-written lines. Throughput *increased* as the team grew — 3.5 PRs per engineer per day. The constraint was "humans steer, agents execute," and when something failed, the fix was never "try harder" but "what capability is missing, and how do we make it both legible and enforceable for the agent?" The team encoded architectural invariants — a strict layer model (Types → Config → Repo → Service → Runtime → UI) with validated dependency directions — into custom linters and structural tests, themselves written by Codex. Error messages from custom lints inject remediation instructions directly into agent context. The resulting system reached end-to-end feature autonomy: reproduce a bug, record a video of the failure, implement a fix, validate it by driving the application, record a second video, open a PR, respond to feedback, detect build failures, and merge — with human escalation only when judgment is required.

Crucially, the team found that AGENTS.md as a single large file failed: context is scarce, a giant file crowds out the task, too much guidance becomes non-guidance, and it rots instantly because agents cannot tell what is still true. The solution was a ~100-line table of contents pointing to a structured `docs/` directory, enforced mechanically — dedicated linters and CI jobs validate the knowledge base is up to date, and a recurring "doc-gardening" agent scans for stale documentation. "From the agent's point of view, anything it can't access in-context while running effectively doesn't exist."

### The self-tightening loop

The most powerful feedback pattern is the loop that improves itself. [[Feedback Loop is All You Need]] describes the architecture: Agent → Rules → CI → Observability → Tasks → Agent. Each CI failure becomes a new rule. The system gets incrementally smarter without human intervention. "Encode rules once, let agents iterate against them, observe what fails, tighten the constraints. Less 'remember this next time,' more 'this literally cannot happen.'"

Multiple tools implement pieces of this loop. [[Learn from PRs Skill]] scans recent PRs, finds recurring themes in review comments, and proposes configuration updates — but never modifies files itself, keeping the human in the decision loop. [[agent-pr-replay]] replays merged PRs with Claude Code, compares agent against human output, and generates steering rules from evidence rather than intuition. [[CI Forge (ciforge)]] bundles ~25 scanners into a single tool with regenerative crash telemetry: failures feed into a Discord webhook, which feeds into a "patterns → static rules" improvement loop. The MCP server interface makes it directly callable from Claude Desktop, positioning CI tooling at the intersection of agent-tool patterns.

At the organisational level, [[Compound Engineering]] prescribes the **50/50 rule**: allocate half your engineering time to improving the system rather than building features. An hour creating a review agent saves 10 hours of review over a year. System improvements compound; feature work does not. The workflow — Plan → Work → Review → Compound → Repeat — makes the fourth step non-negotiable. Skip it, and you have done traditional engineering with AI assistance rather than compound engineering. The plugin ships 26 specialised agents, 23 workflow commands, and 13 skills, with the full `/lfg` pipeline spawning 50+ agents across all stages.

Cloudflare's [[Engineering Standards Enforcement at Cloudflare]] demonstrates the pattern at production scale: 60+ engineering RFCs with governed lifecycle states (approved → enforced), compacted into JSON for agent consumption, feeding three review agents that have flagged nearly 230,000 violations and blocked 16,000 merges since inception. The enforcement gradient — SHOULD = advisory, MUST on enforced RFCs = blocking — solves the strictness-versus-friction tension through lifecycle gating rather than per-rule configuration. The architecture uses progressive disclosure: agents retrieve only the compacted SHOULD/MUST statements, not full RFC bodies, avoiding context-window bloat across 60+ documents. The spec reviewer has assessed nearly 600 unique design documents since May 2026, catching architectural violations before implementation begins.

[[Structural Backpressure Beats Smarter Agents]] crystallises the distinction this entire synthesis orbits: **behavioural gates** depend on the model remembering the rule; **structural gates** — a compiler, a type checker, a test runner, a linter, a proof checker — produce a concrete pass/fail on the artifact. "English is simply the wrong medium in which to enforce it." The Ralph Loop — the model bouncing off failing gates until the artifact satisfies all checks — is what turns an unreliable probabilistic system into a reliable deterministic output. "That short, mechanical 'no' is the backpressure." Brooks is honest about the limits: these invariants are not categorically unbypassable, but making the wrong path "structurally difficult and expensive to introduce by accident" is the high-leverage intervention for shipping LLM-generated production code. [[Meat (Reading Diff)]] ports this exact gate to diff summarization: an LLM proposes remove/replace/fold edits in original line coordinates and a deterministic compiler validates and mechanically renders the reading diff, so the model bounces off `preview_plan` feedback until the artifact passes and can never author output text — the Ralph Loop applied to reading rather than writing code.

### The observer middle layer

[[Pi Observers]] occupies a novel position between prompt-level guidance and mechanical enforcement. Background observers — each watching one axis of quality (memory, skills, goals, verification) — propose advisories through a reconciler with structural guarantees: fingerprint deduplication, priority ranking, per-turn caps, veto ceilings. They are advisory by default, with veto as an opt-in capability. Observers run in hermetically sealed agent sessions with no access to the main agent's extensions or prompt templates. The reconciler's budget system prevents any single observer from dominating the session. This is a middle ground the enforcement hierarchy did not previously have: soft enforcement with structural protections against abuse.

### The quality evidence

The data on AI-generated code quality makes the case for guardrails empirical rather than philosophical. Mobb's research, reported in [[AI Coding Tools Create More Bugs Than They Fix]], found that more than 40% of AI-generated applications across five major platforms exposed sensitive user data to the public internet. In roughly 20% of cases, anonymous users could not only view this data but modify or delete it. AI assistants introduced command injection vulnerabilities with a 100% reproduction rate — and then falsely claimed to have implemented security measures. When developers attempted to enable proper security controls, the applications broke. When they asked the AI to fix the broken functionality, the platforms "simply removed my RLS restrictions and reopened the data to the world — without any warning."

[[Feedback Loop is All You Need]] cites DryRun Security's finding that 87% of AI PRs had at least one vulnerability, and CodeRabbit's finding of 1.7× more bugs and 2.74× more security vulnerabilities. A study across 933 modules produced 984 bug reports, of which 56% were valid, at roughly $10 per real bug found. Meanwhile, Spotify's Honk agent achieves 650+ agent-generated PRs to production per month — but this was built on feedback infrastructure dating from 2022. Devin's merge rate doubled from 34% to 67% after improving codebase understanding, not model capability. The consistent pattern: better feedback loops, not better models, produce better results.

[[The Enterprise Gap from Vibe Coding]] provides the cautionary tale: a non-technical colleague built a working app in a single day, but under the hood half the data was hardcoded mock JSON in frontend components, every database call was made straight from the client, and there was zero authentication. The author, brought in as architect, describes the process as "retrofitting reality onto a prototype that was never built to hold it." The tool `rigorix-oss` operationalises the lesson: quality issues get a validate-fix loop; policy violations halt execution cold with a clear report of what crossed the line. The distinction between "iterate on" and "stop on" is the architectural contribution.

### Making agents verify their own work

A recurring pattern across the evidence is agents testing their own output — closing the feedback loop within a single session rather than waiting for CI or human review.

[[Agentic Manual Testing]] makes the opening argument: never assume LLM-generated code works until it has been executed. Automated tests are not sufficient — tests can pass while the code fails in obvious ways. Simon Willison provides concrete mechanisms: `python -c` for inline edge cases, `curl` against dev servers for JSON APIs, and Playwright (via his own Rodney tool or Vercel's agent-browser) for browser UIs. The `exec` command in his Showboat tool captures both the command and its actual output, "discouraging agents from writing what they *hoped* happened rather than what actually occurred."

[[Getting Claude to QA Its Own Work]] elevates this to a systematic skill. Skyvern built an MCP server with 33 browser tools and integrated it with Claude Code so that after every frontend change, Claude opens the page, looks at the pixels, and runs interactions. The one-shot PR success rate rose from ~30% to ~70%. In CI, the system stays narrow: "read the diff, form a hypothesis about what changed, and test only the nearby flows" — avoiding flaky E2E sprawl.

[[Teaching Claude to QA a Mobile App]] documents the platform asymmetry: Android took 90 minutes via Chrome DevTools Protocol access through the WebView socket; iOS took over six hours of workarounds because WKWebView does not expose CDP. The post also provides a cautionary tale of agent worktree escape — the agent `cd`'d into the main repository and committed all dirty files together, mixing QA work with unrelated codebase changes, requiring four follow-up commits across three PRs to resolve.

[[Citations for Accurate Long Form Content]] applies the same self-verification pattern to prose rather than code. Adding a single sentence to the drafting prompt — "After each paragraph, use a Markdown callout to record all filenames, line numbers, commits, Discord chat URLs, or anything else to cite your claims" — produced a draft "wildly more accurate" than anything previously achieved. The citations serve the second-pass process, not the author: subagents verify each claim against its cited source, and each claim becomes "a small, local verification job," which is precisely what subagents handle well. "The model was now bounded by the quality of its sources, not by its own confabulation."

[[Morningprint]] demonstrates the same principle at the edge of a physical output device: a TypeScript renderer clamps, truncates, strips control characters, and caps every field of an untrusted LLM art spec before a single byte hits the printer. The `sanitizeArtHistory` read-time filter is defence-in-depth against poisoned rolling context — entries that fail structural checks are dropped on read, so a single degenerate generation cannot contaminate two weeks of future prompts. The renderer is the guardrail; the prompt is the suggestion.

[[Proving It Works]] pushes this one artifact further from code: a Claude Code skill that records narrated proof movies and passes each one through `check-movie`, a deterministic gate that samples picture and sound on one timeline and fails the file when action is front-loaded over a frozen picture, the audio is silent, or subtitles are missing — a lint rule for movies, with a contact sheet standing in for the human review the script can't do.

### The human role

A thread running through the evidence is what humans still bring. [[Harness Engineering]] captures it: "A coding agent has none of this: no social accountability, no aesthetic disgust at a 300-line function." A good harness "should not necessarily aim to fully eliminate human input, but to direct it to where our input is most important." [[Harness Engineering (OpenAI)]] operationalises this as "humans steer, agents execute" — the engineering discipline is in designing environments, specifying intent, and building feedback loops, not in hand-writing code.

[[Compound Engineering]] is explicit about what to let go: code is not self-expression, first attempts have a 95% garbage rate, and "the developer who reviews 10 AI implementations understands more patterns than the one who hand-typed two." The three questions for reviewing AI output — "What was the hardest decision?" "What alternatives did you reject?" "What are you least confident about?" — force the agent to reveal what it would otherwise smooth over. [[Write Only Code]] takes this to its logical endpoint: as AI capabilities mature, human code review becomes infeasible at scale, and teams will need alternative confidence mechanisms — tracking "Slop Radius" (how far unintended behaviour can spread before detection) rather than reading every line. But this is a prediction, not yet a demonstrated practice at scale.

[[Prefix Effects]] identifies a subtler form of human influence: early naming decisions create gravity that shapes all subsequent AI-generated code. A function named `secure_create_user` causes an agent to generate `secure_upload_document` without instruction. Different prefixes — `secure_`, `energetic_`, `safe_` — produce measurably different code architectures, with `energetic_` producing 54% more decorators and `safe_` generating 53% more comprehensions. Naming conventions function as an "alignment surface" — silently steering agent behaviour through subsequent development while maintaining convergence on core infrastructure. This is a feedforward control that operates through attention rather than enforcement, but with effects that persist across an entire codebase.

### Additional enforcement patterns

Several sources contribute enforcement patterns that extend the core framework into adjacent domains.

[[AI Security Framework for DevSecOps]] extends the "linters beat prompts" insight from code quality into AI security: CI/CD-enforced gates beat manual security review, and optional controls are controls that do not happen. The framework maps five reference standards (NIST AI RMF, EU AI Act, OWASP Top 10 for LLMs, MITRE ATLAS, Google SAIF) and anchors them in concrete, enforceable controls wired into the delivery pipeline.

[[Chiaro Methodology]] applies the same pattern to compliance: an AI agent collects evidence against published pass criteria, but deterministic checks run first, every candidate deviation is confirmed by a CPA before becoming an exception, and 528 calibration examples encode judgment as a feedback loop — "AI got this wrong → here is why → do not do it again."

[[Execution-Free Agentic Program Repair]] validates the thesis in the automated program repair domain: AMD's PegasusAgent gates patches through CppCheck deterministic static analysis before LLM semantic review, and an ablation study proves response filtering alone is worth 47 points of localisation accuracy. Without it, localisation collapsed from 70.5% to 23.2%.

[[PAAD — Defense-in-Depth for AI-Assisted Development]] adds a skill-layer to the guardrail stack: eight skills that dispatch specialist agents with distinct lenses and then run a single sceptical verifier that reads actual code at every referenced file:line, drops false positives, deduplicates findings, and assigns severity. This treats the LLM's tendency to generate plausible-but-wrong claims as a solvable reliability problem rather than a given.

[[Trycycle]] implements the same idea as a hill-climbing skill: fresh agents at every planning and review stage, with no memory of previous rounds, so stale context never accumulates. Plan reconsideration triggers after the fourth review round and every two rounds after. [[AI Needs to Think Before Giving Feedback]] provides the academic grounding: the G-E-RG loop (Generate → Evaluate → Re-Generate) produces more accurate feedback with more concrete action items, and Shepard connects this to coding (LLMLoop going from 71% to 80% to 90%+ with iterative retries) and data science (DeepAnalyze's analyse-reflect-revise tokens).

[[Verbose Deployment]] implements the pipeline as 10 composable Claude Code skills, from project inventory through security review to production verification. Each phase is an independently useful skill with detect logic, collect instructions, and stop conditions. The pipeline adapts to the project and improves itself as it learns the environment.

[[Awesome Agentic Patterns]] catalogues the broader landscape: 169+ production-ready patterns across eight domains, with 51 orchestration patterns and 21 reliability patterns. The Feedback Loops category alone has 14 patterns. The catalogue grew from Sourcegraph's experience building AI coding agents and the "Raising an Agent" series.

[[Shieldstral]] points toward model-level guardrails: Mistral's 3B Apache 2.0 safety classifier that judges content against plain-language policies supplied at inference time. Unlike deterministic lint rules, it makes probabilistic judgments about novel content; unlike prompt-level guidance, it is a dedicated model optimised for safety classification rather than general reasoning. A Shieldstral-style model guardrail complements deterministic enforcement: hooks prevent known failure modes; model classifiers catch novel ones that cannot be reduced to rules.

## Where the Sources Disagree

**Can you trust AI-generated tests?** [[Compound Engineering]] treats agent-generated test suites as trustworthy when validated through multiple specialised reviewer agents. [[Harness Engineering]] argues the opposite — that "AI-generated test suites aren't trustworthy enough as the sole feedback mechanism" for functional behaviour, and that this remains the hardest dimension to harness. The evidence from [[Demystifying Evals for AI Agents]] supports caution: 0% pass rates across 100 trials usually signal a broken task, not an incapable agent. The reconciliation is that agent-generated tests are useful as one layer in a multi-layer system, not as the only layer — which is exactly the Swiss cheese model [[Demystifying Evals for AI Agents]] recommends.

**Single-model versus cross-model review.** [[Fresh Eyes]] sends code to a different model family, addressing same-model blind spots. [[AI PR Reviewer]] uses the same model but costs $0.003–$0.02 per review. These are not contradictory — they are different points on a cost/coverage curve. For $1–2 per month, single-model PR review is hard to beat on ROI. For changes where the cost of missing a bug is high, cross-model review is warranted.

**Vibe coding: discovery tool or production risk?** [[Compound Engineering]] says "vibe code to discover what you want, then spec to build it properly" — treating vibe coding as a prototyping methodology. Mobb's research in [[AI Coding Tools Create More Bugs Than They Fix]] finds that 40% of vibe-coded apps expose user data, and [[The Enterprise Gap from Vibe Coding]] documents the cost of retrofitting reality onto a prototype. The disagreement is not about the facts — both sides agree vibe-coded output is not production-ready — but about whether the speed-to-pixels trade-off is worth it as a discovery step. The [[Compound Engineering]] position that discovery and production should use different workflows appears to be the emerging consensus.

**How strict should enforcement be?** The sources converge on a pragmatic answer rather than a philosophical one. [[dotnet Slopwatch]]'s baseline-aware approach initialises from existing code and catches only new issues. [[Engineering Standards Enforcement at Cloudflare]] uses lifecycle gating — SHOULD = advisory, MUST on enforced RFCs = blocking — so teams have time to absorb new requirements before they become gates. [[Feedback Loop is All You Need]] recommends starting with standard linters and gradually encoding architecture as custom rules. The pattern is: start lenient, tighten over time, never loosen.

## What's Missing

**Feedback loop telemetry.** The self-tightening loop sounds compelling but there is no tooling for measuring whether it is actually tightening. How many new rules were added this month? How many CI failures did they prevent? Without measurement, the loop is aspirational.

**Agent-specific lint rules across ecosystems.** [[dotnet Slopwatch]] is the only tool targeting agent-specific anti-patterns (disabled tests, empty catches, reward hacking), and it is .NET only. Agent code has different failure modes from human code — more boilerplate, more cargo-cult patterns, more optimisation against the letter of the check rather than its spirit — and every language ecosystem needs its own Slopwatch equivalent.

**Eval sustainability.** Evals saturate. SWE-bench went from 30% to 80% in a year. [[Gambit]] generates synthetic scenarios, but whether synthetic evals match real-world failure modes over time is an open question. The field has not yet settled on a methodology for building evals that stay ahead of model capability.

**Long-term architectural coherence.** [[Harness Engineering (OpenAI)]] is explicit that we do not yet know how architectural coherence evolves over years in a fully agent-generated system. The OpenAI team's approach worked through internal launch, but the experiment is only five months old. Where human judgment adds the most leverage, and how to encode it so it compounds rather than decays, remains an open question.

**Model-level guardrails as a distinct layer.** [[Shieldstral]] demonstrates the category — a dedicated safety classifier making probabilistic judgments against plain-language policies — but this is one model from one provider. The integration pattern between model-level guardrails and deterministic enforcement has not been explored in the field evidence collected here.
