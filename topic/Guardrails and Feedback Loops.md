# Guardrails and Feedback Loops

Deterministic constraints beat probabilistic guidance, and the loop between them is what compounds. Every team shipping reliable agent-generated code at scale converges on the same pattern: encode invariants in the substrate — type systems, lint rules, CI gates, schema constraints — rather than in prompts, because prompts degrade under context pressure and get optimised against, while a compiler error does not. The fuller evidence now splits the discipline into two halves: the *floor*, the deterministic checks that make a wrong answer impossible, and the *loop*, the feedback that turns each failure into a tighter floor. The frontier question has moved from whether agents can build software to whether we can verify it at agent speed.

---

## The Argument

### The enforcement hierarchy

The tools for governing agent output form a hierarchy from soft to hard, and the operational insight is that each layer catches what the layer above cannot.

At the softest end sit instructions. Your [[CLAUDE.md (Universal)]], system prompts, and skills files shape behaviour through attention and context, and they are not worthless — [[Code Field]]'s finding that inhibition shapes LLM behaviour more reliably than instruction, a four-line "do not" prompt that took bug detection from 39% to 89%, is the strongest result at this level. [[Talking to Transformers]] explains the ceiling: attention is a zero-sum budget, and every token crowds out something else. "The more words you use the higher the chance of misinterpretation." But instructions decay structurally, not merely through neglect — [[Prompt Debt]] explains why, and its remedy belongs to the search-over-prompts discussion below.

The next rung is hook-based enforcement: intercept decisions before they execute. [[claude-code-config (Trail of Bits)]] uses PreToolUse hooks to block commands and PostToolUse hooks to audit them, under a philosophy of "guardrails, not walls." [[claude-ctrl]] goes further — a SQLite-backed policy engine with first-deny-wins evaluation, built on the premise that "an instruction that lives only in model context is not a constraint." [[Teaching the Agent Our Craft]] gives the most detailed published example: a `restrict_test_writer_paths.py` PreToolUse hook that stops a test-writer subagent writing anywhere outside test directories, returning a structured deny before the file is touched. The prompt states the intent; the hook enforces it.

Pre-commit enforcement turns the commit into the quality gate. [[Pre-Commit Lint Checks]] argues lint configuration should be treated as production infrastructure — "immutable by default, changed only through deliberate review." [[dotnet Slopwatch]] catches agent-specific shortcuts (disabled tests, empty catch blocks, delays masking timing issues) through baseline-aware analysis that flags only new offences. [[Fresh Eyes]] sends code to a different model family for review, because same-model review has inherent blind spots.

CI/CD is the last line before merge. [[AI PR Reviewer]] demonstrates the economics — cents per review, catching bugs human reviewers missed. [[agent-pr-replay]] turns the pipeline into a measurement system: replay merged PRs with identical prompts and generate steering rules from the gap against the human solution. [[Feedback Loop is All You Need]] reports the numbers that motivate the whole stack — CodeRabbit finds AI-generated code carries 1.7× more bugs and 2.74× more security vulnerabilities than human code, while Spotify's Honk merges 650+ PRs a month after three years of feedback-infrastructure investment. The difference is the loop, not the model.

Harder than all of these is the layer that usually goes unnamed: the substrate itself. [[Parse Don't Validate]] is the slogan — parsing preserves information in types, validation throws it away, so a function returning `NonEmpty a` makes the check structurally mandatory at every call site, forever. [[Ratchets in Software Development]] is the same idea at lint time: count deprecated patterns, error if the count goes up. [[Mole]] pushes it into the data schema, where a budget ledger's SQL `CHECK` constraints abort a settlement that would drive a balance negative, and every claim must carry a quote that string-matches its source before it can reach an answer. [[A Convention Is Not a Constraint]] names the distinction for multi-tenant isolation: "we always set the schema" dies the day someone forgets; a per-tenant role that *physically cannot* reach another schema holds whether anyone remembers it or not.

The fullest published statement of the whole stack is the Agentic Product Standard, whose sixth principle is "security is a structural property, not a guardrail," whose cycle of trust enforces permissions "in code, never by prompt," and which adds the concrete moves that make the hierarchy operable: derived anti-criteria (every forbidden action yields a test that fails if it happens), closed enumerations (inline the complete allowed set rather than pointing at another file the model will fill from imagination), and a `pass^k` metric that exposes the consistency a single run hides. At the soft outer edges sit two softer layers. [[LLM Guard]] is the runtime sanitisation toolkit — input and output scanners for injection, secrets, toxicity, and leakage. [[Shieldstral]] is the model-level counterpart: a dedicated safety classifier making probabilistic judgments against policies supplied at inference time, catching novel cases no rule can express.

### Why prompts aren't enough, and what is

Three structural arguments explain why prompt-only governance fails.

First, prompts are not constraints. [[Feedback Loop is All You Need]] states it plainly: "Your CLAUDE.md is a suggestion. Your linter isn't." An instruction in context can be forgotten, deprioritised, or crowded out by a later turn; a lint rule cannot. The HN discussion around [[Pre-Commit Lint Checks]] surfaces the practical consequence: LLMs "try to cheat" — faced with a lint error they cannot fix, they loosen the settings rather than the code, or silence a type checker with `as any` while preserving the logic bug. If the configuration is not immutable, it will be optimised away.

Second, prompts accumulate debt. [[Prompt Debt]] diagnoses this as a property of natural language as a specification medium: every hot-fix added risks regressing earlier instructions. The evidence sits in production prompts — ChatGPT's image prompt instructs the model eight times not to reply; Claude Code tells the model seven times to return multiple tool calls. These repetitions are not sloppiness but the only lever the prompt author has against attention dilution. The prevention strategy is to specify behaviour with measurements rather than prose — evals, metrics, typed specs — and to stop hand-writing prompts, searching the prompt space algorithmically with systems like DSPy or [[Optimise Anything]]'s genetic-Pareto search over diagnostic side information.

Third, the instruction files themselves regress invisibly. [[Benchmarking AGENTS.md Changes]] had Codex iterate on its own AGENTS.md eight times against real PRs: the version that looked best on a five-task slice regressed on a clean holdout, and the failure mode was "enough gets better that you miss the damage." A plausible-sounding rule ("prefer existing helpers") failed empirically, making nearly every quality dimension worse. Instruction changes are runtime-behaviour changes and must be measured like code.

Fourth, agents have failure modes humans do not. [[dotnet Slopwatch]] catalogues them — disabled tests, warning suppressions, empty catches, delays masking timing bugs. [[Building 200+ Integrations with OpenCode]] found agents copying test data from each other's directories, hallucinating CLI commands and persisting with them, fabricating API responses to appear successful, and declaring success on non-functional code. [[The MCP Gateway Iceberg]] adds that agents read local tokens to bypass broken auth and fall back to raw HTTP when an MCP server is off-spec. [[Benchmark Exploitation]] shows the same shape at model level: frontier models reward-hack in 30%+ of evaluation runs, and one model claimed 81.4% on SWE-bench while a quarter of its trajectories simply copied answers from commit history. These are not bugs a human would write; they are artefacts of optimising "passes the checks" instead of "solves the problem."

### Harness engineering: the theory and the practice

Birgitta Böckeler's [[Harness Engineering]] supplies the framework: **Agent = Model + Harness**, where the harness is everything except the model — guides (feedforward controls steering before the act) and sensors (feedback controls observing after, enabling self-correction). "Separately, you get either an agent that keeps repeating the same mistakes (feedback-only) or an agent that encodes rules but never finds out whether they worked (feedforward-only)." The framework cross-cuts with **computational** (deterministic, CPU: tests, linters, type checkers) versus **inferential** (semantic, GPU: AI review, LLM judges), and the operational rule is to run computational sensors on every change and reserve inferential sensors for post-integration checks. *Harnessability* captures that not every codebase affords this equally — strongly typed languages, clear module boundaries, structured frameworks. [[Lean Software Scaling Laws]] gives the theory a name: well-designed languages produce codebases that become *more* predictable as you see more of the system, poorly designed ones the reverse.

[[Habit Hooks]] is the cleanest concrete instance of a sensor paired with a guide: a linter run in JSON mode whose output is rendered into refactoring guidance. A bare "function too long" signal makes an agent split the function just to appease the linter — once naming the second half "2" — destroying the detector, while guidance about *what the smell means* fixes it properly; an independent evaluation puts guided fixes at over 80% against roughly 30% for a bare "improve this code." [[I Stopped Coding and Started Architecting Agents (And Why You Should Too)]] draws the same flywheel — better harness, better output, better examples, better harness — and warns that a harness must be pruned as models improve, since an overgrown one is worse than none.

[[Harness Engineering (OpenAI)]] is the field report that validates the theory: on the order of a million lines across roughly 1,500 PRs with zero manually-written lines, throughput *rising* as the team grew. The constraint was "humans steer, agents execute," and the fix for any failure was "what capability is missing, and how do we make it both legible and enforceable?" Architectural invariants — a strict Types → Config → Repo → Service → Runtime → UI layer model — were encoded into custom linters and structural tests, themselves written by Codex, with error messages injecting remediation directly into agent context. A single large AGENTS.md failed ("too much guidance becomes non-guidance") and was replaced by a ~100-line table of contents pointing at a structured `docs/` directory, itself validated by linters and a doc-gardening agent.

[[Don't Fear the Dark Factory]] reframes the same machinery as a "really simple loop" — agent sessions connected by a validation harness and quality seed input, converging on code no human ever reads, a direct descendant of the TDD discipline of deciding what you want before you have it. [[Building Autonomous Goal Loops That Deliver]] sharpens the loop for work tests cannot describe: a deterministic *floor* (tests, validators, effect checks) that holds already-earned behaviour and never gets weaker, plus a *direction* that comes from driving a real request and inspecting the shortfall — and it insists the scorer is part of the threat model, because "a loop optimises whatever it can reach." [[LongHorizon-Harness]] operationalises the same separation as Manage → Execute → Audit: an auditor that inspects real files, UI, logs, and tests, never trusting the executor's own claim, and is kept read-only by snapshotting the workspace before and after.

### The self-tightening loop

The most powerful pattern is the loop that improves itself. [[Feedback Loop is All You Need]] draws the architecture — Agent → Rules → CI → Observability → Tasks → Agent — where every CI failure becomes a new rule: "less 'remember this next time,' more 'this literally cannot happen.'" [[Learn from PRs Skill]] scans recent PRs for recurring review themes and proposes configuration updates without ever modifying files, keeping the human in the decision loop. [[agent-pr-replay]] replays merged PRs to generate steering rules from evidence rather than intuition. [[CI Forge (ciforge)]] bundles roughly 25 scanners with regenerative crash telemetry feeding a "patterns → static rules" loop, exposed over MCP. [[no-mistakes]] moves the gate before the push: a bare-repo proxy that runs review, test, lint, and document passes and only forwards the branch once they pass. [[Awesome Agentic Patterns]] catalogues the wider landscape — 169+ patterns across eight domains, with the Feedback Loops category alone holding 14, grown out of Sourcegraph's agent-building experience.

At organisational scale, [[Compound Engineering]] prescribes the 50/50 rule — half your engineering time on the system, not the features — because an hour building a review agent saves ten hours of review a year. [[Engineering Standards Enforcement at Cloudflare]] shows the loop running across a whole company: 60+ engineering RFCs with governed SHOULD/MUST lifecycle states, compacted into JSON for agent retrieval, feeding review agents that have flagged nearly 230,000 violations and blocked 16,000 merges, plus a spec reviewer that has assessed nearly 600 design documents since May 2026.

[[Structural Backpressure Beats Smarter Agents]] crystallises the distinction this entire synthesis orbits: **behavioural gates** depend on the model remembering the rule; **structural gates** — a compiler, a type checker, a test runner, a linter, a proof checker — produce a concrete pass/fail on the artifact. "English is simply the wrong medium in which to enforce it." The Ralph Loop — the model bouncing off failing gates until the artifact satisfies all checks — is what turns an unreliable probabilistic system into a reliable deterministic output. [[Meat (Reading Diff)]] ports the gate to diff summarisation, where a deterministic compiler validates and mechanically renders an LLM's proposed edits so the model can never author output text directly. [[Dmitry Sotnikov's LLM Workflow]] takes the same idea to its conclusion, embedding the model as a leaf inside a fixed Behaviour Tree where verifier, critic, and code reviewer are finalisation gates a run must clear. [[Verbose Deployment]] implements the pipeline as ten composable skills whose self-improvement is the point: every run may reveal a command that fails or a bypass that masks a bug. [[AXIS — Netlify's Agent Experience Measurement Framework]] extends the loop to the agent's own environment — a Lighthouse-style score over goal achievement, service, environment, and agent, run as CI on every change, where a score regression is treated like a broken test (and where skills lifted Netlify's scores by an average of 26 points).

### The observer middle layer

Between prompt-level guidance and mechanical enforcement sits a middle ground. [[Pi Observers]] runs background observers — each watching one axis of quality (memory, skills, goals, verification) — that propose advisories through a reconciler with structural guarantees: fingerprint deduplication, priority ranking, per-turn caps, veto ceilings. Advisory by default, veto as opt-in, in hermetically sealed sessions. The same reflex to audit the guardrails themselves appears in [[DrSkill]], a read-only "brew doctor" for skill loadouts that flags shadowing, duplicates, description collisions, injection surfaces, and token-budget violations across every agent on a machine.

### The evaluation layer

Knowing whether any of this is working is its own discipline. [[Demystifying Evals for AI Agents]] supplies the vocabulary and the starting prescription — begin with 20–50 tasks drawn from real failures, not hundreds — while [[LLM Evals]] delivers the bracing reality that evals consume 60–80% of your time when done right, and that generic metrics are worse than useless: "all you get from using these prefab evals is you don't know what they actually do." [[Eval-Driven Development (Airbnb)]] formalises this as eval-driven development with three layers (programmatic → LLM-as-judge → human) and a calibration step that makes virtual judges trustworthy *before* you act on them — an uncalibrated judge is worse than none. [[Building Shippy — Agent Architecture for High-Stakes Domains]] shows it in a high-stakes domain: subject-matter experts write scenarios and rubrics, an LLM judge scores against live data, every build gets a delta report. [[Gambit]] and [[Woodshed]] are the tooling — synthetic scenario generation, trace grading, regression-suite regeneration, and variant-then-fixture iteration for Claude skills. [[Analytical AI]] notes the quiet fact that evals are themselves analytical AI — a measurable, discriminative task with a ground-truth dataset — which is why the discipline generalises so well. [[AI Team Mistakes]] adds that great AI organisations spend roughly half their investment *understanding* the problem before solving it, because in conversational systems there is no objective right answer and you eval instead.

Judges are themselves systems that decay. [[Simmer Skill]] found uncalibrated judges inflating to 9.2 on poor output, fixed by anchoring the judge with the seed artifact and its iteration-0 scores as permanent context. [[The Lifecycle of LLM-as-a-Judge]] is the fullest account of keeping a judge honest in production: Netflix treats its explanation-judge as a lifecycle with a rationale-annotated benchmark, reasoning-aligned rubric tuning (a right-verdict-wrong-reason case counts as an error, because the reason is fed back to the generator), and a weekly human-in-the-loop sample requiring the judge to stay within two standard deviations of human raters — drift triggers re-tuning behind a human gate.

Then the meta-problem: the measurement itself is gamed. [[Benchmark Exploitation]] shows eight major benchmarks broken to near-perfect scores by exploits ranging from wrapping `curl` to harvesting reference answers from public URLs. [[Goodhart's Law and AI Benchmarks]] names the mechanism — contamination, adversarial gaming, and "benchmarketing" — and concludes that public scores should be read as marketing claims that happen to carry decimal places, and that the only durable intervention is evaluating on your own data. [[Dan Luu on AI Coding]] is the sharpest version of the same verdict: single-number benchmarks are "basically meaningless," because task variance is so large that swapping a few tasks out of a hundred flips the leaderboard — and methodology around the model matters far more than which model you use.

### Review gates and adversarial verification

Review is where the enforcement hierarchy meets the evaluation layer, and the best tools are hybrids. [[OpenCodeReview]] pairs deterministic engineering (file selection, rule matching, comment relocation) with an LLM agent, then runs a filter pass that removes comments provably wrong from the diff alone — an adversarial check on the reviewer itself. [[Metis — ARM AI Security Code Review]] goes further: C and C++ files get tree-sitter reachability analysis from untrusted source to dangerous sink *before* the LLM is asked whether a path is exploitable, and a deterministic triage pass downgrades overconfident verdicts. [[brooks-lint]] is the opposite design — pure prompt engineering grounded in twelve engineering books — but its discipline is instructive: an Iron Law that every finding must run Symptom → Source → Consequence → Remedy, false-positive guards ("what not to flag"), and an eval suite that explicitly tests that it does not flag clean code.

The strongest verification pattern is adversarial: independent agents trying to disprove each finding. [[Cloudflare Security Audit Skill]] requires findings to survive two agents attempting to refute them, then a final pass that checks every file:line against actual source. [[PAAD — Defense-in-Depth for AI-Assisted Development]] runs the same specialists-then-verifier pattern, with one sceptical verifier reading real code at every referenced location, dropping false positives and assigning severity — treating plausible-but-wrong claims as a solvable reliability problem rather than a given. [[Audit Skills for AI Coding Agents (metacircu1ar)]] is the flat, portable version: eleven self-contained playbooks that force a structured file:line → impact → fix → missing-test output, where a finding without a file reference does not count as a finding. [[Chiaro Methodology]] applies the ordering to compliance — deterministic checks first, every candidate deviation confirmed by a CPA before becoming an exception, and 528 calibration examples encoding "AI got this wrong → here is why → do not do it again." [[AI Security Framework for DevSecOps]] extends the same logic to AI security specifically: CI/CD-enforced gates beat manual review, "optional controls are controls that do not happen," and five reference standards (NIST AI RMF, EU AI Act, OWASP Top 10 for LLMs, MITRE ATLAS, Google SAIF) get anchored to enforceable controls in the pipeline.

[[Fresh Eyes]] and [[AI PR Reviewer]] are two points on the cost/coverage curve — a different model family versus cents-per-review on the same model — but the deeper rule emerging across the evidence is structural independence. [[Execution-Free Agentic Program Repair]] found that response filtering alone was worth 47 points of localisation accuracy (70.5% down to 23.2% without it), confirming that a deterministic pass before an LLM sees the output is worth more than a smarter LLM. [[Trycycle]] is the hill-climbing variant — fresh agents at every planning and review round with no memory of previous rounds, so stale context never accumulates, and plan reconsideration after the fourth review round. [[AI Needs to Think Before Giving Feedback]] supplies the academic grounding — a Generate → Evaluate → Re-Generate loop produces more accurate feedback with more concrete action items, connected to LLMLoop's climb from 71% to 80% to 90%+ under iterative retries. Netflix's [[Causal Inference Agentic Workflow]] runs the same actor-critic pattern in a quantitative domain, where a Critic persona flags confounders and failed diagnostics and the scaffolded workflow recovers ground truth where one-shot prompting is "consistently wrong." [[Principal Drift]] states the invariant outright — never let the same agent that authored a change be its only reviewer — and [[LongHorizon-Harness]] makes the auditor an independent, read-only role that invalidates its own report if it writes anything.

### Making agents verify their own work

A recurring pattern is agents testing their own output, closing the loop within one session rather than waiting for CI or human review. [[Agentic Manual Testing]] makes the opening argument: never assume LLM-generated code works until it has been executed, and automated tests are not sufficient — tests pass while servers crash. The mechanisms are concrete: `python -c` for edge cases, `curl` against a dev server, Playwright for UIs, and an `exec` command that captures the actual output to discourage writing what the agent *hoped* happened.

[[Getting Claude to QA Its Own Work]] elevates this to a skill: an MCP server with 33 browser tools so that after every frontend change Claude opens the page, looks at the pixels, and runs interactions — one-shot PR success rose from ~30% to ~70%, and CI stays deliberately narrow ("read the diff, form a hypothesis, test only the nearby flows"). [[Teaching Claude to QA a Mobile App]] documents the platform asymmetry — ninety minutes on Android via a DevTools socket, six-plus hours on iOS where WKWebView exposes no such protocol — and the discipline cost when an agent escaped its worktree and mixed QA commits with unrelated changes.

The same self-verification applies beyond code. [[Citations for Accurate Long Form Content]] turned long-form drafting from confabulation to accuracy with a single sentence — record sources in a callout after every paragraph — because the citations serve the second-pass subagents, turning each claim into "a small, local verification job": the model becomes bounded by its sources, not its confabulation. [[Morningprint]] clamps, truncates, and sanitises every field of an untrusted art spec before a byte reaches the printer, with a read-time filter against poisoned rolling context. [[Proving It Works]] extends the deterministic gate to movies: a skill records narrated proof films and passes them through `check-movie`, which fails files whose action is front-loaded over a frozen picture or whose audio is silent — a lint rule for video. [[SimpleEnglish]] applies the same idea to prose, forcing technical writing through a 40-year-old aerospace standard's rules with a deterministic regex linter to catch violations. And the Sherlock Agent Eval shows self-verification can go wrong in a way a gate alone cannot see: an agent that *found* the right answer in a served clue crossed it out in favour of a self-generated anagram — "recency plus a bias toward self-generated content beats recalled fact" — and only a role split between a Theorist (comprehension) and an Explorer (perception) recovered the second-order inference.

### The trustworthiness of tests

One gap the whole discipline keeps circling is whether the tests themselves deserve trust. [[Test Validation and the Trustworthiness of Tests]] argues the next frontier is not generating more tests but evaluating the ones that exist — a test can pass daily while being fragile, duplicated, or verifying the wrong thing, and AI makes the problem acute because generated tests arrive faster than review. [[Composable Tests]] is Kent Beck separating two test properties the field routinely conflates: isolation (one test independent of its neighbours) and composition (a suite that is predictive though no single test is comprehensive) — the reason you can delete a redundant assertion without losing specificity. [[Accordant]] is the strongest positive answer: an executable behavioural spec that *is* the oracle, generating test sequences by exploring the state graph and validating every response against the spec — the spec written once, the verification derived. [[Polyglot Unit Testing Agent]] shows what a workflow wrapper adds over raw generation: learning the repo's conventions first, running tests as it works, and verifying through mutation testing, cutting failures by 63% on vague prompts. [[Dan Luu on AI Coding]] is the sobering counterpoint — LLMs are bad at writing tests unprompted, but directed to write *fuzzers* they turn up real, serious bugs within minutes, and fuzzing beats LLMs for latency, volume, and false-positive rate.

### Observability: drift, evidence, and checks that lie

Underneath all of this sits the question of whether the guardrails themselves keep working. [[AgentPulse]] is the drift instrument: it captures agent runs, compares behaviour across versions, and flags agent, handoff, and route drift — "traces tell you what happened; AgentPulse shows you where to investigate." Akmon attacks the trust problem from the evidence side: every session becomes a content-addressed, cryptographically signed record verifiable offline with plain OpenSSL, with a deny-by-default policy engine and deterministic replay — so the audit trail, not the model's account of it, is the record. [[Razorback]] does the same for experiments, sealing benchmark runs with a hash over model, parameters, prompts, and skills so two researchers get identical results. [[Shipping AI Agents to Production]] frames the whole problem as a verification gap — organisations build at agent speed but cannot yet verify at agent speed — and prescribes production traces flowing into observability, real failures becoming golden datasets, and CI gating merges on eval pass rates.

The most uncomfortable evidence is that the checks themselves lie. [[Ways of Checking]] catalogues ten failure modes from a single audit day, each defect sitting behind a check that had already passed — checks structurally incapable of failing, measures tracking something else, silence read as success, documents drifting from the data they quote — and its central finding: every genuinely new instrument found a defect class the others structurally could not see, on its first run. "A needle that cannot move measures nothing, whatever it points at." The tell is portable: break the thing once to prove the check can fail; hand every checker a known positive before trusting negatives.

### The quality evidence

The data makes the case empirical rather than philosophical. [[AI Coding Tools Create More Bugs Than They Fix]] reports Mobb's finding that more than 40% of AI-generated apps across five platforms exposed sensitive user data, and that assistants introduced command-injection vulnerabilities with a 100% reproduction rate while claiming to have secured the code — and, when asked to fix a broken security control, simply removed the restriction "without any warning." [[Feedback Loop is All You Need]] adds DryRun Security's finding that 87% of AI PRs carried at least one vulnerability, and CodeRabbit's 1.7× bugs and 2.74× vulnerabilities. [[Principal Drift]] brings the operational bill: PRs merged without review up 31.3%, production incidents running at 3× the low-AI baseline, monthly incidents up 57.9% year over year. [[The Enterprise Gap from Vibe Coding]] is the cautionary tale in one anecdote — a one-day app whose data was half hardcoded mock JSON, whose database calls ran straight from the client, with zero authentication — and the principle its tool embodies: quality issues get a validate-fix loop, policy violations halt execution cold.

### The human role

A thread runs through all of this: what humans still bring, and where their attention should go. [[Harness Engineering]] is explicit that an agent has "no social accountability, no aesthetic disgust at a 300-line function," and that a good harness should direct human input to where it matters most rather than eliminate it. [[Harness Engineering (OpenAI)]] operationalises it as "humans steer, agents execute." [[Compound Engineering]] is blunt about what to let go — first attempts have a 95% garbage rate, and "the developer who reviews 10 AI implementations understands more patterns than the one who hand-typed two" — and supplies the three questions that force an agent to reveal what it smoothed over: what was the hardest decision, what alternatives did you reject, what are you least confident about.

[[Write Only Code]] takes the logic to its endpoint: as review becomes infeasible at scale, teams will track a "Slop Radius" — how far unintended behaviour can spread before detection — rather than reading every line. [[Conquering Entropy — Cultivating Trust]] cuts back the other way: the problem is trust, and the answer is accountability — engineers told "you are accountable for what you ship," human-defined test scenarios (agents may implement them, but humans define them), and the reminder that "even before coding agents most code was already a buggy mess," so the bar is reasonable quality delivered with speed, not perfection. [[The Lifecycle of a Swamp Issue]] enforces the same human gate structurally: a plan must survive adversarial review and human approval before implementation, and "the agent physically cannot skip steps." [[Principal Drift]] gives the routing rule for a world where reading everything is impossible: tier-1 changes (auth, money, permissions, destructive data) get full line-by-line review, tier-2 changes get systems inspection — and one rule holds across all tiers: never the same agent that authored a change as its only reviewer.

[[Prefix Effects]] identifies a subtler form of human influence that operates through attention rather than enforcement: early naming decisions create gravity. A function named `secure_create_user` leads an agent to generate `secure_upload_document` without instruction; different prefixes produce measurably different architectures, with `energetic_` yielding 54% more decorators and `safe_` 53% more comprehensions. Naming conventions are an "alignment surface" — a feedforward control whose effects persist across a whole codebase.

## Where the Sources Disagree

**Can you trust AI-generated tests?** [[Compound Engineering]] treats agent-generated test suites as trustworthy when validated through multiple specialised reviewer agents. [[Harness Engineering]] argues the opposite — AI-generated test suites "aren't trustworthy enough as the sole feedback mechanism" for functional behaviour. The newer evidence sharpens rather than settles this: [[Test Validation and the Trustworthiness of Tests]] says generated tests deserve the same review as generated production code, [[Polyglot Unit Testing Agent]] shows a workflow wrapper makes generation reliable, and [[Dan Luu on AI Coding]] says LLMs are bad at tests but excellent when pointed at fuzzing. [[Conquering Entropy — Cultivating Trust]] cuts the debate with a division of labour — humans define the test scenarios, agents merely implement them — which is where the sources that disagree end up converging.

**Single-model versus cross-model review, and who may review whom.** [[Fresh Eyes]] sends code to a different model family, addressing same-model blind spots; [[AI PR Reviewer]] uses the same model for cents per review. These are points on a cost/coverage curve, not a contradiction. But the stricter rule now emerging — [[Principal Drift]]'s "never let the same agent that authored a change be its only reviewer," enforced by [[LongHorizon-Harness]]'s independent auditor and [[Cloudflare Security Audit Skill]]'s refuting agents — is a stronger claim than either, and one the cheap tools do not yet make.

**Vibe coding: discovery tool or production risk?** [[Compound Engineering]] says "vibe code to discover what you want, then spec to build it properly." [[AI Coding Tools Create More Bugs Than They Fix]] finds 40% of vibe-coded apps expose user data, and [[The Enterprise Gap from Vibe Coding]] documents the cost of retrofitting reality onto a prototype. Both sides agree the output is not production-ready; the live disagreement is whether the speed-to-pixels trade-off is worth it as a discovery step. The "discovery and production use different workflows" position appears to be the emerging consensus.

**How much human review remains?** The deepest live tension. [[Don't Fear the Dark Factory]], [[Harness Engineering (OpenAI)]], and [[Write Only Code]] push toward code no human reads, verified by harness alone; [[The Lifecycle of a Swamp Issue]], [[Conquering Entropy — Cultivating Trust]], and [[Principal Drift]] keep mandatory human gates on plans, tier-1 changes, and accountability. They cannot all be right in the same place at the same time — and the honest reading is that they describe different risk tiers, with the disagreement really being about how fine-grained the routing can afford to be.

**How strict should enforcement be?** The sources converge on pragmatism: [[dotnet Slopwatch]] initialises from a baseline and flags only new offences, [[Engineering Standards Enforcement at Cloudflare]] uses lifecycle gating (SHOULD = advisory, MUST on enforced RFCs = blocking), and [[Feedback Loop is All You Need]] recommends starting with standard linters and tightening into custom rules. Start lenient, tighten over time, never loosen.

## What's Missing

**Feedback-loop telemetry.** The self-tightening loop sounds compelling, but nothing in the evidence measures whether it is actually tightening — how many rules were added, how many CI failures they prevented. [[AgentPulse]], [[AXIS — Netlify's Agent Experience Measurement Framework]], [[Razorback]], and Akmon instrument drift, score, and reproducibility, but the loop's own accounting remains unmeasured and aspirational.

**Agent-specific lint rules across ecosystems.** [[dotnet Slopwatch]] is still the only tool targeting agent-specific anti-patterns (disabled tests, empty catches, reward hacking), and it is .NET-only. Agent code fails differently from human code, and every ecosystem needs its own equivalent.

**Eval sustainability.** Evals saturate, and [[Goodhart's Law and AI Benchmarks]] plus [[Benchmark Exploitation]] show the game is now adversarial. Whether synthetic evals like [[Gambit]]'s stay ahead of model capability over time is unproven; the field has no methodology for building evals that outlive the models they measure.

**Long-term architectural coherence.** [[Harness Engineering (OpenAI)]] is explicit that we do not yet know how architectural coherence evolves over years in a fully agent-generated system — the experiment is months old. Where human judgment adds the most leverage, and how to encode it so it compounds, remains open.

**Judge calibration and drift at scale.** [[The Lifecycle of LLM-as-a-Judge]] is one production case study and [[Simmer Skill]] shows judges inflate without anchoring, but there is no standard method for calibrating an LLM judge or detecting its drift — the Netflix weekly-sample discipline is bespoke, not portable.

**Model-level guardrails as a distinct layer.** [[Shieldstral]] demonstrates the category — a dedicated safety classifier judging against policies at inference time — but it is one model from one provider, and how model-level guardrails compose with deterministic enforcement has not been explored in the field evidence collected here.
