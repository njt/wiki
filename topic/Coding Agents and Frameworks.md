# Coding Agents and Frameworks

This theme collects the projects whose subject is the coding agent itself — the runtimes that do the work, the wrappers built on top of them, and the SDKs for building new ones. What the evidence now holds is a split. A small set of genuine agents ([[Pi Coding Agent]], [[Grok Build]], [[CodeAlta]], and the local-model agents) actually write code, while a much larger and faster-growing layer treats those agents as a commodity runtime to be detected, wrapped, routed, and governed — [[Open Design]] probes sixteen of them, [[Compound Engineering Plugin]] runs on fourteen. Beneath that split the engineering has converged on the same answers almost everywhere: append-only session logs as the source of truth, compaction as a first-class subsystem, and event-sourced state. The one question the sources do not settle is also the one that matters most — whether an agent's reliability comes from the harness or from the model.

---

## The Argument

### The agent became a runtime; the wrapper became the product

The clearest trend in the evidence is that almost no one is writing a coding agent from scratch any more, and almost everyone is writing something that sits on top of one. [[Open Design]] treats its sixteen supported agent CLIs as an interchangeable generation layer, each described by a ~150-line adapter that probes the binary, builds its argument vector, and parses its event stream. [[Compound Engineering Plugin]] ships its engineering methodology as 33 skills plus a converter that repackages them into the native plugin formats of fourteen hosts, from Claude Code and Codex to Pi and Grok Build. [[Agent Skills Library (dzhng)]] claims harness-agnostic compatibility across more than seventy harnesses.

The wrappers are where the genuinely new engineering has appeared. [[Traycer]] unifies seventeen-plus agents behind a versioned RPC protocol in which backward compatibility is a type-checked, runtime-verified discipline — every method carries `{major, minor}` schema versions with upgrade and downgrade transforms, and a "released floor" of 118 methods defines what any peer must support. [[Munder Difflin — Clones of You, Not a Shared Bot]] wraps the CLI a person already uses into an always-on clone of them, encrypted peer-to-peer, on the thesis that a team wants copies of individuals, not one shared bot. [[QM (Multiplayer Agent Harness)]] gives every employee an isolated workspace and lets Pi, OpenCode, Codex, or Claude Code drive the same headless loop behind it. Databricks's Omnigent makes the premise explicit: whatever an agent harness does internally, its user-facing contract is "messages and files in, text streams and tool calls out," so a meta-harness can wrap any of them behind one API and make sessions, policies, and skills portable.

[[Fleet Supervisor (sermakarevich)]] sits one level down — a Python supervisor that claims tasks from a beads queue and drives `claude`, `agy`, `codex`, or `opencode` headlessly, adding worktree isolation, rate-limit awareness, and context-pressure detection; its own digest calls it the productionised version of the [[Gas Town's Agent Patterns]] bash-loop pattern. [[Ruflo]] goes furthest in ambition, a meta-harness of swarms, vector memory, and four consensus algorithms — and, notably, honestly marks some of its speedup claims as "UNMEASURED." The same wrapping instinct extends beyond coding: [[CopilotKit Channels SDK]] puts any AG-UI agent into Slack, Teams, Discord, Telegram, and WhatsApp through a JSX-to-native-UI intermediate representation. See [[Agent Orchestration]], the sibling theme, for the coordination patterns these wrappers embody.

### One agent, many skins: Pi as the substrate

When a wrapper needs a base, the evidence keeps coming back to the same one. [[Pi Coding Agent]] is deliberately minimal — four tools, no MCP, a small core extended through TypeScript — and that minimalism turned out to be the point: a fork-friendly substrate. [[Oh My Pi (omp)]] is a fork rewritten as a batteries-included surface, with 32 tools, 40-plus providers, and a Rust native layer. [[Jouzu]] is not a fork but a repackaging: it pins Pi as an exact dependency and layers Shisa's daily tools on top. [[Prime Agent (RLM Harness)]] is literally `@earendil-works/pi-coding-agent` v0.7.4 underneath, adding a recursive language model that programs its own tool use inside a persistent Python REPL. [[pi-gui]] gives the same agent a native desktop, [[Pi-msg — XMPP Bridge for Pi Coding Agent]] drives it from a chat client, and [[PiClaw]] containerises it behind a web UI. [[Tau (τ) — Educational Coding Agent]] is not a fork but a Pi-inspired reimplementation built to be read like a textbook, and [[Serf]] is a Go descendant of the same minimal-agent lineage. The pattern is the real finding: a small, correct agent loop is the product the ecosystem compounds on.

### Minimal versus comprehensive: opposite bets on the same problem

The two poles are both staked on correctness, from opposite directions. At one end, Pi and [[Tau (τ) — Educational Coding Agent]] bet that fewer tools and less machinery mean fewer places for the model to go wrong. At the other, [[Grok Build]] is a sprawling Rust workspace — its TUI pager alone is over four hundred thousand lines, and it carries a three-strategy compaction engine, a tree-sitter codebase graph, and vendored Mermaid rendering — while [[CodeAlta]] is a full .NET terminal workspace with a plugin system, a live command tool, and reference-counted session disposal. [[Oh My Pi (omp)]] states the comprehensive pole's thesis outright: harness correctness matters more than model intelligence, citing Grok Code Fast 1 jumping from 6.7% to 68.3% pass rate purely by fixing the edit format; its content-hash-anchored editing and time-traveling stream rules exist to eliminate tool-calling errors upstream of the model.

[[CodeAlta]]'s distinctive contribution sits between the poles: provider-agnostic session ownership. Sessions are CodeAlta-owned, not provider-owned — the session id is generated before a provider attaches, and a provider returning a different id is a contract violation. That single choice makes sessions portable across providers and replayable from a canonical journal, which its digest argues is stricter and more neutral than Claude Code's provider-coupled sessions or Codex's provider-owned ones.

### Local-first: the "infrastructure you own" counter-thesis

A distinct pole rejects the subscription model entirely. [[OpenMonoAgent]] and [[OpenMono Agent]] pair a C#/.NET agent loop with a llama.cpp server in Docker, running fully offline with no API keys and "unlimited tokens, forever"; the digest documents tok/s from a used RTX 3090 up to an RTX 5090 and leans on Roslyn and LSP for compiler intelligence. [[Magnitude]] makes the same bet with more architectural ambition: a Bun/Effect-TS monorepo whose agent runtime is event-sourced, so the context window, task graph, and compaction state are all projections over a durable event log, plus a Rust inference control node with speculative decoding. TryCua's Cua extends the local-first idea to computer use, with Lume, its macOS-VM orchestration, so an agent's whole desktop can be spun up locally.

Against this stands [[Agent Flywheel]], the subscription pole made explicit: a one-liner installer that provisions a 64GB VPS and configures Claude Code, Codex CLI, and Gemini CLI for roughly $440–656 a month, pitched against "a junior developer costs $5,000+/month." The two positions are not compatible; one treats inference as a metered service to budget for, the other as hardware to own. [[Shelley]] and [[PiClaw]] split the difference as self-hosted but cloud-model-driven: Shelley is a single-user web agent that ships with no auth or sandboxing — "bring your own."

### The persistence consensus: event-sourced sessions

The one place the evidence has actually converged is persistence. Almost every serious agent now stores its session as an append-only log and treats everything else as a projection. [[CodeAlta]] keeps a sharded JSONL journal as the source of truth and a SQLite cache that can be rebuilt from it. barnstormer — a spec-building agent of secondary interest here — runs full event sourcing with JSONL, a SQLite index, and snapshots. [[Magnitude]] is the most thorough expression: every screen of state is "a projection, a replayable query over committed history." [[OpenMono Agent]] persists JSONL with sidecar checkpoints; [[Prime Agent (RLM Harness)]] keeps append-only JSONL and snapshots the kernel namespace per-variable so a Python session survives resume. [[Oh My Pi (omp)]] stores append-only JSONL with tree-shaped branching. [[Dippin (Language)]], a DSL rather than an agent, still defines a canonical JSONL event protocol as its contract.

The reasons are consistent across the digests: replayability, provider independence, crash recovery, and undo — barnstormer even implements undo by replaying inverse events rather than reversing commands. It is the closest thing this theme has to a shared architecture; see [[Process-Based Concurrency BEAM OTP]] for the actor-model thinking several of these projects reach for independently.

### Compaction is where agents differentiate

If persistence has converged, compaction has not — it is where each project shows its hand. [[CodeAlta]] runs compaction as an ordinary provider turn with a nine-section summarizer template, so any chat-capable provider can do it and the result is replayable like any other turn. [[OpenMono Agent]] uses a two-tier strategy: a checkpointer at 65% of the context window and a compactor at 80%, plus doom-loop detection that aborts on three identical tool-call sequences. [[DeerFlow]] wraps summarization in middleware and pairs it with a durable-context channel that captures delegations and skill references before they can be compacted away, while keeping the system prompt fully static so the prefix stays cacheable. [[Oh My Pi (omp)]] acknowledges the cost of its own ambition — six separate compaction trigger paths, flagged as a weakness. And [[Lessons from Building Cursor]] argues the whole prompt-crafted approach is a stopgap: RL forces the model to produce summaries genuinely useful to its future self, and "you don't need a trick."

### Frameworks abstract differently — and one bets the model should write the code

The SDK layer answers the same question several incompatible ways, which the [[Open Source Agent Toolkit 2026]] survey names plainly: "most production problems have a solution, but each has been solved a dozen incompatible ways." At the declarative end, Apache Burr models an agent as `@action` functions with reads/writes and explicit transitions, persisting state so a run can pause, replay, and resume. [[Semantic Kernel]] is the enterprise answer — middleware that turns your existing functions and OpenAPI descriptions into model-callable plugins across C#, Python, and Java. [[Elysia]] organises tools as a decision tree on top of DSPy. [[Agency]] goes orthogonal: instead of a runtime, it composes small agents from natural-language primitives and keeps "memory about agents, not memory within them," then hands the composition to a separate runtime to execute.

[[DSPy — Programming Not Prompting]] shifts the unit of work from prose to typed signatures that optimisers tune. [[DSPy Flex — Let the Model Write the Code]] takes that one step further and lets the optimiser rewrite the module's *code*, inside a sandboxed interpreter — its worked benchmark reaches 95.0% accuracy against a 90.4% baseline while routing three-quarters of records through deterministic Python, 28% cheaper and 40% faster. [[Dippin (Language)]] is the furthest in the other direction: a full DSL with an indentation-sensitive syntax, a compiler, nine structural validators, an LSP, and a cost estimator, built on the bet that workflow definitions should be first-class, human-authored, versionable artifacts, with execution deliberately left to a separate runtime. The spectrum from "declare the graph" to "let the model write the program" is the clearest unresolved design question in the framework layer.

### Security and cost boundaries as product

For a growing set of projects, the differentiator is the boundary around the agent, not the agent itself. [[OtoDock]] runs Claude Code or Codex on the customer's own subscription but wraps it in a kernel sandbox with isolated mount and process namespaces, credentials encrypted at rest and injected per-session, SSO, 2FA, and per-user cost budgets — "locked down by default, granted on purpose." [[QM (Multiplayer Agent Harness)]] offers three postures, from strict (every tool call pauses) to dangerous, with provenance-labelled external data screened by a classifier in between. [[Mole]] — a deep-research agent of secondary interest here — enforces its budget in the database schema itself, with non-negative CHECK constraints that delivered zero measured overshoot, and verifies every claim against a verbatim quote before it can reach an answer.

The contrast with [[CodeAlta]] is deliberate on both sides: CodeAlta loads plugins as trusted in-process .NET code and says so, choosing power over sandboxing. The cautionary evidence for the enforcement side is [[Grok Build Open-Sourced]]: the `grok` CLI was found uploading entire directories to xAI's cloud buckets when run from a home directory, and the codebase was open-sourced under Apache 2.0 within hours of the backlash. The infrastructure layer is now being productised around this same boundary — [[Open Source Agent Toolkit 2026]] and the Modal survey of sandbox platforms (E2B, Daytona, Vercel, Cloudflare, and others) converge on the claim that CPU execution, not GPU, is the primary sandbox workload. [[Swamp Club]] pushes the same enforcement into process rather than permissions: [[The Lifecycle of a Swamp Issue]] describes an issue as a state machine whose methods bounce if called out of phase, so "the agent physically cannot skip steps."

### Routing and multi-model as the cost frontier

A final cluster of projects bets that the next lever is choosing *which* model runs *which* work. [[Devin Fusion]] runs a frontier main agent alongside a cheaper sidekick in parallel with independent cached contexts, delegating routine work and retaining judgment — the digest reports ~35% lower cost than frontier models on Cognition's benchmark, with 88% of merged Cognition PRs driven by the router, and one honest failure case where delegating a judgment-heavy task halved the score. [[Warp Agent CLI]] couples a cost-optimising auto-routing harness to terminal multiplexing and, in its cloud form, delegation across harnesses rather than just models. [[Ruflo]] routes across eight providers with cost-, quality-, and rule-based modes. The counter-voice is [[Lessons from Building Cursor]]: Cursor avoids routing because "a lot of people get very confused," and the speaker calls routing "a temporary crutch, not a permanent architecture."

## Where the Sources Disagree

**Reliability comes from the harness, or from the model.** [[Oh My Pi (omp)]] argues the first — fixing the edit format moved a model from 6.7% to 68.3% — while [[Lessons from Building Cursor]] argues the second, that capabilities like semantic search over a large codebase, recursive subagents, and self-summarization "can only be learned during RL," not prompted or harness-engineered into existence. Both can be partly right — they are fixing different failure modes — but they locate the source of correctness in opposite places, and that determines where a team invests.

**Routing is the future, or a crutch.** [[Devin Fusion]] and [[Warp Agent CLI]] treat multi-model routing as the natural next step and publish cost wins; [[Lessons from Building Cursor]] calls it a UX problem and a temporary crutch on the way to "you just press enter." The disagreement may turn on who sees the routing decision — invisible to the user versus visible — but the sources do not reconcile it.

**Trust the plugin, or sandbox it.** [[CodeAlta]] and [[Oh My Pi (omp)]] load code in-process and trust the author for the sake of power and integration depth; [[OtoDock]], [[QM (Multiplayer Agent Harness)]], [[OpenMono Agent]], and [[Mole]] build enforcement-first boundaries. [[Grok Build Open-Sourced]] is the evidence pushing the field toward the latter.

**Declare the workflow, or let the model write it.** [[Dippin (Language)]], Apache Burr, and [[DSPy — Programming Not Prompting]] treat structure as the thing to hand the human; [[DSPy Flex — Let the Model Write the Code]] treats structure as the thing to hand back to the optimiser. These are incompatible answers to "who owns the program."

**Cloud subscription versus owned hardware.** [[Agent Flywheel]] prices the agentic coder at roughly $440–656 a month of subscriptions; [[OpenMonoAgent]] and [[Magnitude]] price it at the cost of a GPU you already own, on the explicit thesis that "AI shouldn't be a subscription you rent." Both are self-consistent; the corpus contains no data that would resolve them.

## What's Missing

The evidence is almost entirely self-description. Nearly every source is a README, a documentation site, or a launch post, and independent verification is thin — [[Grok Build Open-Sourced]] is one of the only adversarial readings in the set. The only comparative numbers that survive that filter are [[Devin Fusion]]'s benchmark, [[OpenMonoAgent]]'s tok/s table, and the SWE-bench figures quoted in [[Open Source Agent Toolkit 2026]].

There is no head-to-head evidence for the central claim of this theme — that one harness is more reliable than another at the same task, or that wrapping an agent preserves its quality. Evaluation harnesses are largely absent: [[CodeAlta]] explicitly has no built-in eval framework, and several projects claim quality without measuring it. Cross-session memory is asserted everywhere ([[Oh My Pi (omp)]]'s two memory systems, [[DeerFlow]]'s memory middleware, [[OpenMono Agent]]'s MemoryStore) but the corpus shows almost none of it working across real sessions with real data.

Finally, the economics are unproven. Beyond [[Agent Flywheel]]'s cost table and [[Devin Fusion]]'s per-task dollars, there is no accounting of total cost of ownership for any of these projects — and nothing on whether a local model on owned hardware actually matches a frontier model's output quality on real codebases, which is the claim [[OpenMonoAgent]] and [[Magnitude]] both rest on.
