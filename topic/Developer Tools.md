# Developer Tools

The tools collected here split along one fault line: who the primary user is. One breed treats the AI coding agent as the customer — it exposes CLI-first interfaces, machine-readable output and disposable infrastructure so a program can deploy, review, diff and file issues on its own. The other breed treats the human's own machine as the point — plain files on disk, no account, no cloud, nothing that stops working when a vendor does. The two camps disagree about almost everything, and still converge in the same two places: the terminal, once again the most ambitious surface in developer tooling, and the document, which a whole sub-industry is busy turning into something a machine can actually read.

---

## The Argument

**The agent becomes the user.** A growing set of tools is built for a program to drive rather than a person to click. [[Cloudflare Temporary Accounts for Agents]] mints disposable accounts an agent can create and discard, with `wrangler deploy --temporary`; [[Code Storage]] sells "off the shelf Git infrastructure for your AI application"; [[Google Workspace CLI]] is "built for humans and AI agents," and [[Google Workspace CLI Skills]] packages the skills that teach an assistant to drive it. The same assumption shapes developer-facing tools: [[Kata]] gives agents a structured, local-first place to record tasks and decisions, [[Macotron — macOS Host API for Coding Agents]] exposes the host machine to agents over a local API, and [[Chrome DevTools MCP — Debug Your Browser Session]] hands an agent the DevTools protocol so it can debug the browser it is using. Editors reorient too: [[Pencil]] is an agent-driven MCP design canvas, [[ProofEditor]] a collaborative editor "built for agents and humans," [[Collaborator]] arranges terminals and running code on an infinite canvas for agentic development, and [[Miren]] ships agent skills so a coding assistant can run a whole deploy. Distribution follows the same logic — [[sx]] is a team's "private npm for AI assets." A few tools go further and shape the agent's behaviour rather than its environment: [[Ponytail]] injects a "lazy senior developer" ruleset that makes an agent exhaust the standard library before writing a line.

**The local-first counterweight.** Against this stands a school that treats "no account, files on my disk" as the feature rather than the fallback. [[ctx – Agentic Development Environment]] is an agentic environment built local-first; [[Lovelace]] keeps a team's tickets, ADRs and session records as Markdown files in `.lovelace/`, with "no server, no cloud, no account"; [[Locker]] is self-hostable storage where you bring your own S3 or disk; [[tolaria]] and [[Introduction to Obsidian]] insist on plain Markdown files and "file over app" ownership. [[Local Review]] keeps code review on the machine, [[Doing]] transcribes voice without the audio leaving the Mac, [[Mist]] is collaborative Markdown with "no accounts, no vaults," and [[AgentsView]] advertises "one binary, no accounts, everything local." [[vibes-cli]] collapses whole apps into single HTML files with an embedded database, and [[Upwelling]] brings version control's branching to collaborative writing. The position is not nostalgia: these tools argue that local files are what keep a tool trustworthy when the other primary user is a program you may not fully control.

**The terminal renaissance.** The most technically ambitious work here happens in the terminal. [[cmux]] builds a multiplexer on libghostty; [[Zellij]] reimplements the multiplexer in Rust around WASM plugins and its own terminal emulator; [[Ratty]] turns the terminal into a GPU-rendered plane that can warp, rotate and embed 3D objects; [[VHS]] records terminal GIFs "as code"; [[Chawan]] is a from-scratch TUI browser; and [[grok-mermaid — Terminal Mermaid Renderer via WebAssembly]] renders Mermaid diagrams as Unicode box art. [[Hunk]] is a diff viewer, and [[Webwright]] argues "a terminal is all you need" for a web agent — the browser is disposable, the durable artifact is the code and logs in the workspace.

**Version control and review rethought for agents.** The collection treats version control as overdue for a rethink. [[DeltaDB]] starts from the claim that "software is made between commits"; [[sem]] is semantic version control at the level of entities rather than files; [[gh-stack]] makes stacked PRs a first-class GitHub workflow; [[Introducing git-wt — Worktrees Simplified]] smooths parallel worktrees; and [[Git Diff Drivers]] shows how to teach Git to diff non-text files semantically. On the review side, [[Meat (Reading Diff)]] abridges a diff into a "reading diff" that strips mechanical noise so a reviewer sees only the change to the program, and [[Twigg]] reimplements Google's Critique review system from scratch in Go, with trunk-based development and versioned commits as the default rather than the discipline.

**One source of truth, derive everything.** A recurring answer is to define once and generate the rest. [[Dev Containers]] makes `devcontainer.json` the single description of an environment and [[Container-Maker]] derives containers from it; [[TriadJS]] makes an API's specification, implementation, validation and tests literally the same TypeScript definition, then generates OpenAPI, typed clients and database schemas; [[Bookshelf (Self-Hosted Ebook Library)]] treats the library as regenerable from its sources.

**Document intelligence as a pipeline.** A large share of the collection exists to turn documents into something machines can read. [[markitdown]] converts formats to Markdown on the argument that Markdown is "highly token-efficient"; [[Kreuzberg]] and its successor [[Xberg]] extract text, tables and structure across a hundred-plus formats; [[pdf-inspector]] classifies PDFs in milliseconds so only the scanned remainder goes to OCR; [[Dolphin]] is ByteDance's universal document-parsing model; [[magika]] detects file types; [[docmason]] builds a traceable local knowledge base from office files; and [[Chunker (Document Chunking Tool)]] segments documents hierarchically. [[OpenWiki]] and [[DeepWiki]] extend the same idea to codebases, generating documentation wikis from a repository.

**Native versus Electron.** The old argument recurs, now with agents in the mix. On the native side, [[Zed]] is a from-scratch Rust editor from the Atom and Electron creators, [[cmux]] leans on libghostty, [[Lumide]] is a Flutter IDE with an agentic sidebar, [[ascdraw]] a "native, keyboard-first" diagram editor, and [[Gova]] a declarative GUI framework for Go. On the Electron side sit [[MarkText]], the agent command centre [[Broomy]], and the parallel-agent orchestrator [[Orca]] — a roughly 590,000-line TypeScript Electron app. [[tolaria]] splits the difference with Tauri. The disagreement is the familiar one — speed and polish versus the reach of the web stack — except that the thing being orchestrated is often an agent, which cares less about pixel polish than about reliable hooks.

**Watching the agents work.** With agents doing the coding, a new category has formed: observability for agent sessions. [[AgentsView]] browses and searches sessions locally; [[Cargento (Agent Cartography Dashboard)]] maps an agent's work; [[claude-replay]] turns transcripts into shareable HTML replays; [[session-analysis]] measures how long things actually took; [[engineering-notebook]] turns transcripts into an engineering journal; [[atifact]] converts agent logs to ATIF trajectories; [[Mindwalk]] replays a session as light moving through a 3D map of the codebase; [[Subspace]] and [[Subtext]] surface an agent's thinking; [[Xirp]] runs parallel sessions each in its own worktree; and [[Proving It Works]] records a narrated movie that proves software works, with a checker that rejects the frozen-picture defect that per-frame checks miss.

**Driving the desktop and browser programmatically.** [[xa11y — Desktop Automation via Accessibility APIs]] argues that accessibility trees are a sturdier basis for computer-use agents than screenshot vision; [[FlaUInspect]] browses the Windows UI Automation tree; [[Maestro (UI Testing)]] frames mobile and web UI testing; [[Talon]] controls a computer hands-free by voice and eye; and [[Browser Use]] and [[surf-cli]] hand an agent a browser. [[Webwright]] goes furthest, replacing step-by-step DOM interaction with code the agent writes and runs.

**Networking and remote as everyday tooling.** [[Headscale]] self-hosts the Tailscale control server; [[Tailcat]] and [[Tailport]] expose services across a tailnet; [[Tunnet]] builds a mesh VPN over QUIC; [[RustDesk]] is open-source remote desktop; [[Portless]] replaces port numbers with named `.localhost` URLs "designed for both humans and AI agents"; [[Cloudflare OAuth for All]] opens the Cloudflare app ecosystem to third parties; [[zeroserve]] serves sites from a tarball with eBPF request scripts; and [[Copyparty]] turns nearly any device into a multi-protocol file server.

**Simulate the cloud, locally.** [[Nektos Act]] runs GitHub Actions workflows in Docker before you push; [[floci]] is a free local AWS emulator; [[QuickEmu]] wraps QEMU so virtual machines "automatically do the right thing"; and [[The GUS Stack — Go, Unix, SQLite]] proposes a minimal shared stack precisely so agents stop rebuilding scaffolding. [[Windows in Docker]] and [[WSL Containers]] stretch the same idea toward Windows environments.

**Small, single-purpose utilities.** The purest expression of craft here is the one-job tool. Simon Willison's [[CORS Fetch Tester]], [[HTML Table Extractor]] and [[LLM Cliché Highlighter]] are single-purpose browser utilities; [[Music Decoy]] stops macOS launching the Music app by impersonating it; [[Castor]] casts web video to smart TVs; [[aispace]] is a "bot-friendly" temporary file drop for agents; [[Micasa]] is a home-maintenance TUI in Go. Diagramming and visualisation get the same treatment — [[TALA (Diagram Layout Engine)]], [[Flint Chart]], [[graphify]], [[json-render]] and [[SQL to ER Diagram]] each turn one kind of data into one kind of picture.

## Where the Sources Disagree

**Native versus Electron is unsettled.** [[Zed]], [[cmux]], [[Lumide]] and [[ascdraw]] bet that rewriting in a systems language is worth it; [[MarkText]], [[Broomy]] and [[Orca]] bet that the web stack and its ecosystem win. The evidence cuts both ways and nothing in the collection offers a benchmark that settles it.

**"Built for agents" points in two directions.** The agent-first tools disagree about where the agent should live. [[Cloudflare Temporary Accounts for Agents]], [[Code Storage]], [[sx]] and [[Orca]] assume an agent is best served by disposable, hosted infrastructure; [[Kata]], [[Lovelace]], [[ctx – Agentic Development Environment]] and [[AgentsView]] insist the same agent can work against plain local files with no account at all. Whether "agent-first" means more automation in the cloud or more sovereignty on disk is a genuine, unresolved split.

**Flattening documents helps tokens and hurts meaning.** [[markitdown]] and [[pdf-inspector]] treat "convert to Markdown, then classify" as the efficient default, on the explicit argument that Markdown is token-efficient for LLMs. [[docmason]] argues the opposite — that flattening office files into text loses "presentation layouts, spreadsheet relationships, formatting-based semantics" — and [[Xberg]] and [[Dolphin]] keep structure around for the same reason. The two sides are optimising different things: throughput versus traceability.

## What's Missing

The collection skews to the new and the indie. The dominant production tools — Git's internals, VS Code, JetBrains, the major build systems and package managers — are barely represented, so this page can say little about the mainstream against which these tools are a reaction. Many entries are product homepages with claims but no demonstration ([[Miren]], [[Pencil]]), so it is not always possible to separate a working tool from a launch promise. Almost nothing here measures whether agent-first tooling actually reduces errors or merely speeds up plausible-looking output — the one honest benchmark is [[Ponytail]]'s, and it is a single small study. Windows and mobile are thin relative to macOS and Linux, and there is little on the accessibility of the tools themselves.
