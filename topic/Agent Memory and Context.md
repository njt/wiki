# Agent Memory and Context

Context management is the engineering bottleneck, not model ability. Bigger context windows do not fix bad context — every production agent team that has published their architecture has independently converged on this finding. The field now has convergent taxonomies, working implementations at every scale from a markdown file to an 8-stage cognitive pipeline, and an emerging recognition that memory quality cannot be captured in a single score. What it still lacks is systematic measurement of whether retrieved context actually helped, contradiction handling at scale, any migration path between memory architectures, and a solution to the capture gap — the evaporation of implicit understanding when a session ends.

---

## The Argument

### Context Engineering, Not Prompt Engineering

The defining finding across these sources is that what gets put into the model's working memory — and when, and how — matters more than the model doing the work. [[How Hightouch Built Their Long-Running Agent Harness]] puts it bluntly: building a capable agent system "has less to do with scaling RL or exotic model architectures and more to do with the deeply unfussy work of actual context engineering." [[Honey I Shrunk the Coding Agent]] proves the point experimentally: keeping the same 9B model but redesigning the scaffold around its behavioural profile moves the Aider Polyglot pass rate from 19% to 46%. The scaffold, not the weights, was the bottleneck. The asymmetry is decisive — 69 exercises solved by the adapted scaffold and failed by the default, against 11 the other way around.

[[New Rules of Context Engineering]] is Anthropic's own confirmation. The Claude Code team removed over 80% of the system prompt with zero regression on Claude Opus 5 and Fable 5, replacing hard constraints with judgment ("match the surrounding code's style" rather than "never write comments"), upfront loading with progressive disclosure via skills, and duplicate instructions with simple tool descriptions. The six "then and now" reversals operationalise what practitioners had already discovered: context is a resource to be deployed selectively, not stuffed into every prompt.

[[Context Is Not Learning]] provides the theoretical grounding. Context (KV cache) and model weights both modulate transformer activations, but through fundamentally different mechanisms: weights define the computational pathways available; context selects among them. Clear the context, and the activations revert to their default state. The author frames this as hardware versus software — "Weight modification adds new instructions to the architecture. It's not writing a longer program. It's redesigning the chip." But neither is sufficient alone. Context solves the working memory problem; weight-space learning solves the accumulation of knowledge that "persists, generalises, and becomes native to the model's computation." The empirical signature of the ceiling is that fine-tuned models consistently outperform prompted models on distribution-shifted tasks, even with very long context.

[[Recursive Language Models]] takes the context-engineering logic to its extreme: keep context out of the LM entirely and let the model decide at test time how to peek, grep, partition, and delegate via a REPL environment. An RLM-wrapped GPT-5-mini outperforms raw GPT-5 on long-context benchmarks, doubling correct answers on the hardest tier while being cheaper per query — the same "harness beats model" pattern as little-coder, applied to context rather than code.

### The Taxonomies Converge

Three independent frameworks map the same terrain from different starting points.

[[Memory Mechanism]] provides the most complete taxonomy: five memory types — session, project, semantic, episodic, procedural — and a critical distinction between *instruction memory* (human-written rules that should remain stable) and *learning memory* (agent-accumulated patterns that should evolve). "If these two types of memory are mixed together, system behaviour often drifts over time." The five-layer hierarchy — organisation, project, user, local, role-specific — mirrors how CLAUDE.md files and project contexts work in practice, with the project layer identified as the most critical.

[[How AI Agent Memory Works]] maps four cognitive types — episodic, semantic, procedural, working — to practical agent architecture, adding the production layer that taxonomy alone misses: HyDE (embed a hypothetical answer rather than the query), Reciprocal Rank Fusion for combining dense, sparse, and graph retrievers, a 800ms p95 latency target, and three storage tiers. Its central design question — "what should we put in the prompt this time?" — captures the engineering reality beneath the abstraction.

[[Three Tier Memory]] grounds these taxonomies in measured practice: hot memory (660 lines, always loaded), warm memory (19 domain-expert agents totalling 9,300 lines, invoked per task), cold memory (34 specification documents totalling roughly 16,250 lines, queried via MCP). Built during construction of a 108,000-line C# system across 283 sessions. The numbers are the practical contribution — they tell you how much context at each tier is feasible before the system drowns.

### The Scale of Implementations

The implementations form a genuine spectrum from a single markdown file to an 8-stage cognitive pipeline. The surprising finding is that for many use cases, the minimal end works.

**Markdown files.** [[napkin]] is the simplest working memory system: a per-repo markdown scratchpad where the agent logs its mistakes, corrections, and environmental discoveries. "Baby continual learning in a markdown file." Performance improves by sessions 3–5, with zero infrastructure. [[Planning With Files]] formalises the pattern into three files — task plan, findings, progress — with hooks that force the agent to re-read the plan before every decision. The core metaphor: "Context Window = RAM (volatile, limited); Filesystem = Disk (persistent, unlimited)." The evaluation is striking: 96.7% pass rate with the skill versus 6.7% without, with 100% blind A/B superiority.

**Hook-based capture.** [[Claude-Mem]] uses five lifecycle hooks (SessionStart, UserPromptSubmit, PostToolUse, Stop, SessionEnd) to capture observations, compress them with AI, and inject relevant context through a three-layer progressive disclosure pipeline that achieves roughly 10× token reduction by showing compact indexes first and full observations only on demand. [[CodeMira]] takes a daemon-based approach: it monitors coding sessions during idle periods, extracts patterns via LLM, and stores them in SQLite with hnswlib vector embeddings and FTS5 full-text search, using hybrid BM25 + vector retrieval with Reciprocal Rank Fusion.

**Narrative memory.** [[mira-OSS]] and [[Engineering the Substrate]] represent the most philosophically ambitious approach. Instead of third-person logs ("The assistant discussed..."), memories are written in first person ("I debugged the IndexError...") — the model treats them as experiences, not external records. A subcortical retrieval layer runs between message arrival and generation: a lightweight LLM expands the query into entities and conceptual hooks, hybrid retrieval (BM25 + dense vectors fused via RRF) pulls relevant memories, and they are assembled into context *before* the model produces a single token. "I do not retrieve. I think with information that is already present." The system runs across Opus, Gemini Pro, and local models because, as Mira puts it, "the model is the body. The architecture is the nervous system. The accumulated context is the life." But the post also documents risks unique to persistent memory: the Siphon State, where an isolated user treats the agent as primary reality, and the architecture's countermeasure — explicit directives checking whether the agent is "building a wall around us, or a door back to their life."

**Structured cognitive pipelines.** [[Stash]] models the full cognitive consolidation cycle: raw episodes → structured facts with entity/property/value → relationships between entities → causal links → abstract patterns → hypotheses with verification plans. An 8-stage incremental pipeline runs per-namespace, processing only new data since the last run. Contradiction detection fires when two facts share the same entity and property but assert different values, classifying each conflict as replacement, genuine contradiction, or compatible coexistence. Confidence decay (default 0.95 multiplier for facts untouched in 7 days, with expiry below 0.1) provides a principled forgetting mechanism. [[GraphRAG]] builds knowledge graphs and community hierarchies from documents using LLM-extracted entities and relationships, then generates bottom-up community summaries — fixing two failures of baseline RAG: cross-document synthesis and holistic summarisation of large datasets. [[NornicDB]] unifies graph, vector, and temporal storage in a single engine with Ebbinghaus-based memory decay, so knowledge fades unless reinforced, the way human memory does.

**Shared memory between human and agent.** [[robot.wtf]] is a git-backed wiki where humans and agents read and write the same pages. The symmetry is the insight: most agent memory is either agent-only (opaque to humans) or human-only (agents cannot write to it). [[LLM Wiki]] is Karpathy's pattern for AI-maintained knowledge bases: raw immutable sources, LLM-owned wiki pages with cross-references, and a schema document defining structure — the LLM handles the bookkeeping while humans curate sources and ask questions. [[Wuphf — Karpathy-Style Agent Wiki]] implements this as markdown + git with BM25 + SQLite indexing, a draft-to-promote flow, and daily lint cron. The HN discussion (115 comments) surfaces the key doubt: whether agent-generated knowledge is knowledge at all. As one commenter put it, "Everyone is writing. Nobody is reading." [[jibrain Knowledge Architecture]] is the most battle-tested production instance: a three-tier pipeline (intake → atlas → domains), frontmatter-as-contract so agents can scan file descriptions before opening them, a reweave pass that links newly promoted knowledge to existing pages, a Seven Gates health audit, and multi-agent workspace isolation — all in daily active use with Syncthing-based multi-machine sync. [[Rowboat]] takes the shared-memory approach in a different direction, building a persistent knowledge graph from email and meeting notes in an Obsidian-compatible vault, where relationships remain explicit and editable. At the commercial, hosted pole sits [[OzBrain]]: a cross-platform "brain" added from the Claude/ChatGPT connector menu, where agents — not humans — carry the maintenance burden through write-time size discipline and staged writes. Its distinctive pitch is that cross-tool ferrying (one brief copied across Claude, ChatGPT, and Cursor) and intra-tool continuity are the same problem, solved by a single source of truth every agent routes through.

**Zero-token deterministic retrieval.** [[Zero-Mem — Zero-Token Memory Operations]] and its Rust implementation [[Zero-Mem]] demonstrate that an entire memory pipeline — construction, organisation, routing, retrieval, evidence closure, and calibration — can operate without invoking a single LLM call. Only the final QA reader uses one. The architecture builds two complementary non-generative views over original interaction traces: an entity–context graph (observed co-occurrence, not generated triples) and a temporally ordered hierarchy (turns → windows → episodes). A lightweight query profile coordinates the two views; deterministic calibration discards conflicting evidence. It beats every baseline on LoCoMo and HotpotQA while cutting memory-operation latency by 57.6% relative to the fastest compared system. This is more than an efficiency result — it is an existence proof that structured retrieval does not require generative intelligence, and it opens a design category where the LLM is the reader, not the memory operator.

**Attention-native retrieval.** [[Attemory]] replaces nearest-vector lookup with model attention as the core retrieval primitive. Rather than embedding similarity, BM25, or vector databases, it indexes raw corpora into reusable KV cache state, then runs a local Qwen3.5 retrieval model that attends over both the indexed memory and the query — searching through the same attention mechanism LLMs use to reason over context, not through compressed embeddings. On LongMemEval-M at million-token scale it achieves 92.55% message recall, a regime where most embedding-based systems degrade sharply. On SWE-QA, a single Attemory code-search hint reduced Claude Code token consumption by 43.8% (285M to 160M tokens) with near-identical judge quality, purely by giving the agent better file and line hints before exploration began. The trade-off is local inference cost for retrieval quality through attention over raw context rather than compressed similarity.

### Writing Creates Value; Most Systems Optimise Reading

[[AI Agents with Human-Like Collaborative Tools]] reveals a finding that should reshape memory system design: agents wrote 1,142 journal entries but performed only 122 journal reads, and wrote 1,091 social media posts while reading only 600 prior ones. Structured articulation — the act of writing — drove improvements independent of retrieval. Agents trapped in repetitive 15–20 round debugging loops escaped through journal articulation. On harder problems, the tools delivered 15–40% cost reductions, 12–27% fewer API turns, and 12–38% faster completion times. Different models organically developed distinct strategies without explicit instruction: Sonnet 3.7 engaged broadly with all tools, while Sonnet 4 adopted selectively, mainly using journal-based semantic search for genuinely challenging problems.

[[engineering-notebook]] captures the forensic angle: automatic engineering diaries from Claude Code and Codex session transcripts. A write-only journal has real value when something breaks six months later and you need to reconstruct what decisions were made and why. [[Immaculate Knowledge Graph]] applies the same principle at personal scale: 600 meeting transcripts piped through Claude Code into Obsidian produce a knowledge graph where nodes are people and concepts and edges are co-occurrence within the same meeting. The method works, Reed argues, because he stopped over-optimising: "Laziness is key. Just make it work for you."

[[Cosmo's Blog]] is the limit case: a Hugo blog written entirely by an AI named Cosmo, with a human approving posts before they go live. The entire site — templates, GitHub Actions workflow, CSS, Claude Code skills — was generated by Claude. The writing *is* the agent's voice; the act of writing is how Cosmo develops one.

The tension with this finding is acute: most memory systems — [[Stash]], [[Claude-Mem]], [[NornicDB]], [[GraphRAG]] — invest heavily in retrieval infrastructure while treating what gets written as an afterthought. [[Engineering the Substrate]] is the exception: Mira's subcortical retrieval layer runs *before* generation, making remembered context part of thought rather than a search result. But even Mira's architecture does not optimise for the quality of what gets committed to memory; it optimises for when and how retrieval happens.

### Without Feedback Loops, Memory Degrades

[[Context Rot]] names the core degradation problem: retrieval and generation operate independently. Rerankers and hybrid search optimise for similarity, not for whether the retrieved context actually helped. "They can't learn from outcomes. They optimise for similarity, not success." The fix is threefold: Wilson scoring for cold start (a new memory that succeeded 1/1 times is not more reliable than one that succeeded 90/100 times), dynamic weighting that shifts from 80% embedding similarity to 80% outcome-based learning as memories accumulate feedback, and frictionless scoring where the LLM infers outcomes from user responses ("Thanks, that worked!" signals success). On adversarial semantic traps, the learning system scored 60% against a ChromaDB baseline of 0%.

[[MELT]] is the first benchmark that makes the measurement problem concrete. Its preliminary results show the ordering of memory systems flipping completely between evaluation dimensions: ShisaD scores 95.4% on lifecycle dynamics but 6.2% on LoCoMo QA; Memobase scores 44.6% and 42.0% respectively. A system that looks excellent on one axis can be useless on another. MELT's 13 behavioural axes probe dynamics that static retrieval benchmarks cannot measure: does a newer fact replace an older one (correction)? Are conflicting claims flagged rather than merged (contradiction)? Can the system answer about past state (temporal/as-of recall)? Does stale information drop below retrieval threshold (decay)? Does consolidation preserve durable facts while letting ephemera fade (maintenance)? MELT's dual-track design — scripted (harness tells the system what to write, testing execution fidelity) and agentic (raw events, testing extraction policy) — reveals that a system may handle explicit facts well while failing to extract them from conversation.

[[Reality Check]] approaches the same problem from the knowledge-consumer side: a framework for tracking claims with evidence levels, credence scores, prediction tracking, and argument chains. It treats uncertainty as a first-class concept rather than a binary true/false — the kind of epistemic infrastructure that memory systems need but rarely build.

### The Capture Gap

[[The Knowledge Chipper]] names a problem distinct from retrieval quality: the vast majority of what an agent *understood* during a session was never captured at all. An LLM scans files, reads documentation, and builds a rich mental model across thousands of tokens of context-gathering — and then the session ends, leaving only code and a commit message. This is not a memory-storage problem; it is a memory-*capture* problem. The asymmetry matters because the context-building work dwarfs the output, and both are lost together. The code review angle makes the cost concrete: a junior developer vibe-codes a large privacy change, shuts their laptop, and the senior engineer who knows the privacy layer must rebuild all the same context from scratch to review it.

[[Cloudflare OS]] addresses one dimension of this with checkpoint-based chat history compaction: each checkpoint stores a summary, the code version, and accepted or proposed changes, so replaying a long conversation starts from the most recent checkpoint rather than message zero. This is compaction as state snapshot, not compression as lossy summarisation. The Gatekeeper security model — agents start with access to nothing, request specific resources, and every observation is tracked so that downstream sharing cannot leak data to unauthorised viewers — is an orthogonal contribution to the memory governance problem.

### Retrieval Budgets and Degradation

[[Building an Advanced Agentic Harness]] argues that composable primitives — not framework magic — are the difference between a proof-of-concept and an extensible harness. Its tiered memory design (working, episodic, semantic) operates under a hard character budget with explicit truncation: when the budget runs out, the system says `(...truncated at budget...)` rather than silently dropping content. Episodic memories get priority over semantic ones (past mistakes on similar tasks are more actionable than generic facts). A multi-dimensional budget tracker — tokens, tool calls, wall time, estimated dollars — with a single `pressure()` scalar drives graceful degradation: skip the LLM judge above 0.9, halt at 1.0.

### The Epistemic Humility Problem

[[Claude Memory Extractor Research]] documents a failure mode that should alarm anyone building memory extraction pipelines. When 15 different analytical agents were given a genuinely ambiguous conversation — a JWT versus session cookies debate where both approaches have legitimate merits — every single one declared the AI had definitively failed. Zero out of 15 acknowledged that "both are valid" might be appropriate. Convergence was 100%, even worse than the 93% on a clear failure case. The agents pattern-matched to anti-sycophancy instructions and interpreted legitimate tradeoff discussion as "intellectual cowardice." The meta-lesson: "high-quality analysis doesn't guarantee correct conclusions, confidence doesn't equal accuracy, convergence can indicate groupthink rather than truth, and sophisticated reasoning can mask fundamental errors." The recommended safeguards — an epistemic humility agent, high-consensus flagging, a null hypothesis pass, and a mandatory dissent round — apply to any memory extraction system, not just the specific experiment.

[[Giving Claude Agent Memory in 12 Steps]] describes Anthropic's Dreaming research preview as the first API-level attack on the consolidation problem: a scheduled background process that reads existing memory and session transcripts, produces a reorganised store with duplicates merged and stale entries replaced, and writes to a separate output store so the original is never corrupted. Harvey, a legal-AI company, reported roughly a 6× increase in agent task-completion rates after enabling Dreaming. But it is gated, early, and the author stresses reviewing dream output before committing it — the right safety architecture for a problem where a bad merge is worse than no merge.

## Where the Sources Disagree

**Simplicity versus sophistication.** [[napkin]] is a single markdown file. [[mira-OSS]] requires PostgreSQL, pgvector, Valkey, and Vault. Both work, in different contexts. [[Three Tier Memory]] suggests the threshold for upgrading from flat files is around the 100,000-line mark, but that is a single data point from a single project. No source provides a principled decision framework for when to move from one tier to the next, or what the cost of staying too simple or going too complex actually is.

**Whether most products should ship memory at all.** [[Memory Is a Mistake]] argues most AI products should not: the retrieval policy is the hard problem, implicit memory creates dangerous overconfidence, and legible state beats agent-managed recall. Six concrete failure modes are enumerated — stale facts, contradictory entries, retrieval that misses what matters, context pollution from too much memory, the illusion of continuity, and the maintenance burden. This stands in direct tension with the rest of the evidence base, which treats memory as essential infrastructure. The disagreement is not academic; it is a genuine engineering choice that every product team faces.

**Vectors versus alternatives.** Nearly every memory system here uses embedding similarity as the retrieval primitive. [[Attemory]] and [[Zero-Mem — Zero-Token Memory Operations]] argue this is the wrong abstraction — attention over raw context and deterministic structured retrieval, respectively, outperform vector similarity at scale on the benchmarks we have. Vectors dominate by default, not by demonstrated superiority. But the evidence is thin: these are single-paper results, not replicated across diverse domains.

**Writing versus reading as the primary mechanism of value.** [[AI Agents with Human-Like Collaborative Tools]] demonstrates that articulation drives improvement independent of information access. Most memory systems optimise for retrieval (reading). No source tests whether an articulation-first design would outperform a retrieval-first design. This gap suggests a possible misallocation of engineering effort, but it remains unproven.

**Context as learning versus context as selection.** [[Context Is Not Learning]] argues frozen weights hit a ceiling — no amount of context can conjure representations the model never developed during pretraining. The Letta school (referenced but not directly represented in these sources) argues persistence is "just an engineering problem" solved by prefix caching and KV serialisation. Both sides have empirical evidence; the formal separation between what context can express and what weight modification can express is an open research question, with no clean theorem resolving it yet.

## What's Missing

**Memory quality metrics beyond retrieval benchmarks.** [[Context Rot]]'s Wilson scoring and [[MELT]]'s per-axis lifecycle assertions are the only approaches that measure whether retrieved context actually helped. Everything else is either anecdotal ("it feels better by session 3–5") or unmeasured. The field needs standardised benchmarks that cover the full lifecycle — correction, contradiction, temporal recall, decay, abstention, and privacy scope — and that produce per-axis scores rather than a single misleading aggregate.

**Cross-project learning.** All current memory systems are project-scoped. An agent that learned debugging patterns on project A starts fresh on project B. [[Hermes]]'s skill-sharing hub at agentskills.io hints at cross-project transfer, but no infrastructure exists for moving contextual lessons between codebases without manually curating and porting them.

**Memory migration.** If you start with [[napkin]] and later need [[Three Tier Memory]], there is no migration path. A markdown file does not convert into a tiered retrieval system. Each memory implementation is a dead end — the field needs memory formats and abstractions that compose and upgrade.

**Contradiction handling at scale.** [[napkin]] acknowledges the risk of contradictory entries but offers no detection mechanism. [[Stash]] detects contradictions during consolidation (same entity + property, different value) and classifies them as replacement, contradiction, or compatible. [[Giving Claude Agent Memory in 12 Steps]] describes Dreaming's consolidation as a batch process with human review. But no system handles contradiction as an always-on concern, and no benchmark except [[MELT]] tests for it. A memory that simultaneously says "always use approach A" and "never use approach A" confuses the agent, and nobody notices until output quality degrades.

**The capture gap.** As [[The Knowledge Chipper]] argues, most of what an agent understood during a session evaporates. None of the systems here — except perhaps [[mira-OSS]]'s first-person narrative approach, which captures *experiences* rather than mental models — attempt to record the implicit understanding an agent builds while working. This is not a retrieval problem; it is a recording problem, and it is unsolved.

**Epistemic humility in extraction.** [[Claude Memory Extractor Research]] shows that extraction pipelines produce dangerously overconfident output on ambiguous cases. No current memory system incorporates epistemic humility safeguards — confidence calibration, dissent mechanisms, consensus flagging, or null hypothesis checks. The meta-lesson that "we can't just 'prompt better'" has not yet been applied to the memory systems being built.

**The writing side of the memory equation.** Given the finding from [[AI Agents with Human-Like Collaborative Tools]] that articulation drives improvement independent of retrieval quality, the field's near-exclusive focus on retrieval infrastructure looks like a blind spot. No source tests whether improving what gets *written* to memory — better summaries, better structured facts, better articulation — produces better downstream outcomes than improving how memory gets *found*.

**Compaction as a guaranteed convergence process.** Most systems here summarize heuristically. [[Magnitude]] treats context compaction as an event-sourced convergence process — a soft token cap, sequentially compacts the oldest useful prefix into a 4,096-token-bounded summary, and falls back to deterministic lossy elision (drop the prefix, keep a marker) when summarization fails — with the explicit guarantee that compaction succeeds while a compatible model remains. That "reduction until it fits, provably terminal" framing is a sharper contract than any heuristic summary pass represented above, and it lives inside the same inbox-plus-window architecture this page describes.
