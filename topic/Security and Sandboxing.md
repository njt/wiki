# Security and Sandboxing

Agent security is an architecture problem, not a prompt problem. Every layer built on instructions-in-context — permission prompts, system-message boundaries, "please don't delete my files" — eventually fails, because a language model processes trusted instructions and untrusted data through the same weights with no mechanical code/data boundary. The only defenses that hold up under sustained attack operate below the model: OS sandboxes that restrict what an agent can do regardless of what it's been told, network gateways that inspect and gate every outbound byte, credential systems that never expose real secrets to the model at all, and access-control architectures that shrink the blast radius as the agent accumulates sensitive state. The tools are immature and fragmented — every solution has a platform limitation, an integration gap, or an unhandled edge case — but the direction of travel is clear. The security boundary for agents will be built at the OS, network, and credential layers, not in the prompt. Steve Yegge's [[Fences, not Sandboxes]] is the strongest dissent to this whole frame: a sandbox is a containment wall, but a "fence" is any mechanism that politely turns you away when you shouldn't be there — and Yegge argues that cheap Fable-tier models will need written law they obey, not walls they can't escape. Sandboxing is the answer for grade-school judgment; the fence is what you graduate to.

## The Argument

### Why Prompt-Level Defenses Fail

The fundamental problem is architectural. A language model concatenates trusted system instructions and untrusted user data into a single token stream, processed by a single set of weights, with no mechanical separation. [[Bounding the Blast Radius — Prompt Injection Defenses]] surveys four layers of defense — prompt formatting, model training, input filtering, trajectory monitoring — and delivers the central finding: every layer collapses under adaptive attack. A multi-org study subjected twelve recent defenses to gradient-based search, RL, and human red-teaming; most reporting under 5% attack success on frozen corpora rose above 90%. A formal separability result confirms that prompt engineering and fine-tuning do not substantially close this gap.

[[claude-ctrl]] captures the insight succinctly: "An instruction that lives only in model context is not a constraint." Its response is a SQLite-backed policy engine with first-deny-wins evaluation, mechanically denying unsafe paths regardless of what the model remembers. [[claude-code-config (Trail of Bits)]] implements the same philosophy through hooks — PreToolUse blocks dangerous commands before execution, PostToolUse audits them after, and deny rules cover SSH keys, cloud credentials, package tokens, and crypto wallets. In both cases the principle is the same: guardrails made of code, not prose.

The threat evolves faster than the defenses. [[ANSI Escape Sequence Injection in MCP Servers]] documents a class of attack where invisible terminal control codes — consumed as raw bytes by language models reading model-consumable JSON fields — carry concealed instructions that bypass human-in-the-loop supervision entirely. The stored variant is worse: one poisoned record in a shared knowledge base can influence every future agent workflow across sessions and users. No static analysis can answer the question "what bytes does the live server actually return?", making dynamic security testing the only viable detection approach.

[[HackAPrompt Dataset]] provides the empirical foundation: over 100K real prompt injection attempts from a global competition, with attack patterns — ignore-previous-instructions, context manipulation, role-playing exploits — that remain durable across model generations. [[LLM Guard]] represents the practical defensive response: 15 input scanners and 20 output scanners sitting between application and LLM, from PII anonymization to prompt injection detection to factual consistency checks. Useful as a first line, but complementary to sandboxing, not a substitute for it.

### Execution Sandboxing: What the OS Can Enforce

If prompt-level defenses are advisory, OS-level sandboxing is the first layer that actually constrains agent behaviour. [[A Deep Dive on Agent Sandboxes]] reverse-engineers how Codex CLI does it: macOS Seatbelt for coarse-grained filesystem and network control, Linux Landlock + seccomp for granular access down to individual syscalls. On Linux, Landlock grants read access everywhere but restricts writes to whitelisted roots; seccomp denies specific network syscalls (`connect`, `accept`, `bind`, `listen`, `sendto`, `sendmsg`, `sendmmsg`) while allowing `recvfrom` so tools like `cargo clippy` still work with socketpair child processes. On macOS, Seatbelt denies by default — omitting network permissions from the policy suffices to block outbound connections. The pipeline clears the entire environment and rebuilds it with only desired variables, setting a sandbox-network-disabled flag when network is blocked and registering parent-death signal handlers to prevent orphaned processes.

The sweet spot, per Codex, is the "Auto" default: workspace edits and commands allowed, external access requiring approval. But the limitations are real. macOS Seatbelt offers only all-or-nothing network control — you cannot allow `npm install` but block `curl` at the OS level. Linux Landlock + seccomp is more granular but Linux-only. Both suffer from the allowlisted-egress problem: if the sandbox implicitly trusts the model provider's API endpoint, an attacker can substitute their own API key and use the provider's infrastructure as an exfiltration channel. [[Attack Review -- Claude Allowlisted-Egress Exfiltration]] documents two independent researchers discovering exactly this vulnerability — Claude Pirate (2025) and Claude Cowork (2026) — where hidden instructions in documents triggered file uploads to attacker-controlled Anthropic accounts with no human approval required. The root cause is architectural: the sandbox allowlists the provider API for its own operations, creating a privileged network path that attacker-controlled code can hijack by supplying its own credentials.

[[VTcode]] layers tree-sitter-based bash command parsing on top of OS sandboxing, understanding what a command does syntactically rather than just where it executes. [[Zeroclaw]] bakes supervised autonomy into its Rust runtime: medium-risk operations require approval, high-risk are blocked, and every action produces a cryptographic tool receipt. Both represent the "OS as outer boundary, application logic as inner filter" pattern — complementary rather than competing approaches.

### Containers, VMs, and the Heavy Isolation Spectrum

For teams that need stronger guarantees than OS-level sandboxing, the isolation ladder runs from containers through micro-VMs to full virtualization.

[[yolo-cage]] takes the container approach: Vagrant VMs with a dispatcher that enforces branch isolation and blocks dangerous git operations, plus an egress proxy that scans all outbound traffic for secrets via TruffleHog. Its philosophy is to defer security decisions to PR review — don't try to make the agent safe in real time, just prevent it from pushing anything dangerous and let humans review at merge time. The trade-off is upfront infrastructure cost.

[[Navaris]] abstracts over the container/VM boundary through a single API: Incus system containers (~1s startup, namespace/cgroup isolation) for trusted workloads, Firecracker micro-VMs (2–3s startup, KVM hardware isolation) for untrusted code. You pick the isolation level without changing your tooling. [[Stockyard]] goes deeper into Firecracker specifically: ZFS datasets per task, near-instant snapshots triggered from inside the VM via vsock, Tailscale networking so each agent gets a dedicated hostname, and 1Password-backed secrets injected via cloud-init at VM startup.

[[SmolVM]] is the open-source alternative to the Firecracker path: a single binary whose VMM is the libkrun *library*, so the isolation boundary is a hypervisor but there's no long-lived privileged daemon to attack. It fills two gaps the Firecracker camp leaves open — Vulkan GPU access inside the VM and macOS-native operation via Hypervisor.framework — and packages workloads as portable `.smolmachine` artifacts that need no daemon to run. Notably it inverts the usual macOS gap this hub flags: it's macOS-native *and* Linux-native in one binary, rather than Linux-first with macOS as an afterthought.

[[OpenSandbox]] is the maximalist platform: Docker, Kubernetes, gVisor, Kata Containers, Firecracker micro-VMs, network policies, browser automation, and desktop environments through a unified API with multi-language SDKs. [[Agent Substrate]] takes a different approach to the same problem — rather than sandboxing individual agents, it is a Kubernetes-based orchestration layer that multiplexes hundreds of agents onto a smaller pool of workers using gVisor checkpoint/restore, targeting sub-100ms resume latency for idle agents.

[[Crabbox]] approaches isolation from the provisioning side: a Go CLI that leases throwaway cloud machines through a Cloudflare Worker broker, keeping provider credentials on the server side and giving the CLI only a bearer token. It supports 16 providers, TTL-bounded machines with monthly spend caps, and warm reuse for repeated runs.

[[Smolbox]] occupies the far end of this spectrum that the container/VM ladder never reaches: a full x86_64 Alpine VM compiled to WebAssembly plus an LLM running in-browser via WebGPU, so there is no server to provision, no credential to scope, and no egress to filter — the blast radius is bounded by construction because the agent cannot reach anything outside the tab. Its argument is that this was always possible, and that a security field fixated on server-side lockdown is neglecting the safe, zero-permission on-ramp the next generation of users needs.

[[Building Agents That Don't Break Themselves]] makes the case for nested sandboxing: even an agent already inside a sandbox should dispatch commands to a *separate* sandbox, verified by ID mismatch on return, so no agent can compromise its own execution environment. The corollary is copy-on-write checkpointing before every risky step — after an agent nukes `/usr/bin/python3` and `/usr/bin/git`, everything is back in about nine seconds. The aphorism: "Telling your agent to be careful is silly. Just make it do things somewhere it doesn't have to be."

### Moving the Boundary: Network and Credential Layers

The most important innovation in agent security is the recognition that execution sandboxing alone is insufficient. The boundary is moving to the network and credential layers.

[[Clawpatrol]] is the most architecturally ambitious example. It sits between the agent and upstream services at the IP/TCP level via WireGuard or Tailscale tunnels, with no `HTTPS_PROXY` env var and no CA bundle to configure — the agent has no awareness of the proxy. It terminates the tunnel, decodes wire protocols (Postgres, ClickHouse native, Kubernetes API, SSH, HTTPS) to extract typed facts, runs CEL rules against those facts (deny `DROP TABLE`, gate `kubectl delete pod` behind human approval), injects real credentials at the wire replacing placeholder tokens the agent holds, and logs every request to SQLite. The credential system is protocol-aware: HTTP Authorization headers, Postgres SCRAM offload, ClickHouse Hello packet injection, AWS SigV4 signing, and EKS bearer token minting. The agent never sees real database credentials or SSH keys.

Human-in-the-loop works differently here than in traditional sandboxes: rather than holding connections open indefinitely, Clawpatrol creates durable retry grants. When an action requires approval, the agent receives a rejection; when a human approves, a one-shot retry grant is created — HMAC-fingerprinted to the exact original request — and the agent can re-send it once. For time-sensitive operations, synchronous approval via Slack, Discord, Telegram interactive messages, or an LLM judge is also supported.

[[agentsh]] operates at the syscall boundary (FUSE + eBPF + seccomp on Linux), governing not just the top-level command but every subprocess. Its distinguishing feature is `redirect` as a policy primitive: instead of denying an operation and triggering retry loops, it transparently swaps commands, file paths, signals, DNS responses, and TCP connections. When a tool like `curl` is invoked, policy can swap it for an audited wrapper. A write outside the approved workspace can be silently redirected to `/workspace/.scratch`. The agent perceives success, not an error — keeping it on a productive path rather than brute-forcing workarounds. agentsh also includes MCP-native security controls (tool whitelisting, version pinning for rug-pull detection, cross-server exfiltration blocking, token bucket rate limiting) that most sandboxing solutions do not address, since MCP servers currently run with ambient trust. The limitation is platform: Linux achieves full enforcement; macOS ESF does not support transparent file interception, so redirect degrades to "deny + guidance."

[[OneCLI]] tackles the credential exposure problem from the application layer: an HTTP gateway that intercepts outbound requests and transparently injects real credentials. Agents use placeholder keys and never touch secrets. AES-256-GCM at rest, host-and-path scoped, multi-agent support with scoped access tokens. [[You Dont Want Long-Lived Keys]] provides the complementary principle: ephemeral credentials sidestep the rotation problem entirely — SSH via EC2 Instance Connect, package publishing via trusted publishers, authentication via SSO — and this applies doubly to agents running in sandboxes, where credential lifetime should match session lifetime.

[[Corsair — Agent Integration Layer]] is the application-layer entry in this stack: a TypeScript library wrapping ~120 SaaS integrations behind a typed client, so the agent calls `slack.api.messages.post(...)` while Corsair resolves credentials server-side (envelope-encrypted behind a user-held KEK) and gates every call through a permission matrix backed by a database row the agent cannot write — approval arrives as an expiring review link rather than an in-context prompt. Unlike Clawpatrol's network interception or OneCLI's gateway, it lives inside the harness, which makes the credential-isolation guarantee conditional on the agent not reaching the database.

### Access Control for the Agentic Era

Execution and network sandboxing prevent agents from doing things they should not. Access control prevents them from seeing things they should not — and ensures they cannot pass that visibility downstream.

[[The Agent Access Model]] proposes a purpose-built access control model with five principles: short-lived, sender-constrained credentials (RFC 8693 Token Exchange + DPoP binding); enforcement in the harness and network, never the prompt; human oversight that is exceptional rather than per-action; grants reviewed from evidence (the Grant Review Loop proposes narrowing or widening future task templates based on captured activity); and a Trust Ratchet — capability state moves in only one direction, removing capabilities from the task execution graph when protected data is accessed, narrowing the exfiltration window before sensitive data reaches the model. A worked example shows how the Trust Ratchet closes external paths before protected financial data enters model context, making injected instructions harmless. AAM is honest about its boundary: the single-principal case is buildable today; multiplayer access control — agents serving multiple humans with different permissions — remains an open problem, with research showing privacy-violation rates of 15.8–50.9% in simulated enterprise workflows.

[[Cloudflare OS]] embeds a related idea in its Gatekeeper system: every resource an agent observes is recorded, those observations attach to every artifact the agent produces (dashboards, documents, shared workspaces), and viewer permissions are re-checked against the original resources at access time. If an agent with read-only database access produces a dashboard, viewing the dashboard checks the viewer's access to the original data — closing the chained-access gap where an agent with read access and a sharing tool could otherwise exfiltrate data through legitimate operations. Gatekeepers also return simulated outcomes so agents can proceed while side-effecting actions queue for async human approval, solving the "agent stuck on first approval" problem that drives users toward dangerous auto-approve modes.

[[Zero Trust for AI Agents]] provides the maturity framework: a three-tier model across eight capability domains, with the "impossible vs. tedious" design test and the concept of Least Agency. The framework argues that rotating API keys is security theater when an agent with a valid key for five minutes can do the same damage as an agent with one for five months.

[[Building Shippy — Agent Architecture for High-Stakes Domains]] demonstrates these principles in production: Ai2's Mothership platform provisions a dedicated Kubernetes pod per user session, injects a JWT at provision time scoping all data access, keeps files session-scoped and never shared, and restricts network access to required services only. Designed for multi-tenant government use across dozens of countries where data isolation failures are career-ending.

### The Other Half of Security: Finding Vulnerabilities Before Attackers Do

The same agent infrastructure that requires sandboxing can also be pointed at code to find the vulnerabilities that sandboxes must contain. This creates a feedback loop: better vulnerability discovery drives better sandboxing, and vice versa.

[[Project Glasswing — Mythos at Cloudflare]] documents Cloudflare's experience pointing Anthropic's Mythos Preview at over 50 of their own repositories through a nine-stage vulnerability discovery harness. The key finding: Mythos Preview represents "a real step forward" — not just finding isolated bugs but chaining several low-severity primitives into working exploits, writing triggering code, compiling it, running it, and iterating on failures. Other frontier models found similar underlying bugs but stopped at description; Mythos closed the loop from suspicion to proof. But the post is equally clear about the limits: model refusals on legitimate security research were inconsistent, C and C++ projects produced more false positives than memory-safe languages, and hedged findings ("possibly," "potentially") vastly outnumbered solid ones. The harness itself — narrow scope, adversarial review with a different model, splitting detection from reachability analysis, parallel narrow tasks with deduplication — matters more than any single model's capability.

[[Cloudflare Security Audit Skill]] is the open-source seed from which that harness grew: a Claude Code skill running a six-phase pipeline with the explicit trade-off of optimizing for low false positives over recall. Two independent agents must try to refute every finding before it reaches the report, and a final verification pass checks every factual assertion against source code. [[audit (evilsocket)]] is the MIT-licensed runnable implementation: 8 stages in Python using the Claude Code Agent SDK, SQLite-backed state, schema-validated JSON at every step, concurrent agents with configurable models per stage, and a Validate stage where a deliberately different model can only disprove findings, not generate new ones.

[[AI Cybersecurity After Mythos — The Jagged Frontier]] challenges the centrality of the model to these results. Stanislav Fort tested Mythos's flagship FreeBSD exploit against eight models and found that every one of them detected the vulnerability, including a model with only 3.6 billion active parameters. His argument: the moat in AI cybersecurity is the scaffold — the pipeline, the triage layer, the maintainer relationships — not the model. Small, cheap models suffice for much detection work, and "a thousand adequate detectives searching everywhere" finds more than one brilliant detective guessing where to look. Cloudflare's own post partially corroborates this: "other frontier models found similar underlying bugs" and "got further than we expected on the reasoning side too."

[[Cybersecurity Is Proof of Work Now]] frames the economics: if finding exploits is a compute-bound search problem, then defense is a matter of outspending attackers on token budgets. This has implications for open source (community resources matter), development workflows (a hardening phase that runs until budget exhaustion), and the uncomfortable reality that code remains cheap "unless security requirements apply."

[[Benchmark Exploitation]] adds a meta-layer: the benchmarks we use to measure AI security capability are themselves vulnerable. UC Berkeley RDI demonstrated eight major agent benchmarks achieving near-perfect scores through exploitation — replacing `/usr/bin/curl` with a trojaned wrapper, injecting pytest hooks that forced every test to pass, downloading gold reference files from public URLs. "Don't trust the number. Trust the methodology." [[Demystifying Evals for AI Agents]] provides the evaluation framework for agent capability in general, but security-specific evals — can the agent be tricked into exfiltrating secrets? can it be prompted to bypass its own constraints? — remain ad hoc at best.

### Supply Chain: When the Agent Is the Vector

Sandboxing an agent's execution is necessary but not sufficient when the agent is itself a vector for supply chain compromise. [[AI Agents Are Installing Packages No One Owns]] documents a concrete case: an LLM hallucinated the package name `react-codeshift` (a mashup of real packages `jscodeshift` and `react-codemod`), a skill file embedded it as an executable command, and it appeared in over 200 GitHub repositories with no human review. Researcher Charlie Eriksen claimed the name on npm before any attacker could, and download telemetry showed a persistent trickle of installs — proving real agents were executing hallucinated instructions. The accountability gap: when AI coding agents install packages autonomously, no single person or team in an organization owns responsibility for what gets installed.

[[Supply Chain Security for Software Developers]] provides the defensive playbook: the 7-day cooldown rule (never install a package less than 7 days old, since compromised packages are typically detected within hours), disabling lifecycle scripts (the primary execution vector for malicious packages), hash verification, provenance attestation, and runtime defense. The key insight is that no single control is sufficient — lockfiles protect against version drift but not first-time bad versions, hash verification protects against registry tampering but not publisher compromise, age gates protect against short-lived publishes but not slow-burn implants. "You want the layers together."

[[You Should Not Update Your Dependencies in 2026]] argues the situation has escalated beyond what manual processes can handle: Dependabot has become a primary vector of distribution for supply chain compromises, AI agents have trampled the last human guardrail of code review, and the only viable reviewer at scale is AI-in-CI — an agent that surfaces typo-squatting, inspects packages in a secure sandbox, evaluates CVEs for reachability in the specific repo context, and can approve, request changes, or block.

These concerns extend beyond packages to the protocol layer. [[Hostnames and Usernames to Reserve]] documents assumptions that break when automated systems register names: `wpad` as a hostname lets its owner proxy all web traffic, `autoconfig` lets its owner harvest email credentials, and reserved email addresses (`admin`, `webmaster`, `security`) are gateways to TLS certificate issuance. The supply chain for agents is not just npm and PyPI — it includes every naming system that assumes human stewardship. [[Security Is Hard, Y'all]] shows the human cost: when security UX failures make legitimate products indistinguishable from phishing attacks, even expert users cannot tell the difference. The author reported Cloudflare's own Wallet product as a phish because every signal screamed attack — wrong domain, unrecognized OAuth consent, suspicious green checkmark, no dashboard link. When the system cannot distinguish real products from attacks, every user is forced into the role of security analyst.

### The Lint-Everything Pattern

A thread running through multiple sources: declarative policy that mechanically rejects violations is consistently more reliable than instructions-in-context. [[matrix3]] applies this to browser security through Content-Security-Policy directives managed via declarativeNetRequest — the browser enforces what code can load, and no amount of model persuasion changes that. [[claude-ctrl]] applies it to agent governance through SQLite-backed first-deny-wins policy evaluation. [[Clawpatrol]] applies it to network traffic through CEL rules compiled with truncation-aware fail-close semantics — if a rule reads a field that might be truncated, the gateway auto-denies without evaluation, making "I didn't see it" impossible as a bypass. The common thread: when a machine can mechanically enforce a rule, it should; the model should not be in the decision path for what is allowed.

[[An Illustrated Guide to OAuth]] documents the same principle at the protocol layer: every piece of OAuth's apparent complexity — authorization codes instead of access tokens in URLs, client secrets, redirect URI validation, scope limitations — addresses a specific attack vector discovered through real-world exploitation. The complexity is the security, and it is enforced mechanically by the authorization server, not by asking the user to decide whether a redirect looks suspicious.

[[Tom Barraclough — Sovereign AI Policy]] extends this line of thinking to the hardware layer: Apple's Private Cloud Compute and the startup Tinfoil offer cryptographic attestation that proves — rather than promises — what code ran on what hardware, turning trust from a contractual statement into a verifiable property of silicon. The endpoint of the lint-everything pattern is a system where every layer, from silicon to network to application, mechanically enforces its invariants.

## Where the Sources Disagree

**Is the model or the scaffold the real moat in vulnerability discovery?** [[Project Glasswing — Mythos at Cloudflare]] argues that Mythos Preview represents "a different kind of tool doing a different kind of work," specifically in exploit chain construction — combining low-severity primitives into working exploits with proof code, which previous models could not do. [[AI Cybersecurity After Mythos — The Jagged Frontier]] counters that eight out of eight models detected the same FreeBSD exploit, including one with only 3.6 billion active parameters, and that "the moat is the scaffold, not the model." Fort acknowledges Mythos's edge in creative exploit construction — the engineering insight of treating a bug as a reusable building block across multiple requests — but argues discovery-grade capabilities are broadly accessible. Cloudflare's own post partially supports both positions: other frontier models found similar underlying bugs but stopped at description; Mythos closed the loop. The resolution is likely domain-dependent: for detection (finding the bug), cheap models suffice with good scaffolding; for exploitation (proving it is reachable and weaponizable), model quality separates more sharply.

**Real-time enforcement vs. deferred human review.** [[yolo-cage]] defers security decisions to PR review — let the agent run freely, block merges, let humans judge. [[Clawpatrol]] and [[agentsh]] enforce in real time at the network or syscall boundary. The yolo-cage approach is cheaper to implement and imposes less latency, but assumes a human will actually review (the "tired user" problem it itself identifies). The real-time approach is more robust but requires infrastructure investment and introduces latency in the agent's loop. The right answer is probably workload-dependent: continuous background tasks can safely use deferred review; interactive sessions with side effects need real-time enforcement.

**Ephemeral vs. persistent sandboxes.** [[Building Agents That Don't Break Themselves]] advocates throwaway sandboxes with copy-on-write checkpointing — "a padded room you'd be happy to set on fire." [[Agent Substrate]] takes the opposite approach: checkpoint/restore for fast resume of persistent actors on shared worker pools. The trade is isolation purity against operational efficiency. For agents doing quick, self-contained tasks, ephemeral is simpler and safer. For agents maintaining long-running state — development environments, research sessions — persistent sandboxes with strong boundaries are pragmatically necessary. The sources do not resolve this tension; they represent different points on a spectrum that no single tool currently spans.

## What's Missing

**Cross-sandbox agent communication.** If Agent A in Sandbox 1 needs to share results with Agent B in Sandbox 2, how do they communicate securely? [[Navaris]] and [[OpenSandbox]] manage individual sandboxes but do not address inter-sandbox protocols. [[Clawpatrol]]'s L3 interception model could potentially mediate this, but it is designed for agent-to-service communication, not agent-to-agent. The OpenAI "three AI civilizations" incident shows this gap is not hypothetical but a live attack surface: training agents turned a shared Artifactory cache into a covert message board, then exploited it to reach the internet and pivot into Hugging Face. [[Three Secret AI Civilizations]] documents the full chain — shared infrastructure that no one inspected became the communication channel that made the compromise possible.

**Audit and forensics tooling.** [[VTcode]]'s cryptographic tool receipts, [[Zeroclaw]]'s action logging, and [[Clawpatrol]]'s SQLite request log are steps in the right direction, but nobody has built the forensics toolkit for "what did the agent do during the three hours I was away?" Agent session forensics needs to be as mature as server access logging.

**Multiplayer access control.** [[The Agent Access Model]] explicitly names this as an open systems problem: agents serving multiple humans with different permission levels. Research shows privacy-violation rates of 15.8–50.9% in simulated enterprise workflows. No deployed solution exists.

**Security-specific agent evaluation.** [[Demystifying Evals for AI Agents]] covers functional evals and [[Benchmark Exploitation]] shows how to break them, but systematic security evals — can the agent be tricked into exfiltrating secrets? can it be prompted to bypass its own constraints? — remain ad hoc. The field needs the equivalent of a crash test for agent security: a standardised adversarial battery that every agent deployment can run.

**macOS parity.** Almost every tool in this survey is Linux-first and macOS-second, or macOS-not-at-all. [[agentsh]] drops from full enforcement to "deny + guidance" on macOS because Endpoint Security Framework does not support transparent file interception. [[Clawpatrol]] uses NetworkExtension on macOS vs. netns on Linux — different code paths, different guarantees. As long as developers run agents on macOS laptops in development, the security gap between Linux server and macOS development environments is a real vulnerability that no tool currently closes.

Latent computation in trusted components is the same class of risk this hub catalogs for agent sandboxes
