A project has a beginning, an end and usually a large temporary budget.


Modernization should be a permanent engineering capability. .NET now has a predictable annual release rhythm. .NET 11 RC1 already carries a production go-live license. Yet many organizations still wait several years, accumulate incompatibilities, then launch an expensive migration program to recover.


The longer they wait, the more exceptional the upgrade becomes. That is the real problem. A healthy modernization capability continuously maintains:

• Compatibility inventories.

• Characterization tests.

• Automated upgrade recipes.

• Performance baselines.

• Small, reversible pull requests.

• Explicit ownership of exceptions.


AI agents can accelerate much of this work. But the larger change is organizational: moving modernization from an occasional rescue mission into normal engineering hygiene. The best upgrade project is the one you no longer need to create.
