A repository tells an agent what a system currently does. It rarely explains why a boundary exists, which data must remain isolated, what resilience level is required, or which “inefficient” decision protects a regulatory obligation.


That context often lives in diagrams, documents and people’s heads. Humans struggle to find it. Agents may never know it exists. This is why I believe architecture as code is becoming much more than better documentation.


Work such as **FINOS** CALM ( **https://calm.finos.org** ) can give agents machine-readable intent: components, relationships, controls and constraints that can be validated before a change is accepted.


Imagine an agent that does not merely ask:

“𝘋𝘰𝘦𝘴 𝘵𝘩𝘦 𝘤𝘰𝘥𝘦 𝘤𝘰𝘮𝘱𝘪𝘭𝘦?”

But also:

“𝘋𝘰𝘦𝘴 𝘵𝘩𝘪𝘴 𝘤𝘩𝘢𝘯𝘨𝘦 𝘴𝘵𝘪𝘭𝘭 𝘤𝘰𝘯𝘧𝘰𝘳𝘮 𝘵𝘰 𝘵𝘩𝘦 𝘢𝘳𝘤𝘩𝘪𝘵𝘦𝘤𝘵𝘶𝘳𝘦 𝘸𝘦 𝘪𝘯𝘵𝘦𝘯𝘥𝘦𝘥?”


The next generation of AI-assisted engineering will need more than agents that understand code. It will need organizations capable of expressing architecture in a form both humans and machines can challenge.
