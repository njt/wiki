Intelligence as Infrastructure — Igor Sevo, Craft 2025

1. Key Points: The Company Is Already the Agentic Runtime

Conversational chatbots are commodity; proactive, UI-shaping agents are the direction. The differentiator is agents that initiate contact, act while unprompted, render the UI as ad-hoc HTML as you converse, and personalize from ingested user data. His verdict on request-response bots: "obsoleted in a couple of months."

RAG doesn't require ML expertise. A routing-agent architecture ("B-tree inspired") — routing agent → category agents → leaf agents that alone touch databases — lets traditional engineers build retrieval without embeddings. HTEC has had "a lot of success doing this, especially in the POC stage."

Automation is reductionist decomposition. Interview the people doing a process, replicate each step with an individual agent, present a UI only where replication fails; over time agents absorb the UI. Partial automation still pays: filtering 70% of files in a review pipeline saves 70% of the work.

Developers should build private agent tooling now. His extended-reasoning agent — fan out clones of a main prompt plus a revision prompt across multiple models, majority-vote the results — took four hours to build with Copilot and ChatGPT. Metaprompts auto-generate the revision prompts so the whole system is used like a chatbot.

Treat prompts as code, but deploy them on a separate pipeline. One repo, two CI/CD flows: code changes redeploy the app; prompt-folder changes push to a prompt store (Azure Blob) without redeployment. Template with composition and inheritance so ethics/bias review becomes possible later.

Ethics is regional plumbing. The same codebase can run in West Coast US, the Middle East, and Japan, pulling different prompt repositories and different models per region. "Practical ethics": alignment "varies according to the time zone and culture."

AI-assisted code rots without enforced refactoring. Interjecting AI into the dev loop means committing far more often and refactoring every 3–5 steps, because duplication and "poor code written over time by these systems" accumulate fast. Vibe coding is for prototypes only; "you cannot be a poor engineer" to use AI well.

Rising entry thresholds demand automated onboarding. If trends hold, "junior developers will never enter the workforce" — so automate onboarding itself: chatbots that actually test learners, automated tech leads, per-level bots. HTEC already runs a "hand-holding tech lead" for juniors.

Protocols are the substrate of generality. MCP and A2A let exposed tools and copilots interoperate and "merge into more and more complex agents" — the basis of an architecture he built for a Middle East real-estate giant.

The frontier: fine-tune for behavior, not conversation. Models are eager to talk; automation needs them to act. His prototype fine-tunes on XAML operations with agents writing to shared object storage — turn-based conversation emerges from behavior. The "agentic runtime" executes text via two virtual machines (a deterministic interpreter and an LLM), with humans as function endpoints: a UI is presented, the user acts, the action returns as a result. Not viable yet — 10x the cost of a person, conversation bias, nested-agent confusion — but "we've already transitioned": the company already is this runtime, with humans on the slow interpreter.

Four theoretical claims about intelligence. Intelligent systems are (a) non-modular — architecture is "almost like a linguistic artifact" for human readability, not an inherent property; (b) information-compressing; (c) necessarily agentic; (d) general — "intelligence is a measure of generality," near-synonyms. Corollary: benchmarks only measure "the subset of its abilities that overlaps with ours," which is why benchmark stars fail in practice.

The endgame is philosophical, not technological. Coupled systems develop shared representation with users; a system that preempts you "is kind of already you." The repercussion of scaling intelligence "will be philosophical or even phenomenal, like psychological."

3. Tools, Practices, and Methodologies

Chatbot & agent design

Proactive chatbots — agents that initiate conversation and act while nothing is requested; the differentiator against soon-obsolete reactive bots.

Negotiation messages — pre-task messages exchanged between agents to agree on communication format (e.g., rendered HTML) before work begins; enables UI-generating agents.

Auto-personalization — pull in all documents, profiles, and research about the user so the system tailors conversation style and UI without the user negotiating it; validated by a Middle East real-estate client.

Routing-agent RAG ("B-tree inspired architecture") — routing agent → category agents → leaf agents that alone query SQL or vector databases; no embeddings above the leaves; very fast to prototype, proven at POC stage; run balancing agents on the tree afterward.

Process automation

Reductionist process decomposition — interview process owners, replicate each step with an individual agent, present a UI only for non-replicable steps; the UI disappears over time as agents take over.

Human-as-parser audit pipeline — ingest files (Azure/AWS), auto-process what's automatable, route the rest to a human auditor acting as a parser; 70% filtered = 70% saved.

Blind human-vs-agent A/B reinforcement — run the same task sequence with a human in one branch and an agent in the other; raters vote without knowing who did what; the winner is reinforced in the next run.

Personal developer tooling

Extended-reasoning fan-out/fan-in — main prompt + revision prompt ("are you sure you followed the instructions?"), cloned and run across models (Claude, DeepSeek R1), majority voting picks the winner; his version took four hours to build with GitHub Copilot and ChatGPT; he even fed screenshots instead of retyping conversations.

Meta prompting — metaprompts that auto-generate the revision prompts, so the whole pipeline is driven like an ordinary chatbot.

Engineering practice

Two-pipeline prompt/code segregation — one repo, two CI/CD flows: code merges trigger app deployment; prompt-folder changes push to a separate prompt store (Azure Blob) the app reads from. For small projects: just treat prompts as code.

Prompt templating (Mustache, Jinja) — composition and inheritance for prompts; the prerequisite for later ethics and bias review.

Culturally-tailored prompt repositories — same code, different prompt repos and model selections per region (West Coast US / Middle East / Japan); his "practical ethics."

The AI-era dev loop — generate → inspect & verify → clean & refactor → write & revise → test & document; refactor every 3–5 steps; commit much more frequently; vibe coding only for prototypes.

Automated onboarding/testing agents — chatbots that test learners and evaluate results, automated tech leads, separate bots per staff level; HTEC's "hand-holding tech lead" for junior developers is live, version two in progress.

Protocols & infrastructure

MCP and A2A — expose your tools as MCP so copilots and agents can communicate with them and merge into more general agents; the backbone of his real-estate-giant architecture.

Frontier / experimental (HTEC R&D)

Behavior fine-tuning on XAML — fine-tune models to recognize and execute XAML operations instead of conversing; agents write to shared XAML object storage; conversation emerges from behavior; XML renders to HTML, closing the loop with the UI-shaping idea.

Agentic runtime — a simulated OS with instruction and definition segments, executing text via two virtual machines (deterministic interpreter + LLM); interrupt handlers written in English; humans treated as function endpoints (UI → user action → return value); applications are "agentic program prototypes" — "which conveniently abbreviates to apps."

Distributed needle-in-a-haystack benchmark — HTEC's internal benchmark: scatter one piece of information across the context window and test retrieval; probes whether the model encapsulates the entire context.

4. Unanswered Questions and Omissions

Benchmarking is diagnosed, then abandoned. He argues a proper benchmark "isn't one that's a table" and that we can only measure the overlap of a model's generality with our own — then explicitly defers: "how to resolve this, I think, is a separate presentation." The talk's central theoretical problem is left open.

Verification is declared impossible, and the fallback is undefined. "No, you can't… to detect that you would require higher intelligence." His fallback — "traditional procedures" for verifying people — is the same apparatus he calls "the biggest issue with most companies." No way out is offered.

Security, privacy, and adversarial input never appear. A runtime that ingests "all the research about the customer," writes agent state to shared storage, and treats humans as function endpoints raises access-control, PII, and prompt-injection questions. None are mentioned in a talk about deploying these systems globally.

The error rate of the automated 70% is never priced. The file pipeline audits only files that can't be auto-processed. Files auto-processed wrongly — hallucinated extraction, silent misrouting — go entirely unexamined.

The junior pipeline contradiction. If juniors "will never enter the workforce," where do the seniors — who must "not be a poor engineer" to supervise AI — come from? Onboarding bots transfer skills to existing staff; they don't rebuild the missing rung of the ladder.

Cultural alignment relativism gets no ethical scrutiny. "Alignment varies according to the time zone and culture" is framed as practical ethics. Who decides, where the red lines are, and whether some behaviors shouldn't ship anywhere — unaddressed.

"Figure out which models are biased for which things" — no method given. The culturally-tailored model-pulling practice requires a bias map he never explains how to build.

The economics of the agentic runtime. "10 times more than a regular person" today, "very soon this will be viable" — no cost curve, no timeline, no analysis of what flips it. Likewise, the token/compute cost of fanning out every query across multiple frontier models for majority voting is never mentioned.

The nested-agent problem is identified, not solved. Agents containing agents "messes up its conceptual ability"; the stated goal — agents that build agents — remains unreached, with no proposed fix.

The counterargument to non-modularity is never engaged. He frames architecture as a "linguistic artifact" serving human readability — but modularity also serves debuggability, auditability, compliance, and accountability. A non-modular intelligent system may be unmaintainable in ways that have nothing to do with manager convenience. Not addressed.

The philosophical payoff is dropped, not defended. "If it can preempt you in your action, it's kind of already you" and "the more coupled the system is, the more singular the intelligence feels" arrive with no account of responsibility, liability, consent, or worker autonomy for humans literally modeled as function endpoints inside the company-runtime.

Internal tension: he benchmarks while denouncing benchmarks. The four lessons rest on his own internal benchmark (distributed needle in a haystack) even as he argues environment-embedded tests can't be tables. Reconciliation lives in a "hundred page treatise" behind a link the audience can't check.

Q&A hand-waves on readiness. Asked how to identify companies ready to scale agents, the answer is "top level enthusiasm" — which he concedes "sounds like a cliche or cop out." No maturity model, despite the question asking for one.

Regulation and compliance are absent entirely. For a talk about shipping culturally-tailored chatbots for global enterprise clients, liability, audit obligations, and AI regulation never come up.
