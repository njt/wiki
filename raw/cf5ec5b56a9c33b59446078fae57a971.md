LLMs fail on client-domain questions not because they can't reason but because they don't know the domain — and the fix is not better chunking or bigger models, but giving the agent a structured, expert-authored data model (anchors, attributes, and the links between them) that it can explore and query directly. Epoch8 claims that when an AI agent like Vedana is grounded in a Grist-documented data model and fetches exact values from a database via crafted queries, it produces answers that are "absolutely correct" and traceable, where the same question dumped as chunks into ChatGPT fails — meaning the competitive edge in enterprise AI comes from domain documentation, not model choice.

Key points

Epoch8's clients (legal, e-commerce, manufacturing, automotive) share one trait: "a wrong answer is expensive." They need precise, traceable answers — which chunk-dumping into ChatGPT cannot deliver.

The core method is "minimal modeling" by Alexey Mahotkin: any domain is described with three concepts — anchors (the nouns: law documents, court cases, judges), attributes (name, title, enactment date), and links (how anchors relate: "load document can amend another load document"). Links matter most because they encode how the domain works and how the agent should reason across it.

The data model is stored in Grist as exactly three tables — anchor, attribute, link — each with a description, a data example, and a query showing how an agent can fetch an example. The same notation works for human analysts and LLMs.

Two use cases: (1) feed the model to an LLM to extract structured entities from documents; (2) drop the entire Grist document (it's just SQLite) into Claude as context and say "go explore the database, craft some queries and fetch the data that you need."

In their head-to-head, ChatGPT given chunked documents missed respondents and facts; Vedana, working from the data model, crafted a Cypher query and returned the exact value from the database.

The data model cannot be auto-generated: "Claude misses the point, misses the links, misses domain logic." Experts must sit down and define anchors, attributes, and links — but this work is done once, since domains are "pretty stable," after which experts self-serve by adding columns in Grist (e.g., marking discontinued products).

Architecture nuance: Grist is not the production query backend. Experts edit in Grist, an ETL pushes data to Memgraph, and the AI assistant queries Memgraph — necessary because Grist hits performance walls at hundreds of thousands of rows.

Domain playbooks compound: their automotive data model "looks pretty much the same across all the businesses," letting Vedana bootstrap new clients.

Tools, practices, and methodologies

Grist (open source) — spreadsheet-database hybrid used as the documentation layer for data models. Chosen for typed columns, business-user UI, open source licensing for client privacy, API access, Python friendliness, and role-based access. Used as the editing backend for experts, not the production query store.

Minimal modeling (Alexey Mahotkin) — notation of anchors, attributes, and links for describing a domain; has an accompanying book. Adopted pre-LLM for human analysts, then repurposed as LLM context.

Vedana — Epoch8's AI agent platform that explores the data model, crafts Cypher queries against Memgraph, and returns exact, sourced database values instead of guessed answers.

Whole-file SQLite dump / Grist MCP — two ways to hand the model to an agent: dump the Grist SQLite file to Claude, or (post-MCP, called a "game changer") feed the Grist MCP so Claude can set up customer assistants, check data consistency, and write prompts.

Memgraph — graph backend for production queries and large, rapidly changing datasets (e.g., millions of e-commerce products); Grist data flows in via ETL after experts press refresh.

Anchor-by-anchor documentation — start with 2–3 anchors and 3–5 attributes, expert-crafted, never fully auto-extracted; give the assistant SQL/Cypher/Python query examples to learn from.

Structured-first PDF handling — extract anchors, attributes, and links into tables; keep text chunks only as a fallback layer, accepting that quality "drops dramatically" when forced to use them.

Powerful-model bootstrap pattern — use a strong model (Claude) in a powerful harness to write prompts and playbook articles, then run cheaper or local LLMs with that scaffolding; the stack is LLM-agnostic.

Unanswered questions and omissions

No quantitative accuracy numbers: the ChatGPT-vs-Vedana comparison is shown anecdotally ("some typical cases") with no error rates, benchmark sizes, or methodology.

The cost and time of the expert modeling sessions is never estimated — how many expert-hours does a new domain take, and what does "start anchor by anchor" look like in calendar time?

Data model maintenance over time is hand-waved: domains are called "pretty stable," but what happens when regulations change, links break, or the ETL to Memgraph drifts out of sync with expert edits?

Grist's scale limits are admitted (hundreds of thousands of rows) but the split of what lives in Grist versus Memgraph is described loosely ("some fixed amount of data"), with no criteria.

No discussion of hallucination in query generation — what happens when the agent crafts a wrong Cypher query, and how errors are caught or validated before answers reach clients.

The claim that "no AI can help you here" on data modeling is asserted, not argued — no experimentation with LLM-proposed models that experts then correct is reported.

Security and access control for the agent side (who can query what in Memgraph) goes unaddressed, despite role-based access being a stated Grist requirement.
