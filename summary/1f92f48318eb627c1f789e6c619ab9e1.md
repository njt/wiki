A second ytx digest of Florin Coros's Craft 2025 talk (Budapest) — the transcript is byte-identical to the gist already ingested as [[Designing Deploy-Time Flexibility for Modular Systems — Florin Coros, Craft 2025]]; this gist ships a regenerated digest organized into four sections: Key Points, Pithy and Provocative Quotes, Tools/Practices/Methodologies, and Unanswered Questions and Omissions. The talk itself is unchanged in substance: "Microservices or monoliths is not the right question to ask. What I think you all want to build is a modular system." Build a modular system with dependencies only through contracts, implement every contract with a proxy, and use attribute-driven type discovery (the App Boot library) so the same compiled binaries deploy either as a modular monolith (in-process function calls) or as microservices (REST/gRPC/message bus) — decided after compilation, switched by copying DLLs between deployment folders. The origin story is a Dutch investment bank that spent three years splitting a Delphi monolith into message-bus-connected subsystems and ended with 10–15-hop call chains too slow to place an order; Coros's co-deployment proposal won the project. Sizing comes from the build-cost-vs-integration-cost graph (Yuval Lawi's *Writing Software*): in orders of magnitude, ~10 services, 20–25 tolerable, 2 or 90 "astronomical."

Where this digest earns its keep is the Tools section, which itemizes mechanics the first digest summarized loosely: App Boot's `[Service]` attribute declares an implementation and `[ServiceProxy]` registers proxies at lower priority — "always the last ones will override the first ones," so a real implementation found in the deployment folder overrides the proxy and calls become in-process; the Bootstrapper abstracts the DI container itself (Unity in the demo, pluggable); contract assemblies must hold serialization-friendly DTOs ("simple and concrete types… an array rather than an IList"); and for enforcing zero module-to-module references he names three options (ReSharper-generated dependency graphs, Visual Studio Enterprise architecture validation, reflection-based CI reference tests) while admitting he mostly skips automation because illegal references are "very visible" in code review. Production plumbing gets its own entries: a generic host either convention-driven or fronted by dummy proxies that 404 un-deployed contracts, service discovery as "basically like a DNS for production," one Dockerfile per deployment configuration, co-location decisions driven by production metrics, and DLL preloading where startup latency matters (desktop frontends).

The Unanswered Questions section is the sharpest artifact — twelve omissions, several of which are failure modes the mechanism *creates* rather than merely ignores: fault isolation (co-location reintroduces the blast-radius argument he used against monoliths) and independent scaling as "the elephant in the room" pair; in-process boundary erosion (REST's serialization boundary enforces encapsulation; in-process calls pass shared object references, so mutable DTOs crossing module boundaries go unmentioned); a testing matrix that scales with the number of deployment configurations; the anchoring bank story ending before its results are ever reported; the reflection-heavy design unweighed against AOT/trimming; contract versioning across independently deployed services; a "no ifs, no fors" contract-assembly rule enforced only on the honor system; and topology governance reduced to one passing mention of production metrics.
