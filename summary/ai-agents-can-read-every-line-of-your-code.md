A repository tells an agent what a system currently does, but not why boundaries exist, which data must stay isolated, what resilience level is required, or which "inefficient" decision protects a regulatory obligation. That intent lives in diagrams, documents, and people's heads — where humans struggle to find it and agents may never know it exists.

The author argues architecture-as-code is therefore becoming "much more than better documentation": machine-readable specifications of intent (pointing to FINOS CALM — components, relationships, controls, constraints) can be validated before an agent's change is accepted. The agentic question shifts from "does the code compile?" to "does this change still conform to the architecture we intended?"

The closing claim is organizational rather than technical: the next generation of AI-assisted engineering needs organizations able to express architecture in a form both humans and machines can challenge.
