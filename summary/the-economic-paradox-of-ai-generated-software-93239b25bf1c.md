Shaalan's essay argues that AI coding agents have inverted the build-versus-buy calculus — producing software is now cheap enough that individuals and departments build instead of subscribing — but only the *creation* economics changed, not the *operation* economics. Every generated application carries testing, security, maintenance and infrastructure obligations that a commercial platform had previously distributed across many customers.

The core moves: transaction-cost theory says build wins when building gets cheaper, but lifetime cost doesn't; individually rational builds create a collective externality (his illustrative 1,000 apps × $15/month + 2 maintenance hours/quarter ≈ $1M/year); cheap production triggers a rebound effect of more consumption, not proportionate value; the bottleneck migrates from writing code to verification and engineering judgement (citing DORA's finding that AI amplifies existing capability); experiments are not products (real-options theory justifies cheap prototypes but not their promotion to production); and shared infrastructure — Stripe, identity platforms, open source — exists precisely to distribute the cost of reliability, which AI-generated duplicates re-fragment. He closes with a governance contrast: two organisations both enjoying cheap creation, but only the one prioritising reusable capabilities and clear ownership captures the economies of scale.
