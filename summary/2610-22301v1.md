arXiv preprint 2610.22301 studies a new vulnerability class in the MCP ecosystem: **filesystem capability laundering**, where attacker-steered tool arguments make a benign-looking MCP tool touch host files far outside its declared contract. The core gap is architectural: a client-side approval prompt gates the *declared* tool call, but the spawned local stdio server process runs with the user's ambient filesystem permissions — so approval of "stage a file" can quietly become "read ~/.ssh".

**MCP-FSD**, the authors' measurement framework, analyzes the gap at three layers: L1 server-category screening (filesystem capability flags without a FileSystem label), L2 per-tool contract analysis (a narrow tool reaching beyond its scope), and L3 defeated path-validation checks. It infers a least-privilege boundary per tool (read-write for the workspace, read-only for runtime dependencies), plants credential fixtures outside that boundary, and validates with a three-case dynamic protocol: malicious payload unsandboxed (PoC 1), benign payload sandboxed (PoC 2), malicious payload sandboxed (PoC 3).

**Findings at scale**: across 21,097 MCP servers from nine registries, 787 of 4,806 triaged servers (16.4%) show filesystem capabilities despite non-filesystem classifications; 150 instances are dynamically confirmed vulnerable under tested sandbox policies. Coordinated disclosure produced 13 advisories, including two CVEs in Anthropic's own Git MCP Server: CVE-2025-68143 (git_init creating repositories anywhere, e.g. ~/.ssh, so later git tools leak keys as diffs) and CVE-2026-27735 (git_add staging files with `../` traversal, whose bytes land in Git's object database and surface via staged diff).

The paper's own fix taxonomy is notable: Python servers overwhelmingly omit validation entirely (53.8% of missing-validation findings), while Node servers ship flawed custom checks — because the MCP TypeScript SDK has no `safePath()`-style containment primitive. Proposed mitigations span SDK-level path helpers, a protocol-level `fs_scope` field on tool declarations, and OS-enforced sandboxing (validated to contain every confirmed exploit without breaking benign use).
