A pessimistic essay arguing that AI coding has prevailed but created more problems than it solved, and that the interesting future of software engineering is now "boring" caretaking work. The author (programming since ~2005) opens with nostalgia for a time when code was considered line by line and the profession felt prestigious, since "every single person can generate code by prompting an LLM."

Three problems, deliberately left unanswered:

1. **How do we learn now?** The old path — Problem → Research → Brain → Solution — has collapsed to Problem → Solution. Books (Kleppmann's *Designing Data-Intensive Applications*) and Stack Overflow built durable understanding because the brain was engaged; the shortcut skips that step entirely. A bitter aside: years of Stack Overflow answers were scraped "without giving any credit."

2. **Codebase erosion.** Accepting AI-generated code means the codebase eventually erodes: loose interfaces, scattered documentation, bloat, unused and conflicting features. Review is skipped or "AI reviewing AI and stamping everything as LGTM." He quotes: "Give a reviewer a 10-line Pull Request and he will find 10 issues, give him a 500-line one, and he will say LGTM." The boost arrives first; the rot shows later — "it's like a drug for the codebase."

3. **Noise and management.** AI slop extends beyond code into memos and email ("when the email or a doc is also a slop, you are simply showing a lack of respect"), while managers raise expectations because "we have the AI" — feeding back into problems 2 and 3.

He closes: "We used to spend time solving the problems with code, now we've become a caretaker of code that nobody really understands." The comments add a fourth problem — developer apathy ("No one is passionate about babysitting Claude") — and a prediction that human-authored code becomes a hobby, reserved for high-criticality systems like election machines and space shuttles.
