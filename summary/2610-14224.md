Harness2 is a Google Cloud AI Research framework (with a Northwestern first-author intern) for recursive self-improvement of agent harnesses in open-world settings — where tasks arrive fresh at test time, with no ground-truth verifiers to guide harness edits. The core contribution is a two-level recursion. **Task-level recursion** refines the harness for the current task using a contrastive Propose–Probe–Compose step: it proposes two scoped candidates (an "invariant" one targeting cross-domain agentic deficiencies like planning and delegation, and a "domain-specific" one targeting the task's knowledge and constraints), executes each under matched conditions, and composes a successor harness from edits supported by *behavioral contrasts* rather than assumed scores. **Harnessing-level recursion** then extracts lessons from the refinement process itself — which edits worked, under what conditions, with what evidence — into a harness improvement library that guides future tasks.

The harness is decomposed into eight file-level components: system prompt, guardrails, memory, skills, tool guidance, scripts, subagents, and a middleware plugin, extending AHE's seven-component decomposition. Parallel recursion (k candidates composed independently) and sequential recursion (k chained contrastive steps) both improve monotonically with the budget k. An anonymized agentic selector picks the final deliverable without knowing which harness produced it.

Across three professional benchmarks (WorkBuddy-Bench, JobBench, Harvey's LAB) and four executor–harness configurations (GLM-5 and Gemini 3.5 Flash under OpenCode and Codex, edited by Claude Opus 4.8), a single improvement step yields gains up to 11.5 points (WorkBuddy-Bench), 4.5 (JobBench), and 11.8 points (LAB Partial). Parallel recursion at k=5 adds another 2.9–6.7 points. Weaker executors gain more — an improved harness on GLM-5 surpasses base Gemini 3.5 Flash — and the same model serving as both executor and editor still improves on every benchmark. Notably, libraries accumulated with larger recursion budgets improve *future* harnessing without further probing, and a JobBench-derived library transfers to WorkBuddy-Bench. Ablations confirm all three components (library, scoped proposals, composition) contribute; the compute–performance tradeoff sits on the Pareto frontier against ReasoningBank, Meta-Harness, and Harness Scaling baselines.
