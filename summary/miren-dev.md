# Miren

Miren is a deployment platform that ships your apps to any Linux server — bare metal or cloud VM — with Miren Cloud connecting your clusters into one control plane. The pitch is "one tool, every target": deploy, databases, auth, and previews are declared in config, and the product is explicitly AI-friendly, shipping agent skills and predictable docs so a coding assistant can manage the entire deploy lifecycle.

## What it claims

- **Any Linux server.** Bare metal or cloud VM — "your servers, your cloud, your call." No managed-runtime lock-in.
- **One tool, every target.** Deploy, databases, auth, and previews, all declared in config.
- **Databases & services as addons.** Declare an addon, get a running database on deploy: Postgres, MySQL, Valkey, Memcached, RabbitMQ.
- **Admin API.** Expose internal admin endpoints without making them public — "built in, not bolted on."
- **Workload identity.** Every sandbox gets a verifiable OIDC token, so services prove who they are without shared secrets.
- **AI-friendly.** Ships agent skills and predictable docs so an AI assistant can "deploy and debug from your coding agent."

## Positioning

The homepage positions Miren against Google Cloud Run ("How Miren Stacks Up vs. Google Cloud Run") and links three blog posts that sketch the roadmap: v0.14 release highlights (secrets, tasks, maintenance windows, SQLite, reaching clusters off the public internet), a custom RPC system ("RPC That Calls You Back"), and distributed runners ("Your Cluster Is Finally a Cluster").

This is a marketing homepage, so every claim is a promise rather than a demonstration — no pricing, no benchmarks, no code, no author or publication date.
