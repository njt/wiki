Thorsten Ball's October 2026 snapshot of how he works with coding agents, posted as a tweet thread on X (375K views). It is a list of thirteen working habits, each stated as an imperative.

The through-line is trust through verification rather than control through review. He says use the latest models (cheaper-but-dumber ones cost you retries), stop worrying about "slop," and prompt the *What* not the *How* — "Make the bytecode compiler and VM AS FAST AS YOU CAN. Do not stop until it's 2x faster."

The most operational advice: make the whole SDLC legible to the agent — let it run what it builds end to end, read production logs, deploy, flip flags, triage bug reports — because "if the agent can't see something, it makes it up." He evals the accumulated knowledge in AGENTS.md and skills by spawning blind control-vs-treatment agents. Iteration is delegated too: "Generate 20 variations and a little page that lets me combine and test them" instead of back-and-forth prompting.

His "biggest game changer" is asking for irrefutable proof — demo videos, before/after numbers, end-to-end walkthroughs — and putting "this is not evidence" in AGENTS.md. He leans async: don't wait for agents, batch tasks, use schedules and heartbeats ("Check the logs in 2hrs"). Stop managing context by hand — one thread = one task, some threads run 3,714 messages — and treat threads, linked to git commits, as the company's memory.

On review: only code with high blast radius gets read (<5 central files, database migrations); naming, duplication and style he doesn't care about anymore. His bar is "Does it work? Do I understand it at the arrows-in-a-diagram level? Did the agent test it end to end? Can I change it in a month?" Agents shouldn't write for humans except mechanical docs, and local dev is the remaining sore spot — resource conflicts when many agents test end to end.
