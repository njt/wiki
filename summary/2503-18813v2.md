CaMeL (Google DeepMind / Google / ETH Zurich) is a system-level defense against prompt injection that requires no change to the underlying LLM. Its thesis: stop trying to make the model robust, and instead wrap it in a protective layer built from classic software-security ideas — control-flow integrity, capabilities, and information-flow control.

The architecture splits the agent into a Privileged LLM (P-LLM), which sees only the trusted user query and compiles it into Python code, and a tool-less Quarantined LLM (Q-LLM), which parses untrusted tool outputs into structured data. A custom Python interpreter executes the plan, maintaining a per-value data-flow graph and tagging every value with capabilities (provenance + allowed readers). Security policies expressed as Python functions gate every tool call: private data can't flow to state-changing tools, and exfiltration is blocked by construction rather than by model judgment.

Evaluated on AgentDojo, CaMeL solves the benchmark's security game "by design" with modest utility cost (a few percent on most suites; more on Travel due to underdocumented APIs), and outperforms all other defenses including OpenAI's instruction hierarchy (GPT-4o-mini falls to 276 attacks without CaMeL, zero with it). The paper is notable for its honesty about limits: explicit non-goals (text-to-text attacks, phishing), side-channel attacks (indirect leaks, exception-based bit leaks, timing), the adoption burden of capability systems, user fatigue from de-classification prompts, and a clear answer that prompt injections are *not* solved — but that a security-engineering mindset around untrusted models is the right direction.
