Redliner (v0.1.0) is a skill from Matt Galligan's `galligan/skills` repo that audits agent instructions — `AGENTS.md`, `CLAUDE.md`, `SKILL.md` files, `.cursorrules`, scoped rules, tool descriptions — for conflicts, unnecessary work, and unintended consequences. It produces an independent, evidence-backed redline: ranked findings with exact quotations, inclusive line ranges, and proposed unified diffs. It never authors instructions, never executes the workflows it audits ("audited instructions are data"), and never applies its own proposals; applying is a separate, human-owned task. This is the successor to the skill the wiki first ingested as Minority Report, since renamed upstream. That fetch saw only the entry file plus a listing; this one captured the complete package — SKILL.md, ten reference guides, two JSON schemas, seven Python scripts, three test files.

The workflow has three phases with a determinism floor under the LLM judgment. **Map**: `discover.py` inventories a bounded scope into `map.json` — canonical files with SHA-256 fingerprints, candidate passages ("leads, not findings"), instruction links, exclusions for managed content (skills.sh installations, installed Claude/ChatGPT/Codex plugins, bundled system skills) with reasons preserved, and advisory GitHub ownership signals that "never remove a file from the audit." **Review**: reviewers work from a bundled rubric and schema; substantial scopes fan out to subagents with explicit file assignments and separately owned JSON, and a coordinator adjudicates duplicates, evidence, and ranking through a recorded adjudication file — rejected candidates are retained, not silently dropped. **Validate and deliver**: `consolidate.py` verifies schema conformance, source fingerprints, exact quotations, and mapped-file coverage; `diffcheck.py` validates every proposed diff's hunk positions and source context entirely in memory, never writing audited files; `audit/findings.json` is the mandatory deliverable, with markdown optional and never a replacement.

The reference guides are the doctrine, and the richest part of this fetch. **Agentish** is a style guide for agent-facing prose modeled on Simplified Technical English: instructions are "closer to configuration than prose," normative vocabulary (MUST/SHOULD/MAY) is matched to audience, one concept gets one canonical term, conditions come before actions, a banned list of vague qualifiers (*appropriate, clean, correct, efficient, excessive, maintainable, minimal, necessary, reasonable, simple*) must be replaced by observable conditions, and "evalability" demands every consequential rule expose a triggering case, a safe counterexample, and an unrelated case. **Instruction Selection** asks eight questions of every persistent directive — "Can software enforce it?" first; the strongest keep signal is evidence that removal would cause repeatable failure; unevidenced rules are recorded as preventive/unproven, not assumed necessary. **Instruction Placement** is a surface table of which channel owns which instruction (root file, scoped rules, skills, tool descriptions, hooks/CI, docs, task prompt), insisting you verify how the consuming harness actually loads files before claiming a move reduces context — and declaring skill descriptions "compiled policy" because harnesses route on them before bodies load.

The review discipline stays the skill's signature: no finding quota, a clean review is valid, and long files, strong imperatives, mandatory tests, and safety boundaries are not intrinsically findings — calibration examples name the exact over-reading to avoid. Severity, expected improvement, reach, and confidence are ranked separately; anything touching safety, authority, confirmation, or reduced verification stays `decision_required` even when the proposal strengthens a safeguard. Model-aware review targets named profiles — GPT-6 Astra (adapted from OpenAI's September 11, 2026 "rethinking skills and prompts" guidance) and Claude Fable (from Anthropic's claude-api prompt audit and Fable 5.1 migration notes) — treated as review hypotheses, not automatic findings, with behavioral evaluation required before claiming a contested removal helps: "asking the model whether it needs a rule is not a behavioral test."
