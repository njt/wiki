DeepSeek Harness team's architectural essay on the "Super-agent": one continuous agent entity that replaces isolated, human-driven sessions with a system that is Continuous, Productive, Proactive, and Persistent. The bottleneck they identify is human attention — a person can follow only 3–5 parallel sessions — so the system must take over session and context management.

Five modules make up the framework:

1. **Two-level architecture.** A long-lived Router layer handles all human interaction, global coordination and memory (and dispatches only — it deliberately does not execute tasks), while context-isolated Worker sessions run tasks concurrently with the strongest models. Sessions become an implementation detail, not a user-facing unit.
2. **Event-driven Triggers.** Environmental events (chat messages, CI results, review comments) drive the agent instead of typed prompts. Two-stage filtering uses deterministic code as a Fast Path and the LLM as a Slow Path; Threads group consecutive events, with subscription-and-pass-through routing follow-ups directly to the owning Worker; Inline & Spill treats the context window as a cache (with a Chain of Recall over object IDs for multi-hop retrieval); speculative execution lets the agent work ahead on environmental signals.
3. **Full-duplex multi-channel interaction.** Asynchronous start()/stop() calls replace blocking run() so the conversation stays live during long tasks; reply style adapts per channel (100-word cap in IM, dense structured output on GitHub/email).
4. **Separating compute, state and environments.** Stateless elastic containers run the Agent Loop, session state lives in a database, and execution environments stay on users' own machines (BYOM) reached via lightweight daemons — explicitly compared with Anthropic's "Decoupling the brain from the hands."
5. **Watchdog.** An external Control Loop session monitors both infrastructure liveness and task progress, since agent anomalies are usually "stuck in a loop," not crashes.

Preliminary experiments (synthetic workloads, ~300 messages/run): the two-level architecture beat single-session-with-subagent designs on p50/p95 completion time (12.4/15.7 vs 13.8–20.4/29.0–29.5 min), with single-session quality heavily dependent on delegation prompts; pass-through cut Router cache-read tokens ~37% without hurting speed; Router batching amortized inference per decision from 6.4s down to 1.6s as burst rates rose.

Open problems named: scaling/sharding the two layers, session-free product UX, context boundaries and A2A collaboration, and security (prompt injection against a cloud Agent Loop connected to credential-bearing endpoints; "the agent needs a way to use credentials without ever seeing them"). Parts are implemented in the dsh-superagent-prototype plugin, explicitly a prototype, not a product.
