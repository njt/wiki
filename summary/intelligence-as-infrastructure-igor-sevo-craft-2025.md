A ytx gist (digest + full transcript) of Igor Sevo's Craft 2025 conference talk. Sevo — computer scientist with a PhD in machine learning and Head of Artificial Intelligence at HTEC Group — structures the talk from concrete to abstract: chatbot and agent design, process automation, developer practice, and finally a theory of intelligence whose payoff is the claim that the company itself is already an agentic runtime.

The practical core: proactive, UI-shaping chatbots (agents that negotiate rendered HTML as their interface and end up "pretty much replacing a front end engineer in some sense"); routing-agent RAG styled "B-tree inspired" — routing agent → category agents → leaf agents that alone touch databases — so traditional engineers can build retrieval without embeddings; reductionist process automation where each human step is replicated by an individual agent and a UI survives only where replication fails; and partial-automation economics ("if you filter 70% of this work… that's 70% of work saved"). On the personal-tooling side he describes an extended-reasoning agent that fans a main prompt plus a revision prompt across models (Claude, DeepSeek R1) and majority-votes the results — built in four hours with Copilot and ChatGPT, driven by metaprompts so the whole pipeline behaves like an ordinary chatbot.

On engineering practice: prompts treated as code but deployed on a separate CI/CD pipeline (one repo, two flows — code merges redeploy the app; prompt-folder changes push to a prompt store in Azure Blob without redeployment), Mustache/Jinja templating with composition and inheritance as the prerequisite for later ethics and bias review, and culturally-tailored prompt repositories and model selections per region — his "practical ethics," where alignment "varies according to the time zone and culture." The AI-era dev loop he prescribes: generate → inspect & verify → clean & refactor → write & revise → test & document, refactoring every 3–5 steps and committing far more often, because AI-assisted code rots fast. If entry thresholds keep rising, "junior developers will never enter the workforce" — so automate onboarding itself: HTEC already runs chatbots that test learners and a "hand-holding tech lead" for juniors.

The experimental end (HTEC R&D): fine-tuning for behavior rather than conversation (XAML operations written to shared object storage, with turn-taking conversation emerging from behavior), and the "agentic runtime" — a simulated OS executing text via two virtual machines, a deterministic interpreter and an LLM, with interrupt handlers written in English and humans treated as function endpoints (UI presented → user acts → result returns). Not viable yet: about 10x the cost of a person, conversation bias, nested-agent confusion — but "we've already transitioned": the company already is this runtime, with most of the code run by humans on the slow interpreter. MCP and A2A are the substrate that lets exposed tools and copilots "merge into more and more complex agents."

The theoretical close: four claims about intelligent systems — non-modular (architecture as "linguistic artifact" for human readability), information-compressing, necessarily agentic, and general ("intelligence is a measure of generality") — with the corollary that we benchmark "only the subset of its abilities that overlaps with ours," which is why benchmark stars fail in practice. It ends philosophical: coupled systems develop shared representation with their users, and "if it can preempt you in your action, it's kind of already you." The gist's own digest flags the omissions honestly: security and privacy never appear, verification is declared impossible with no fallback offered, the error rate of the automated 70% is unpriced, the junior-pipeline contradiction stands, and regional ethics relativism gets no ethical scrutiny.
