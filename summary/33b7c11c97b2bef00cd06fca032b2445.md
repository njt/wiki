Bruno Sanguinetti, CTO of Swiss startup Dotphoton, describes how his company delivered ESA-grade requirements traceability for a satellite image compressor using Grist plus GitHub, LaTeX/Typst, and Docker — and claims Grist is effectively the only tool that makes this workflow possible. Formal QA tooling (IBM Doors) was too clunky and expensive for a small team, and general-purpose tools (Word, Notion, Airtable, Monday.com) failed on speed, relational structure, or WYSIWYG exports.

Traceability means one-to-one matching across the V model's layers: acceptance tests map to needs, requirements map to needs, tests map to requirements — all staying consistent over a multi-year project. The enemy is QA displacing quality ("someone points to the moon and the idiot looks at the finger"); the fix is making document output automated and painless. Documents must be reproducible and versionable — the same Word file rendered 300 pages on one machine and 301 on another, and French-vs-English Word versions silently changed pagination, which is catastrophic when legal requirements depend on exact output.

The architecture: Grist as both database and interface, GitHub as the versioned release. A Python script pulled Grist data via API as CSV/JSON, injected it into a LaTeX template, and committed the Grist file, LaTeX source, and code into one repository that became the release — everything in sync. The system evolved through three generations: v1 (Python + LaTeX), v2 (bidirectional GitHub integration — "maybe too many features"), v3 (simpler, Docker services, Typst for PDFs, triggered from Grist via a toggle-column REST pattern replacing n8n). Change impact analysis deliberately went meta: tracked in Markdown files in a GitHub master project rather than in Grist, which is treated as "a snapshot of the system as it is now."

Dotphoton cut its documentation-to-execution time ratio from roughly 5:1 (at Bruno's previous company doing Ariane ignition-system testing) to 2:1 or 3:1, achieved an 8:1 compression ratio versus the industry's ~2:1, and got customer sign-off to replace a "many tens of thousands" Doors quote that would have required hiring two extra people. Open source needed a commercial backer to pass procurement — buying Grist's commercial version gave them someone to call "if it stops working on a Friday night." A local LLM (Gemma, on-premise, for security/customer constraints) auto-fills CRM fields and drafts quote emails, and Claude (on non-critical parts) helps write change-impact Markdown files. Schema advice: build the overbuilt version ("Picasso-bison"), then delete fields in two seconds until only the essential lines remain.

Open questions: no demonstration of how an actual ESA auditor received a Grist-backed package; the "only software" claim is asserted rather than proven (modern tools like Jama, Polarion, codebeamer go unmentioned); scaling beyond ~120 people is hand-waved; and the 8:1 compression result is never connected to the traceability system — only cheaper documentation is evidenced.
