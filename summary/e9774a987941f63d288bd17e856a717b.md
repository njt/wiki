Lydia Hallie, of the Claude Code team at Anthropic, argues that the best practices that defined Claude Code usage earlier in 2025 — steering sessions, manually approving commands, emphatic CLAUDE.md warnings, staying in the loop — are now actively counterproductive with models like Opus 5.5 and Fable 5.2. Sessions have changed shape: from one or two short supervised runs to dozens running for hours, verifying their own output, and orchestrating each other. Anthropic went from ~2,500 code changes a day in May to 30,000+ in September.

Her central claim is that wherever a human steps out of the loop, one of three layers must take over: the model (steering and self-verification), the harness (auto mode, deny rules, hooks, CI), and the environment (sandboxes and cloud sessions). Auto mode, the default permission mode since August, uses a classifier to allow known-safe commands and block uncertain ones — and in Anthropic's August study it blocked 89% of clearly dangerous commands versus only ~14% caught by humans in the loop. But only harness-level deny rules give a hard guarantee, and permissions have a blind spot: child processes and dependencies can reach files the approved command never named, which is why sandboxing and cloud sessions (fresh machines, no secrets on disk, network allowlists) matter.

Verification replaces supervision: pass/fail checkpoints, hooks that guarantee linters and tests run, CI as the backstop on every PR, Claude-first PR review with human review tiered by risk, and — the endgame — orchestrator sessions splitting work across worker threads with different models per role. The human's remaining job is to start the first session and review what comes out.
