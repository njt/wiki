kinfey's Microsoft Dev Community post (Oct 1, 2026) walks through a hands-on demo project: one page, two execution paths for the same McDonald's-ordering request — a traditional GitHub Copilot agent loop versus a "Jev Harness" that puts TypeSafe's System One model Jev in front of the Copilot Python SDK, both backed by GPT-6-astra and a McDonald's China MCP service.

The core argument is an allocation-of-responsibility one: the LLM is the chef, the agent harness is the restaurant, and most of what makes agents slow and expensive is giving the chef every administrative decision in the building. Jev handles bounded judgments (Choice/Noul/Score primitives returning typed decisions with probabilities) in one parallel request; ordinary Python code gates execution on confidence thresholds and permissions; the generative model keeps only the open-ended work.

The post is unusually honest about its own numbers: the optimized Jev path cut end-to-end time from 113.28s to 35.41s (~68.7%), but the author insists this is not evidence Jev alone caused the improvement — many optimizations (lean runtime, explicit tools, concise output) apply to the traditional path too, and a fast-but-truncated early run "won by the stopwatch and failed by the user's goal" because it never actually calculated the price. It also distinguishes Jev from a model router (router picks the model; Jev interprets the request into business branches), and warns that schema conformance, semantic correctness, and authorization are three different properties.
