EventCatalog's homepage pitches a documentation tool for software architecture: domains, systems, services, APIs, events, owners and dependencies as one connected, self-hosted model, replacing the scatter of spreadsheets, Miro diagrams, schema registries and tribal knowledge. Resources carry schemas, specs, decisions and ownership; zoomable views go from domain down to messages; business processes are documented as flows.

The agent-era pitch is the interesting part. An EventCatalog MCP server lets Claude, ChatGPT or Cursor query services, schemas and owners ("Ask your architecture from any agent"), scoped per domain so teams get focused context. "Agents can read your code, but not your architecture" — the catalog supplies what a change touches, who owns it and why it was built that way. EventCatalog Agents additionally update the affected docs as code changes, with teams reviewing every update, keeping the catalog in sync with CI/CD pipelines via integrations, generators and an SDK.

Studio adds a live design canvas where humans and agents work together on proposed architecture changes, with the decision kept on record. Deployment is self-hosted and private by default; the page cites 33,000+ catalogs created, 3,000+ GitHub stars and a Success Programme for org-wide rollouts.
