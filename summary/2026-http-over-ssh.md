Vincent Bernat shows how to build a self-hosted alternative to ngrok using only two pieces of software most servers already run: OpenSSH and nginx. `ssh -R 0:localhost:8080` asks the remote server to allocate an ephemeral port and reverse-forward to the local service; a regex `server_name` in nginx (`p(?<port>\d+)\.ssh\.luffy\.cx`) maps wildcard-subdomain requests back to that local port, with a wildcard Let's Encrypt certificate and a DNS CAA/ACME setup behind it.

The interesting part is access control. Since the port number is the only "secret", Bernat uses nginx's `secure_link` module to require a signed, expiring token — carried in the URL as the HTTP basic-auth username, because the hash is base64 and domain names are case-insensitive. An expired link returns 410, a missing or wrong hash returns 401. The token is generated by a one-liner of `openssl md5 | base64` with a URL-safe alphabet.

Because none of this is ergonomic by hand, he wraps it in a helper script installed on the server: it walks the process tree to find the ancestor `sshd-session` processes, scrapes their listening ports via `ss`, mints tokens for each, and prints shareable URLs. An `ssh RemoteCommand` entry in `~/.ssh/config` makes the whole thing a single command. His conclusion is the point: the solution relies only on OpenSSH and nginx, software already running on the server — no new client, no third-party service, no extra daemon. The post was widely discussed on Hacker News.
