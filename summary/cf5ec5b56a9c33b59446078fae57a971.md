A webinar transcript between Grist's CEO (Anais) and Olga Tataranova (co-founder of Epoch8) on how Vedana, Epoch8's AI agent platform, gets traceable, exact answers for clients where "a wrong answer is expensive" — legal, e-commerce, manufacturing, automotive.

The diagnosis: LLMs fail on client-domain questions not because they can't reason but because they don't know the domain. Dumping documents as chunks into ChatGPT produces prose that sounds right but is wrong. The fix is "minimal modeling" (Alexey Mahotkin's notation): anchors (nouns of the domain), attributes, and links — with links described as the most important part because they encode how the agent should reason across the domain. The model lives in Grist as exactly three tables (anchor, attribute, link), each with a description, a data example, and a query showing how an agent can fetch an example.

Two use cases: feed the model to an LLM to extract structured entities from documents, or drop the entire Grist document (it's just SQLite) — or, since MCP arrived, the Grist MCP — into Claude and say "go explore the database, craft some queries and fetch the data you need." In their head-to-head, ChatGPT on chunked documents missed respondents and facts; Vedana crafted a Cypher query and returned the exact value from Memgraph, the production graph backend (Grist is the experts' editing layer, ETL pushes data over because Grist hits performance walls at hundreds of thousands of rows).

Strong claims: the data model cannot be auto-generated ("Claude misses the point, misses the links, misses domain logic"); expertise is "extremely hard to scale"; domains are stable enough that the modeling work is done once, then experts self-serve by adding columns. Domain playbooks compound — their automotive data model looks "pretty much the same across all the businesses," letting Vedana bootstrap new clients. Chunks are kept only as a fallback layer; quality "drops dramatically" when forced to use them.
