# Databases and Data

  - [Write Snapshot Isolation](https://remy.wang/blog/si.html) -- SI checks for “stale writes” but WSI checks for “stale reads”, thus guaranteeing serializability.
  - [Correct by Construction](https://minimalmodeling.substack.com/p/my-take-on-data-quality) -- *this approach to data quality is basically a whitelist: we attempt to build the dataset that is correct by construction. [...] “static” properties: when your dataset is clean, your downstream queries would have a better chance to return correct data.*
  - [dolt](https://docs.dolthub.com/) -- *a SQL database you can fork, clone, branch, merge, push and pull just like a Git repository. Connect to Dolt just like any MySQL database to run SQL queries. Use the command line interface to import CSV files, commit your changes, push them to a remote, or merge your teammate's changes. All the commands you know from Git work exactly the same in Dolt. Git versions files, Dolt versions tables. It's like Git and MySQL had a baby.*
  - [trailmark](https://github.com/trailofbits/trailmark) -- *build and query a graph database representation of source code.*
  - [NornicDB](https://github.com/orneryd/NornicDB) -- graph + vector, with built-in fade-out of memory.
  - [Anomaly Detection](https://uriv.me/blog/anomaly-detection-with-welford-and-kv) -- *If a new value is more than 2 standard deviations from the running mean, it's an anomaly.* which is implementable with just a key-value store to keep track of running mean.
  - [graft](https://graft.rs/) -- SQLite replicated (partially, as needed) to the client. Its [comparison page](https://graft.rs/docs/about/comparison/) is a juicy source.
  - [GraphRAG](https://microsoft.github.io/graphrag/) -- *structured, hierarchical approach to Retrieval Augmented Generation (RAG), as opposed to naive semantic-search approaches using plain text snippets.   - [zvec](https://github.com/alibaba/zvec) -- lightweight, lightning-fast, in-process vector database.
  - [shaper](https://github.com/taleshape-com/shaper) -- *visualize and share your data. All in SQL. Powered by DuckDB.*
  - [Data Engineering for Large Models: Architecture, Algorithms & Projects](https://github.com/datascale-ai/data_engineering_book/blob/main/README_en.md) -- We systematically cover the complete technical stack from pre-training data cleaning to multimodal alignment, from RAG retrieval augmentation to synthetic data generation
  - [dolt](https://github.com/dolthub/dolt) -- *a SQL database that you can fork, clone, branch, merge, push and pull just like a Git repository*.

  - [zvec](https://github.com/alibaba/zvec) -- Alibaba’s lightweight, in-process vector database built on their Proxima engine; supports dense and sparse vectors, hybrid search, and runs wherever your code runs — notebooks to edge devices.
