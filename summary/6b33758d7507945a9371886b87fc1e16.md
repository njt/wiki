A verbatim transcript of Grist's "Grist 101" onboarding webinar, hosted by Natalie, a Grist customer engineer. The session tours the product for new users: personal vs. team sites, the team → workspace → document access-inheritance model, the two-free-collaborators cap on personal documents, and the resources panel (templates, 30-day trash, Grist Basics tutorial, Help Center).

The conceptual heart of the webinar is the reference column. Natalie's thesis: "you never want data to repeat." Converting a text column (owner names in a dogs table) to a reference type links each record to a unique row in an owners table; updates propagate everywhere, lookups pull fields (phone number) into formula columns, and the relationship powers linked widgets — a card widget "selected by" the dogs table shows the selected dog's owner live.

Other coverage: summary tables as Grist's pivot tables (group by location, then "select by" so clicking a summary row filters the detail table, with new rows auto-assigning to the selected group), formulas that apply to whole columns with no dragging (Excel-like functions, Grist functions, and the full Python standard library), safety nets (Document History snapshots with compare/replace, Activity log of ~100 changes, "Work on a copy"), Excel/Google Drive/URL import, and the AI formula assistant — which sends document structure and data to OpenAI, so Natalie suggests practicing on fake data.

The transcript also records what the webinar skips: access rules dismissed in one sentence as "advanced," pricing limits unstated, no comparison with Airtable/Notion, no data-cleaning guidance for messy real imports, and self-hosting mentioned only in passing.
