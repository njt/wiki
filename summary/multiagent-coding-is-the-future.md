Patrick McKenzie — payments infrastructure veteran and Stripe advisor — returns to blogging to argue that multiagent coding is a paradigm shift on the scale of LLMs writing code at all. His evidence is a month of serious use of Grimm, Situational Awareness' internal orchestrator that runs 2–100+ Claude Code instances in a devbox, able to talk to each other and to the user through a web UI over tmux. His core prescription: fire yourself from writing code and operating terminals entirely — the skill advantage you have over a single agent is not durable, but the headcount you can spawn is effectively unbounded, and a new "employee" joins seconds after a text message to the manager process.

He supports the thesis with the accumulating public and private evidence for agent capability: Stripe merging thousands of autonomous "minion" PRs weekly, agent-assisted language ports that collapse the timeline gap that has doomed ports like the IRS's Individual Master File, and lab results in research mathematics arriving as routine marketing events. On non-engineers, he sketches a future where an ops analyst's "?" is a fully actionable ticket and reconciliation breaks come back with most of the engineering work already done — multiagent coding as "Excel for Everything."

The essay also covers trust (double-entry bookkeeping and audits as the model for agent controls, red teams expected to win, the inevitability-of-breach posture banks already take toward robbery), the commoditization of specific knowledge (he shipped 42 PRs against an unfamiliar system in a day — 8,600 lines, $823 of inference — as a side quest), and inference economics: the Situational Awareness lead engineer spent $1.7M on inference in October alone, and capitalism's messengers (your competitors) will push everyone to that adoption curve, with multiagent adopters as "nucleation sites" whose surrounding economy looks discontinuously weird.
