# ASP.NET Core Authentication — The Dirty Details

Chris Klug's NDC Copenhagen 2026 talk is a deep architectural walkthrough of ASP.NET Core's authentication system, drawn from reading the actual source code. His thesis: the system has been rewritten multiple times and is now "quite beautiful" — built entirely on the four-method `IAuthenticationHandler` interface and a central `AuthenticationOptions` registry. The talk covers the handler hierarchy, forwarding mechanics, policy schemes, remote authentication's built-in CSRF protection, claims transformation pitfalls, and a suite of intentionally-overengineered demos including facial recognition and a random identity provider.

## Core Architecture

The entire system sits on `IAuthenticationHandler`: `InitializeAsync`, `AuthenticateAsync`, `ChallengeAsync`, `ForbidAsync`. That's it. Sign-in and sign-out are separate interfaces (`IAuthenticationSignInHandler`, `IAuthenticationSignOutHandler`) because most schemes only prove identity — session creation is almost always delegated to cookie authentication. The `AuthenticationProperties` object carries state across round-trips via its serialized `Items` dictionary (used as the OAuth `state` parameter), while `Parameters` stays in-process only.

## Forwarding and Policy Schemes

The base class `AuthenticationHandler<TOptions>` bakes in forwarding logic: if `ForwardAuthenticate`, `ForwardChallenge`, `ForwardForbid`, `ForwardDefault`, or the dynamic `ForwardDefaultSelector` are set, the handler delegates to another scheme. Policy schemes (`AddPolicyScheme`) exploit this to route requests dynamically — e.g., bearer for `/api` paths, cookies for everything else, or different schemes per user-agent.

## Remote Authentication and CSRF Protection

`RemoteAuthenticationHandler<TOptions>` is the most likely custom implementation point. It adds callback path handling, a backchannel HTTP client, and a built-in correlation ID CSRF pattern: generate 32 random bytes, store in `AuthenticationProperties.Items` under `".xsrf"`, issue a cookie named `".Correlation.{scheme}.{correlationId}"` with the literal value `"N"`. On callback, validate the cookie matches, delete it, and proceed. The encrypted `Items` dictionary ensures the correlation value can't be tampered with.

## Claims Transformation Warning

`IClaimsTransformation.TransformAsync` runs on *every* incoming request — not just at sign-in, but on static files, CSS, JavaScript, images. Database calls inside it are a performance disaster. Klug demonstrated this with a demo showing the arrival-date claim updating on every page refresh.

## Handler Decoration

By replacing `IAuthenticationHandlerProvider` in DI, you can wrap existing handlers in decorators that modify behavior without touching the original code. Klug's example: intercept the cookie handler and return 401/403 for API endpoints instead of a redirect.
